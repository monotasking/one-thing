## 三、`room-1` 的现场(§17.5 #9 那条 verify 红)

verify 报的是 `seq: expected seq 2 at position 1, got 3`。只读读出来的两条事件:

```
seq=1  time=1970-01-01T00:00:00.001Z  message/imported
       {"message":{"id":"m-1","role":"assistant","content":"先看看排期",
        "timestamp":1,"agentId":"fe","source":"collab-turn"},"synthetic":true}
seq=3  time=2026-08-27T07:12:06.307Z  user/message
       {"message":{"id":"u-1","role":"user","content":"大家看看","timestamp":1}}
meta:  {"name":"官网改版组","kind":"room","createdAt":"2026-08-24T06:21:38Z"}
```

三条事实,合起来指向同一个结论:

1. **seq=1 是夹具**:`time` 是 **1970-01-01T00:00:00.001Z**(`time: 1`)、消息
   `timestamp: 1`、`agentId: 'fe'`、`synthetic: true` —— 与
   `packages/backend/stores/__tests__/sessions-collab-turn.test.ts` 里那套
   room/`fe` 夹具同形。真实会话不会有 1970 年的事件。
2. **seq=3 是 08-27 的一次测试外溢**:那一天正是 §16.22「vitest 换 HOME 泄漏真机
   store」三修的当天;那批把 `logPath` 钉死 + 加了 HOME 硬闸(哨兵 7→0),但**已经
   写进去的那两行没有回收**。
3. **断的那一格(seq=2)从来没落盘**:两行之间没有第三种可能 —— 计数器分配过 2、
   写没落成(或落在别的 store 上)。

**定性:`room-1` 不是引擎写坏了一段历史,是一条夹具会话 + 一次已修复的外溢留下的
残渣。** 按 §17.7 #2 的新分栏它归「外来 / 无印章存量账本」。

**给用户的两个选项(本批不动,等拍板)**:

- **A(建议)· 删**:整目录 `~/.onething/sessions/room-1/`(373 字节 events.jsonl
  + meta.json + messages.jsonl + legacy-backup)。理由:它没有任何真实历史,
  留着只会让 verify 永远多一条红、并且需要一条基线行去静音它。
- **B · 收基线**:把那一行写进
  `docs/audit/session-verify-baseline-2026-08-20.txt`。代价是基线里多一条"其实是
  垃圾数据"的条目 —— 基线的语义是"修复前的引擎 bug 已写死在盘上",而这一条不是
  引擎 bug。

**本批既没删也没收基线** —— 它今天仍以原样出现在 verify 的存量栏里。
