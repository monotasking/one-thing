# 跟随滚动 ABA 对照结果

> **最终修复与回归结果：** 见 [修复方案与验证](/Users/yitiansong/data/code/start-electron/docs/audit/follow-jitter-fix-2026-09-15.md)。本文件记录的是第一轮几何 ABA，不能单独用作画面稳定的判据。

> **后续像素验证更正：** 下文“稳定”仅指 DOM 坐标稳定，不能推导画面稳定。回放真实会话后，开启补偿时已复现：提示坐标固定，文字仍切换 1 个物理像素（DPR=2 时为 0.5 CSS px）。详见 [像素复现记录](/Users/yitiansong/data/code/start-electron/docs/audit/follow-pixel-jitter-2026-09-15.md)。以下保留第一轮几何实验结果。

## 结论

**开启补偿稳定 → 关闭补偿出现微小往返 → 恢复补偿再次稳定。**

这次几何实验确认，在本次固定输入下，补偿有效抵消了内容高度与实际滚动量之间的差值；它没有检查文字最终落在哪个物理像素上，因此不能据此排除补偿与绘制的交互问题。

用户录屏中的微抖已经确认存在。不过，本次 A 组没有复现“开启补偿仍然抖”的情况，所以还不能宣布录屏问题已经定位或修复。

没有修改产品滚动代码，也没有移除补偿。本次新增了独立实验脚本和实验记录。

## 三组结果

所有位移单位均为 CSS 像素。微移计数阈值为 0.05px，方向反转指 400ms 内的相反方向移动。

| 指标 | A1：开启补偿 | B：关闭补偿 | A2：恢复补偿 |
| --- | ---: | ---: | ---: |
| 总采样帧数 | 2339 | 2328 | 2327 |
| 满足跟随判据的相邻帧对 | 1939 | 1929 | 1923 |
| 底部提示方向反转 | **0 次** | **53 次** | **0 次** |
| 底部提示超过 0.05px 的位置变化 | 0 次 | 89 次 | 0 次 |
| 最大单次位置变化 | 0.0078125px | **0.390625px** | 0.0078125px |
| 已跟踪正文/工具块向下反移 | 0 次 | 0 次 | 0 次 |
| 实际执行贴底 | 98 次 | 98 次 | 98 次 |

| 采样中出现消息 translate | 有 | **无** | 有 |
| 真实工具卡出现 | 是 | 是 | 是 |

“0 次”是阈值以上的计数，不表示所有坐标在数学上绝对不变。正文/工具块指标只比较前后两帧仍是同一个 DOM 节点、文字长度与高度未变的可见块；并非所有块在所有时刻都被跟踪。

## 捕获到了什么因果链

B 组中，同样一次增长出现了下面两种滚动结果：

| 消息高度增加 | 实际向下滚动 | 底部提示的净位移 |
| ---: | ---: | ---: |
| 38.390625px | 38.5px | -0.109375px，略向上 |
| 38.390625px | 38px | +0.390625px，略向下 |

位置变化可以用下式解释：

**提示位移 ≈ 消息高度变化 − 滚动位置变化 + 补偿值变化。**

三组符合跟随条件的帧对里，这个关系的最大误差为 0.0078125px。B 组没有补偿，余差直接出现在画面坐标里；A1、A2 的补偿抵消了余差。

这是一条实际运行数据，不是单独的算术模拟。此前发现的“可能产生正补偿值”的边界缺陷，本次符合跟随判据的采样中没有触发，不能用它解释这些数据。

## 对照条件与有效性

- 顺序固定为 A1 → B → A2，每组均新建独立 Electron 窗口、临时存储和用户数据目录；没有切换或修改用户正在使用的会话。
- 使用当前渲染层源码及现有本地主进程、后端构建。`ChatStream.tsx` 在实验前后的 SHA-256 一致。
- 三组均为 DPR=2、窗口内容尺寸 1060×860、会话滚动区域宽 640px、根字号 16px。
- 固定三阶段“思考文字 → 工具调用 → 继续输出”。真实工具仅在临时工作目录执行打印固定文字的命令，不调用真实模型服务。
- 每组实际发出 390 个固定分块，内容、顺序、分块边界的哈希三组相同。
- 计划追加间隔相同。实际分块间隔中位数分别为 41.093ms、41.043ms、41.094ms，95 分位分别约为 42.000ms、41.975ms、42.045ms。系统调度并非逐毫秒完全相同，因此保留了实际发送时间。
- B 组只在独立测试 Vite 服务返回的模块里跳过 `snapTail(el)`，保留 `stick()` 的滚动行为。源码文件未被改写；新页面也没有遗留位移。执行计数和 DOM 位移共同确认开关生效。

## 如何采样，哪些情况不计入

采样包含正文块、工具卡、消息行、底部提示、滚动量、留白、补偿值，并为 DOM 节点赋予稳定身份。

普通采样安排在 rAF 后的任务中，另在实际贴底调用之后留下一份几何快照。这样避免直接把 rAF 中、产品尺寸观察器尚未执行时的坐标当作最终结果。但它仍是 DOM 几何采样，**不是合成器每一帧的像素录像**。

上表的跟随统计限定为：前后两帧都在生成；仍是同一条消息和同一个提示节点；留白已归零；底部距离绝对值小于 3px。发送初始定位、工具切换导致节点更换、结束折叠等阶段不混入稳定跟随的计数。

## 对用户录屏问题的影响

1. 可以确认：**滚动量与分数高度之间的差值，确实能产生用户描述量级的微抖。**
2. 可以确认：**当前补偿在这份输入上起到了防抖作用。** 直接删除它，会让本次用例明显变差。
3. 尚未确认：**为什么用户录屏中开启当前功能仍会出现微抖。** 录屏当时加载的渲染代码、具体布局/缩放、历史消息规模、补偿触发阶段等还没有与本实验逐项对齐。

下一步应保留当前补偿，对齐录屏现场的运行版本和布局，并捕获出现微抖时的 `scrollTop`、`translate` 与提示位置。尤其要看：补偿当时有没有运行，运行后是否又发生了一次布局变化。这里是后续排查方向，尚不是已经证实的第二个根因。
