# 停止等待 ask_user 后正文消失

## 结论

正文仍在账本里，历史加载漏画了未结算请求的最后一段。修复已写入工作区：流式与历史加载共用正文补齐规则，停止后重新加载也保留已输出文字。

与上一轮改动有间接关系：新增的重连核对会刷新消息，暴露了原有历史加载遗漏。保留重连核对，否则仍可能漏掉完成事件、一直显示生成中。此次没有改动滚动逻辑。

## 漏画链路

1. 流式物化的 `mergeWater` 已有补齐规则：完整正文比可画文字长、且前缀一致时，补出缺少的尾段。
2. 停止后重连读取历史页，页面消息直接进入装配，不经过 `mergeWater`。
3. 原来的 `anchorMessage` 只在分段列表完全为空时回退到完整正文。已有前文或推理分段时，最后尾段被忽略。

## 修复范围

- 将补齐判断抽到 `data/missing-assistant-text.ts`，流式物化和界面装配共用。
- 只补 assistant 消息且要求前缀一致，避免暴露用户消息中仅给模型看的文件/技能上下文。
- 冷加载和已含工具锚点的快照均补齐尾段，文字仍位于相应工具之前。
- 不修改账本或 core 投影契约。已有受影响消息在加载修复后的界面后可恢复显示。
- 平铺正文不包含缺失部分的精确轮次，沿用已有“最佳可知轮次”的推断；这次修复针对正文，不扩展到未结算的行内思考内容。
