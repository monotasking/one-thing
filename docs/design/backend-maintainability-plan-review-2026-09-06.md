# 后端架构方案复审

日期：2026-09-06。审查对象：[后端问题修复与架构调整方案](backend-maintainability-plan-2026-09-06.md)。目标：减少跨模块改动，让新增能力更容易。

**结论：目标架构和 B0–B7 顺序可保留。本次复审发现 2 项 P1 设计缺口，已补入主方案；对应实现与验收仍须完成，不能据此宣布可发布。** 以下区分设计问题、已吸收意见和实现证据。进度见 [实施台账](backend-implementation-status-2026-09-06.md)。

## 本次发现

### 1. [P1] 会话授权与机器管理权限的边界不明确

**位置：**主方案 §4.4、§6 和 §9.3。修订前 §4.4 只定义固定操作者与会话 owner，§6 又将 B5 描述为互不信任用户共享部署的发布门槛，没有说明该门槛是否充分。

**触发与影响：**合法配置为 Alice 的请求仍可能拥有 settings、MCP、终端等机器管理能力，而语音等固定本机能力只接受 `local-user/default`。即使所有会话 handler 都比较 owner，通用文件与进程权限仍可能访问同一机器上的其他数据。不同域对“可信操作者”的含义不一致，会误导部署和后续功能开发。

**修订：**主方案已明确三类资源政策：会话及派生内容、宿主授予的机器管理能力、固定归属的本机设备。个人 UI 状态另按可信 owner/workspace 保存。全部域及内部入口记录实际资源与授权落点，搜索、媒体和当前会话等间接目标须在读正文或触发副作用前检查。B5 是会话资源边界，不单独构成互不信任用户的机器隔离方案。

**验收：**以默认和非默认可信 owner 经过正式 RPC/HTTP 验证各类能力的允许/拒绝结果；批量操作、原生迟到回调、内部命令均验证真实目标，拒绝时业务副作用为零。机器级能力须有明确宿主配置依据，不能由 payload 自报身份。

依据：[42 域资源核查](backend-rpc-access-audit-2026-09-06.md)、[语音域](../../packages/backend/rpc/domains/voice.ts)、[评测访问边界](../../packages/backend/rpc/domains/evals-access.ts)。后续实施已补齐搜索、媒体、电台和内部工具的已识别遗漏，当前完整 Node 回归通过；机器管理能力仍按本节声明，不能据此扩大部署隔离保证。

### 2. [P1] 回滚规则没有覆盖新增的持久协议

**位置：**主方案 §8，对照 §4.4 的草稿/初始归属和 §5.3 的删除恢复。修订前仅对锁协议明确停机和最低回滚能力；“旧账本可读”不能证明旧版本理解新增状态。

**触发与影响：**级联删除 A/B 在隔离 A 后崩溃，离线处理锁后回退至支持 B2、却不识别删除凭据的版本，残留 B 可能重新显示为正常会话。旧版本忽略草稿 owner、固定迁移目标或会话代际，也可能隐藏正文、重新认领或误删新生命周期的数据。

**修订：**主方案已要求记录 store 最低可写能力，在取得 lease 后、扫描/恢复/修复和业务写入前校验；启用新持久协议前先可靠保存能力声明。受支持回滚目标必须识别相应协议，或由受支持启动器强制检查。不兼容降级只走经验证的离线迁移或完整匹配备份，不能删新标记强行启动。任意旧程序不会自动遵守新标记，这一限制必须保留。

**验收：**带未完成和完成删除凭据、未完成草稿物化、初始 owner/代际的 store，交给旧能力版本时必须在业务数据零改动的情况下拒绝装配。备份恢复覆盖账本、blob、元数据、代际、删除凭据与草稿，不只恢复索引。

依据：[删除恢复记录](../../packages/onething-runtime/src/sessions/deletion-recovery.ts)、[草稿记录](../../packages/onething-runtime/src/scratchpad/drafts.ts)。后续已实现 [最低能力门禁](../../packages/onething-runtime/src/storage/store-format.ts)，并通过真实子进程能力组合及正式 Backend 启动前拒绝/冷重装测试。实际受支持的回滚发行版本、完整备份或离线迁移仍需发布准备；未升级旧程序不能直接使用新 store。

## 发布前仍缺的证据

1. **外部执行器：**SDK/ACP 每次模型、工具执行前能阻塞等待检查点的真实能力。协议草案和模拟 hook 不等于真实 agent 已支持，见 [执行器能力矩阵](execution-checkpoint-capabilities-2026-09-06.md)。
2. **平台：**Windows/Ubuntu 的实际保存、失败传播与生命周期结果。已配置 CI 不等于该平台通过；macOS 进程崩溃验证也不等于断电证明。
3. **完整授权：**已识别的派生数据和内部会话遗漏已补齐；最终沿42域核查表确认发布宿主配置与声明一致，不把通用机器权限误当作会话隔离。
4. **回滚：**最低可写能力检查已有实现与真实进程测试；支持的发行版本清单、离线迁移或完整备份恢复仍需发布准备。
5. **整体验证与性能：**当前完整 Node 915文件9229例通过，3文件8例沿既有条件跳过；类型、五门及三宿主烟测通过。完整桌面渲染前轮241文件4028例通过。本机结果不能替代目标平台与发行打包；全部旁路和性能测量仍需最终记录。不得放宽门禁或以测试 reset 掩盖生产生命周期。

后续仍按“可靠保存与排他 → 生命周期 → 会话边界和授权 → 同步 → 公开面与扩展”推进。评估维护性时看规则能否集中修改、扩展是否只改所属能力，而非新增了多少文件或层。
