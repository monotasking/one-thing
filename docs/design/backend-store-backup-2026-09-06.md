## 命令与实际保证

```text
onething store backup <新的备份目录> --store <已停止的原数据目录>
onething store verify <备份目录>
onething store restore <备份目录> <新的恢复暂存目录>
```

- `backup` 必须显式指定数据目录，取得相同的 StoreLease 后再复制。输出必须是独立、尚不存在的目录；路径别名或嵌套目录同样拒绝。业务文件包括全部账本、blob、会话元数据、代际、未完成/完成删除凭据、草稿、媒体和设置。只排除 `run/` 运行入口，以及已经完成的恢复诊断标记；后者的原址限制记录在备份清单中。
- 清单记录每个目录、文件大小、SHA-256、owner 权限和内部符号链接，并记录格式能力与原始规范化路径。文件采用有界块复制，刷盘后再可靠发布清单；源文件在复制期间变化会拒绝。文件系统树之外的符号链接、特殊文件不能静默遗漏，整个备份失败。备份目录权限为 0700，文件不给 group/other 新增权限。
- `verify` 只读校验清单、全部数据、额外/缺失文件及能力声明；它不修复历史损坏，也不证明一个本来已损坏的业务记录可以正常恢复。不要修改清单或能力标记来绕过拒绝。
- `restore` 在创建目标之前完成校验和能力匹配检查，只写新的暂存目录。开始复制前可靠写入未完成标记，复制与校验全部完成后可靠发布完成标记，再释放 lease。失败保留目录、锁和诊断，返回错误；源数据和备份不被覆盖。完成输出为 `staged: true`，同时返回必须使用的 `activationStorePath`。

## 为什么需要恢复到原路径

媒体索引和部分业务记录含有绝对路径。逐字节复制到另一个目录后直接启动，会继续引用原目录。恢复流程不改写权威账本或猜测哪些字符串是路径，所以完整暂存仍须回到清单指定的原始规范化路径。

恢复标记由 store-format 启动门禁检查。在暂存路径启动会明确拒绝；中途崩溃产生的未完成标记在离线隔离旧锁后仍然拒绝启动。完成的暂存目录回到原路径后才允许正常能力检查和冷恢复。完成标记继续保留，后续备份可以重新生成同样的原址约束。

## 停机恢复步骤

1. 停止桌面、Server、CLI daemon 和任何离线写入命令，并关闭自动重启。备份或恢复过程中不要重新启动这些写者。活锁、未知锁和残留旧锁不会被备份命令自动删除；异常退出按既有离线锁恢复流程诊断。
2. 用 `backup` 创建完整备份，再用 `verify` 校验。保留与目标发行版本匹配的整份备份；不要只保存旧索引。
3. 用 `restore` 写入新的暂存目录，检查输出 `staged: true` 及 `activationStorePath`。暂存未完成时保留失败目录用于诊断，在另一个新目录重试；不删除标记强行启动。
4. 保持全部写者和自动重启关闭，将原目录整体移至一个尚不存在的保留位置；再将已完成的暂存目录整体移到 `activationStorePath`。保留位置不能覆盖旧备份。此步骤是明确的离线原址切换，不能与启动并发。
5. 启动具备所需能力的目标版本，完成正常冷恢复及会话、媒体、草稿核验后，才重新启用自动启动。保留原目录副本和完整备份，直到此次恢复验收完成。

## 兼容范围

| 目标 | 当前证据 |
| --- | --- |
| 当前包含 StoreLease、store-format 与恢复标记门禁的代码 | 完整备份、暂存、原址激活后通过能力门禁；原始归属、附件、删除/草稿文件逐字节保留 |
| 遵守相同门禁、但能力少于备份要求的版本配置 | 在创建暂存目录前拒绝；不会删除能力标记或降级业务记录 |
| 与旧能力匹配的完整历史备份 | 合成 legacy 备份在受控低能力配置下可暂存、原址激活，并保持原内容 |
| 未升级的历史发行版 | 不支持；不能假设它识别 lease、能力或暂存标记。实际受支持回滚发行版/启动器仍需单独发布和验证 |

## 验证记录

本轮在隔离 macOS 目录验证：完整字节/内部链接/可执行权限、能力不匹配、活写者、目标覆盖、目录别名、损坏/缺失/多余文件、错误能力声明、复制失败、源未完成标记、原址激活和再次备份。真实独立 Node 子进程分别在首个文件刷盘后、完成标记发布前和完成标记刷盘后被 SIGKILL；离线隔离该死进程的残留锁后，半份库仍被拒绝，完成副本只能在原址激活，原备份可重新恢复。

真实 Backend 验证覆盖：导入带绝对路径的媒体、正常退出、备份、暂存恢复、暂存路径启动在 settings 初始化前失败、停机原址激活、重新启动并经 ServerMediaDelivery 读回原始字节。保留的旧目录被写入不同字节，确保读取来自恢复后的目录。另验证无 manifest 的正常/截断/跨缓冲区 external/execution 记录不会被低能力版本当作 legacy。

`node scripts/gate-store-backup.mjs` 使用真实 CLI 构建，验证备份、校验、暂存恢复、损坏与覆盖拒绝；无默认数据目录访问或 daemon 启动。运行前先执行 `npm run build:cli`。测试已加入三平台持久性 CI；本地结果不替代 Windows/Ubuntu runner 或断电证据。
