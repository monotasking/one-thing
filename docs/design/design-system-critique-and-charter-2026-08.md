# onething 设计系统 · 专业诊断与重建章程（2026-08-16）

> 背景：2026-08-16 用同一场景并排渲染四种方向（`.playwright-mcp/compare.html`）——
> 0·ledger（现有审美最好版）/ A·paper / B·warm / C·studio。用户判断：A/B/C 全部远好于 0，
> 0「层次感不明显、按钮不像按钮、面板不像面板、像随便乱画的」，要求整体重构。
> 候选源码：`.design-sync/theme-seeds/candidates/{paper,warm,studio}/`；种子对照 `theme-seeds/*.theme.json`。

本文两部分：§1 用专业语言把 0 的问题讲清楚；§2 新设计系统的结构与规则。
§1 的每条都是**方向无关**的——不管最终选 A/B/C 哪条谱系，这些问题都必须被系统本身杜绝。

## §1 现有系统的问题（专业诊断）

### 1.1 可供性失效（Affordance / Signifier）
- 按钮、标签、行、输入框共用同一套视觉语言：1px 墨线 + 3px 圆角 + 透明底。**可点与不可点没有区分线索**。
- 唯一的填充按钮「新会话」是一个无图标、无字重差、和 tag 同形的蓝块——用户原话"不知道是用来干什么的东西"。
- 输入框做成"凹槽"（比地面更暗）。在暗色系统里"更暗 = 禁用/次要"，主输入反而读成不可用。
- **判据**：Notion 候选的「新会话」是白卡 + 淡线 + 内边距 + 「＋」图标 + 中等字重——五个线索指向同一个结论"这是个可按的东西"。0 只有一个线索（蓝色），而蓝色同时还被 tab 下划线、选中文字、链接使用，线索被稀释。

### 1.2 海拔模型缺失且自相矛盾（Elevation model）
- 没有定义"面的阶梯"。侧栏 / 会话区 / 面板三者**同值**（#343331），只靠 1px 线切开——所以三栏读成一块板。
- 局部却出现了矛盾的深度线索：右栏有一张"抬升卡"，中栏输入框是"凹槽"，中栏内容直接躺在地上。同一屏里 z 序无法自洽——用户原话"中间陷进去、右边凸出来"。
- **规则缺失**：什么东西住在哪一层（地 / 区域 chrome / 卡 / 浮层）从没被写下；深度线索（明度、描边、阴影）也没有被要求**指向同一方向**。

### 1.3 围合失效（Gestalt: common region / enclosure）
- 一个"面板"要被读成面板，需要底色差 + 边框 + 圆角 + 内边距（+ 可选阴影）**多线索一致**。0 只给了 1px 线，其余全无 → 分组靠"线在哪"，眼睛要自己推理。
- 工具调用块 `⟨ WRITE ⟩` 是一个描边框加一个骑在边上的标签——它是**图纸符号**，不是容器。用户原话"能看出来它是一个面板，而不是一个什么什么东西"指的就是这个。

### 1.4 层级扁平（Visual hierarchy）
- 字号阶梯 10–22px 封顶、字重只用 400/500、颜色只有四档灰。**没有任何元素能主导视线**。
- 标题 22px vs 正文 15px 的对比比 1.5 还小；专业系统标题至少 2× 正文。
- 层级全部押在"字体家族切换"（衬线/无衬线/mono）上，但在小字号下家族差异不可见。

### 1.5 颜色角色混同（Color roles）
- 一枚蓝同时承担：主行动、选中态、tab 指示、链接、强调文字。**一种颜色 = 五种含义 = 零含义**。
- 状态色和强调色用同一种表达（都只描边）→ 成功/警告/危险与"普通强调"看起来是一回事。
- 没有第二个语义色 → 无法编码"谁在说话"（你 / 助手）或"什么类型的东西"。B·warm 用陶土=你、鼠尾草=助手，一眼分角色，就是这个缺口的反例。

### 1.6 界面语言是机器语言（Voice / labeling）
- `⟨ WRITE ⟩`、mono 大写加宽 kicker、`+128 −41`、`14:02` 作为主要标签。**mono 大写 kicker 是装饰不是标签**：它把"分组名"降格成一枚小图章。
- 对比："写入了 3 个文件 · 用时 1.2 秒"一句人话，比 `⟨ WRITE ⟩` 传达十倍信息。

### 1.7 节奏与密度（Rhythm / density）
- 间距没有阶梯（`--space-*` 采用率 0.3%），所有 padding 都差不多 → 没有"组内紧、组间松"的节奏，分组只能靠线。
- 全屏 10–13px 文字，行高 36–44px 的均质行 → 信息密度高但可读性低，读起来像日志。

### 1.8 组件缺少解剖定义（Component anatomy）
- Button / Card / ListRow / Panel / Tag 没有"解剖图"（槽位、状态、尺寸档），每处实例都是现场拼的（全仓 337 处裸 `<button>` 对 331 处共享 Button）。
- 结果是"同一个东西在不同页面长得不一样，不同的东西长得一样"。

### 1.9 体裁错配（Genre）
- 上述所有选择合起来是"仪表 / 日志查看器"体裁（Bloomberg 终端 × 铅字账本）。onething 是个人 AI 工作台——对话、助手、笔记——是"陪伴 / 文档"体裁。**体裁错了，局部再精致也不对**。
- 这套风格不是被设计出来的，是从工具调用"图纸风"一路沿用长出来的；也是 LLM 被要求"克制高级暗色"时的默认产出（mono kicker + hairline + 微型 meta），有明显的"AI 味"。

### 1.10 五秒测试（判定任何一屏的最低标准）
让一个没见过的人看 5 秒，能否说出：
1. 主行动是什么（哪个最想点）
2. 屏幕上有几个容器、各是什么
3. 哪些能点、哪些不能
4. 谁在说话（你 / 助手 / 系统）
5. 我在哪（当前会话 / 页签 / 面板）
0 五项全挂；A/B/C 五项全过。**新系统的每个模板都必须过这个测试。**

## §2 新设计系统怎么建（章程）

原则：**从种子派生，不从产品收割**。十几个参数决定一切，其余全是推导；组件只消费语义层。

### 2.1 五层结构

```
L0 种子 theme.json      品牌决定：bg/surface/text/accent/accent2 · 字体两族 · density · radius
                        · layoutStyle · dividers · buttonStyle · colorUse （≈13 参数）
L1 原语 primitives      从 L0 派生：OKLCH 100–900 色阶（每个角色一条）· 字阶到 display
                        · 4px 间距阶梯 · 圆角阶梯 · 三档阴影 · 一条动效
L2 语义角色 semantics   面的阶梯 · 墨的阶梯 · 行动角色 · 状态角色 · 焦点 · 选中/悬停
L3 组件解剖 components  ~12 个核心组件的槽位/状态/尺寸档，每个写明"靠什么被认出来"
L4 版式模式 patterns    三栏工作台 · 对话流 · 工具活动卡 · 设置表单 · 空态
L5 声音 voice           README：mood 一段 · Direction · Color · Type · Do/Don't · 语言规则
```

### 2.2 L2 必须写死的规则

**面的阶梯（elevation ladder）** — 只允许四层，每层有唯一住户：

| 层 | 名 | 住户 | 线索（必须一致） |
|---|---|---|---|
| 0 | 地 ground | 窗口本身、对话流正文 | 最低明度（亮色系最暖白/暗色系最深） |
| 1 | 区域 chrome | 侧栏、右栏、页签栏 | 与地差一档明度；可有 1px 分界 |
| 2 | 卡 card | 工具卡、设置卡、输入框、选中的会话行 | 更亮一档 + 1px 淡线 + 圆角 + 内边距；**阴影可选但整套统一：要么全部无影（paper），要么全部软影（warm/studio）** |
| 3 | 浮层 overlay | 菜单、popover、对话框、toast | 唯一允许"明显阴影"的一层 |

禁令：同一层里不得同时出现"凹进去"和"凸出来"；输入框永远不低于卡层。

**墨的阶梯**：primary / secondary / muted / faint 四档，正文最低 secondary，faint 只给元信息。

**行动角色**：primary（一屏一个填充）/ secondary（描边或浅底）/ tertiary（纯文字）/ destructive。按钮必须有可按线索 ≥3（底色或描边、内边距、字重、图标、圆角）。

**颜色角色表**：accent = 人的操作（主按钮、焦点环、选中）；accent2 = 助手 / 系统陈述（助手标记、工具卡脊线、进行中）；status 四色只出现在状态语义上，且表达方式（丸/点/描边）与 accent 明显不同。**一枚色 ≤ 两种含义。**

**字阶**：caption 11–12 · body 15–16 · h4 18 · h3 22 · h2 28 · h1 32–36 · display 44–48；标题 ≥ 2× 正文；负字距从 h3 起。

**语言规则**：分组标题用正常大小写的人话（今天 / 用量 / 状态），不用 mono 大写；机器产出（路径、diff 数、耗时）只在工具卡内部用 mono；界面按钮说动词（发送 / 查看差异 / 确认迁移）。

### 2.3 L3 核心组件清单（先做这 12 个）

Button（3 角色 × 3 尺寸）· Input & Composer · Card / Panel（PanelShell 重做）· ListRow（会话行/设置行）· Tabs · Tag / Pill · Menu & Popover · Dialog · Toast · Message（user / assistant 两态）· ToolCard（标题行 + 文件列表 + 状态行 + 行动）· SidebarItem。
每个组件文档必须包含：解剖图（槽位）、状态（default/hover/active/selected/disabled/focus）、尺寸档、**识别线索**（它靠什么被一眼认出来）、反例。

### 2.4 交付与治理

1. 选定方向 → 定稿 `theme.json`（亮色一份 + 暗色一份，暗色以 C·studio 为蓝本而非 ledger）
2. 派生 L1/L2 → 替换 `packages/renderer/styles/variables.css` 与主题生成器输入；`--ui-*` 语义层**名字不动、值全换**，先换一次皮
3. L3 换血：ledger 行 → ListRow；图签框工具卡 → ToolCard；mono kicker → 正常小节标题；PanelShell 重做
4. 回填 Claude Design：新种子 + README + 组件卡，注册为默认设计系统
5. 棘轮：font-size / padding / gap / border-radius 四属性只许走 token；组件页 `/design-system` 展示 12 件的全部状态

### 2.5 现有资产的处置

- 保留：`--ui-<族>-<角色>-<字段>` 命名骨架、主题四维正交（明暗/强调色/密度/壁纸）、state-alpha 行为层、z-index 表、动效单一缓动。
- 推翻：账页画线风的全部签名装置（墨线分区、mono 大写 kicker、⟨ ⟩ 图签框、只描边不填色、3px 圆角、凹槽输入框）。旧文档 `docs/design/ui-system.md` 的禁令部分继续有效，"配方"部分待本章程 L3 落地后重写；`onething-style-reference.md` 标记为历史。

## §3 在 Claude Design 里落地（对照《在 Claude Design 里设计与调整设计系统》方法论）

方法论核心：**系统质量 = 喂进去的证据质量；成品 > 规范；调整前先诊断归因（A 证据不足 / B 证据冲突 / C 抽取偏差）。**

### 3.1 我们的病因判定

用它的"快速判别法"（一个新入职设计师只看这堆材料能否做出期望页面）：

| 我们喂过的东西 | 判定 |
|---|---|
| `onething Tokens`（1080 枚收割自产品的 token + 730 行规范 + 17 张 token 卡） | **A 类 + 一个更根本的问题**：材料里没有一张"做完的好页面"；更糟的是产品本身就是错的标准——按它做出来就是 0·ledger。这不是证据不足，是**证据的源头（产品）需要先被替换** |
| `onething Design System`（手写 React 再创作，当前是组织**默认**） | **B 类**：与 Tokens 项目互相矛盾（阴影卡 / 紫色 ToolCall / 亮色默认），且是默认——用户新建项目吃到的就是它 |
| Tokens 项目**未注册为设计系统**（`list_design_systems` 里没有） | 结构性缺口：它根本没进入"被继承"的链路 |

处置顺序：**先清洗（B）再喂料（A）再 Remix（C）**——反过来做全白费。

### 3.2 证据集计划（选定方向后执行）

方法论"5–8 个覆盖差异的成品页" → onething 版测试矩阵（同时就是回归测试集，固定不改）：

1. 三栏工作台 · 一段含工具调用的会话（已有：候选 A/B/C 之一）
2. 设置页 · 含开关 / 下拉 / 危险操作 / 分组
3. 工作区面板 · 媒体或任务（PanelShell 的新形态）
4. 空态 × 2 · 新会话空态 + 无搜索结果
5. 权限审批卡 · 一次工具调用请求确认（onething 最有辨识度的交互）
6. 同一会话页的暗色版（种子暗色档，以 C·studio 为蓝本）
7. 笔记 / Todo 窗（Tiptap 编辑面）
8. 命令面板 / 模型选择器（浮层层级的证据）

**只做这 8 张，先不做更多**——覆盖差异不堆数量。全部由种子派生的 styles.css 驱动，保证互相是一套。

### 3.3 判据层 L4（可判定句子，随证据一起喂）

- 一屏内主色实心块 ≤ 1 处；次要操作一律描边或纯文字
- 面只有四层：地 / 区域 / 卡 / 浮层；同层不得既凹又凸；输入框永不低于卡层
- 内容卡不投影（或全部软影，二选一，全系统统一）；只有浮层可有明显阴影
- 标题 ≥ 2× 正文；全系统字号 ≤ 8 种；正文 ≥ 15px
- 一枚色 ≤ 两种含义：accent = 人的操作，accent2 = 助手/系统陈述；状态色表达（丸/点）与强调色明显不同
- 按钮可按线索 ≥ 3（底/描边、内边距、字重、图标、圆角）
- 分组标题用正常大小写人话；mono 只出现在工具卡内部的路径/数字；界面按钮说动词
- 反例集：`⟨ WRITE ⟩` 图签框（图纸符号不是容器）；mono 大写 kicker（装饰不是标签）；三栏同底色靠 1px 线切（不是层级）；凹槽输入框（读成禁用）

### 3.4 闭环与日志

每次只动一个变量 → 重跑 8 张 → 打分（品牌辨识 / 色彩纪律 / 排版层级 / 间距密度 / 组件保真 / 边缘态 / 深色 / 跨页一致）→ 记一行：

| 日期 | 改动 | 病因 | 分数变化 | 结论 |
|---|---|---|---|---|
| 08-16 | 并排渲染 0/A/B/C 同场景 | 诊断 | 0 五秒测试全挂，A/B/C 全过 | 方向待拍板 |
