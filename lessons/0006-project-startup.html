06 / 还原执行顺序 / 约 7 分钟

从一条启动命令，
走到可用的界面。

先抓住一条主线：启动脚本 → Electron 主进程 → 准备后端 → 创建窗口 → 页面取得连接 → React 挂载。学完后，你能解释“这些文件为什么会依次运行”，并找到启动卡在哪一步。

依据 2026-09-11 当前工作区源码静态核对。以开发模式、没有现成 core 的正常桌面启动为主线；复用 core 和网页分支另列。此页只演示流程，不会启动应用或调用 AI。

01

先把三种角色放对位置

进程可以先理解为操作系统里独立运行的一份程序。这个项目的启动脚本、Electron 主进程、窗口里的页面，各有自己的执行路线。

主进程：开窗口，也承载后端

electron/main.ts 在 Electron 的 Node.js 环境里运行。没有可复用 core 时，它在本进程中装配后端。这里的 core 泛指提供会话、工具和 AI 执行能力的后端实例，不只指 packages/core 文件夹。

渲染进程：画界面、请求数据

src/main.tsx 是窗口内页面的入口。preload 在页面代码前运行，提供向主进程询问连接信息的小接口；它不是第三个独立后端进程。

概念依据：Electron 官方：Process Model；本项目的后端归属见 electron/main.ts · assembleOwnCore。

  1. 启动脚本先准备可执行文件与页面服务器编译主进程 / preload → 启动 Vite → 启动 Electron。
  2. Electron 就绪，决定后端从哪里来
    发现可用 core复用地址，直接创建窗口。
    没有可用 core · 本课主线等待后端装配，再创建窗口。
  3. 创建窗口后，两条路线开始交汇
    主进程启动 HTTP/SSE 服务，准备连接信息。
    窗口页面执行 preload 和页面入口，询问并等待连接信息。
  4. 页面发起连接探测，再挂载 React建立客户端 → 订阅事件并请求 sessions.list → 探测结束 → 发起数据加载，渲染 App。
  5. 数据陆续返回，界面继续更新会话列表、助手、设置等异步加载；窗口出现不代表这些数据已经全部到齐。

01 · 命令入口

npm 按 scripts 找到启动程序

npm run dev
→ node scripts/dev-unified.mjs
→ startElectronLane()
→ npm run electron:dev
→ node apps/desktop-react/scripts/dev-app.mjs

npm run 名字 查找根目录 package.json 的 scripts。默认 dev 同时安排桌面和网页路线，桌面不必等网页启动完成。只读桌面这条线时，对应命令是 npm run dev:electron。

现在到了哪里？运行的是负责拉起应用的脚本，还没走进 Electron 主进程。

源码：package.json · scripts / dev-unified.mjs · startElectronLane、main。

02 · 构建与启动

先打包主进程，再给窗口准备网页

build-electron.mjs 完成
→ createServer(...) → await server.listen()
→ spawn(electronPath, ["…/main.cjs"], ...)

构建把 TypeScript 源码整理成 Electron 能执行的文件，包括 main.cjs、preload.cjs 和检索 worker。随后 Vite 提供开发页面（默认桌面端口 5175），脚本把它的地址通过 ONETHING_REACT_DEV_SERVER_URL 传给 Electron。

spawn 的作用是启动一个子进程；这是执行路线跨到另一份运行程序的地方。

源码：dev-app.mjs · 构建 → server.listen → spawn / build-electron.mjs / vite.config.ts。

03 · 主进程就绪

先找现成后端，找不到才自己装配

app.whenReady().then(async () => {
  const existing = readDiscovery()
  if (existing && await isAlive(existing)) {
    // 复用连接，创建窗口
  } else {
    backend = await assembleOwnCore()
    // 接下一步
  }
})

whenReady().then(函数) 把后续工作交给 Electron，在它初始化完成后执行。readDiscovery() 读取当前数据目录下 run/http.json；代码再检查进程和端口，判断已有 core 是否可用。

若可用，就跳过本次后端装配；否则在这个 Electron 主进程里创建后端。默认数据目录是 ~/.onething，可以由环境变量覆盖。

源码：electron/main.ts · L92、L142、L429。概念：Electron：app.whenReady()。

04 · 后端装配

把以后要接收请求的系统准备好

assembleOwnCore()
→ createOnethingBackend(options)
→ OnethingBackend.assemble(options)
→ await backend.assembleSteps()

“装配”就是创建各个部件，并把它们接到一起。压缩来看：接入桌面宿主能力 → 获取数据目录的独占使用权 → 恢复数据、加载设置和助手 → 创建会话层与引擎 → 准备工具、注册 RPC 处理函数。

这一步承接上一课：后端先登记方法，之后客户端发来的 emit 才有地方执行。更完整的装配顺序放在速查页，第一遍不用记住所有函数。

源码：main.ts · assembleOwnCore / backend.ts · assembleSteps、createOnethingBackend / 上一课：注册与调用。

05 · 创建窗口后，启动连接服务

窗口加载与 HTTP 服务启动可以重叠

createWindow()
startPostWindowServices()
  → startEmbeddedOnethingHttpServer(backend)
  → connectionReady = mounting.then(...)

createWindow() 创建隐藏的 BrowserWindow，指定 preload，然后加载 Vite 地址；收到 ready-to-show 才显示窗口。紧接着，主进程启动 HTTP/SSE 服务，成功监听后写出发现文件。

connectionReady 保存一个 Promise，可理解为“连接信息稍后交付的结果”。同时会启动调度任务、发起 MCP 连接和首次模型目录刷新；后两项不作为首屏完成的前提。

这里不要误读成严格先后创建窗口在前；但 ready-to-show 与 HTTP 监听完成谁先发生，没有固定顺序。

源码：main.ts · L214、L380、L450 / embed.ts · startEmbeddedOnethingHttpServer。

06 · 页面询问连接信息

preload 留下入口，页面再调用它

index.html → src/main.tsx → whenConnected()
→ window.onethingHost.getConnection()
→ ipcRenderer.invoke("host:connection")
→ 主进程返回 connectionReady 的结果

preload 先通过 contextBridge 暴露 onethingHost。页面入口做完本地布局等准备后，调用 whenConnected()。它向主进程要 baseUrl（后端地址）和 token（访问凭证）；HTTP 尚未就绪时，等待上一步的 Promise。

这一小段交接走 IPC，也就是进程间通信。之后正常的业务请求走 HTTP，后端事件走 SSE；不是每条业务调用都再经过 preload。

源码：preload.ts · L14 / main.ts · host:connection / connection.ts · connect。

07 · 建立客户端

先订事件，再做一次真实请求探测

client = createOnethingClient({
  transport: createHttpTransport({ baseUrl, token })
})
hub.on(IPC_CHANNELS.SESSION_EVENT, ...)
await client.api(sessionsRouter).list({})

客户端封装“怎么把请求送过去”。首次事件订阅会触发 SSE 连接；SSE 是后端持续推送事件的 HTTP 长连接。随后 sessions.list 探测一次请求往返，记录成功或错误。

两个检查不能混为一谈RPC 返回成功，不表示已经收到首条 SSE 事件，也不表示界面所需数据全部加载完成。

源码：connection.ts · L136–161 / transport/http.ts。

08 · 挂载与后续更新

发起数据加载，马上让 React 画外壳

whenConnected().finally(() => {
  void useSessionsSource.getState().start()
  // 还会启动助手、设置、主题、工作区等加载
  createRoot(root).render(<App />)
})

finally 表示连接尝试结束后执行，不要求探测成功；失败也会显示外壳和错误反馈。这里的 void ...start() 没有等待加载完成，React 可以先画出 loading 状态，等数据回来再更新。

App 在普通模式下渲染 AppShell。到这里，启动主线就接上了你之前读过的“发消息 → 后端执行 → 事件更新界面”。

源码：main.tsx · L87–127 / App.tsx · App / 回看消息生命周期。
