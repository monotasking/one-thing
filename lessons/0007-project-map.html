01

这个软件在干什么

onething（一事）是一个装在电脑上的 AI 聊天应用。你在窗口里打字，它把话发给模型；模型可以让它在你这台电脑上读文件、跑命令、调用工具——每次敏感操作都会先问你。会话保存在本地，不经过项目自己的中间服务器。

产品说明来自 README.zh-CN。本课不展开「工具怎么执行」，那是第 2 课的路线。

02

四个词，先别混

源码里会同时出现这些名字。它们不是四门并列的语言，职责差很多。

JavaScript / TypeScript

JavaScript（简称 JS）是浏览器和 Node 都执行的语言。本仓库大量文件以 .ts / .tsx 结尾，那是 TypeScript（简称 TS）：在 JS 上面加了类型标签，例如 text: string 表示「这个值按约定是一段文字」。标签给人和编辑器看；真正跑起来时，标签会被拿掉，剩下的仍是 JavaScript。

React / Electron

React不是新语言，是用 JS 写界面的库：你改数据，它负责把数据画成屏幕上的按钮和列表。Electron把「浏览器引擎」和「能碰电脑的 Node」捆成一个桌面应用。所以这个项目看起来像网站，却能读写本地文件。

Electron 里同时跑着两份程序：

角色可以把它想成在本项目里
主进程能开窗、能碰硬盘的后台apps/desktop-react/electron/main.ts：开窗口，并常常在这里装配后端
渲染进程窗口里的那张网页apps/desktop-react/src/：React 画界面，用 HTTP 向后端要数据

概念依据：Electron 官方 Process Model。两份程序不能像普通函数那样直接互相调用，要通信。本课只要记住「界面在窗口里，碰电脑的能力在主进程」。启动细节见 第 6 课。

03

四层：从上到下只准往下用

仓库不是一堆平铺的文件夹。产品代码、装配代码、窗口代码被刻意拆开，这样同一套「做事的能力」可以喂给桌面、浏览器和命令行。

壳

你看见的窗口

目录 apps/desktop-react。React 画按钮和列表；窗口里的代码不直接执行 AI，也不直接读硬盘。它像遥控器：发请求、听推送、更新画面。浏览器模式也用这一套界面，只是没有 Electron 窗口。

↓ 打电话：HTTP 请求 + SSE 推送 · 中间经过 packages/client

装配

把零件拧在一起

目录 packages/backend。函数 createOnethingBackend 是唯一装配入口：按固定顺序创建事件、会话、引擎、工具，再登记可供界面调用的方法。桌面、命令行、独立服务器都走这里，只是「这台机器有哪些能力」不同。

↓ 使用产品，不反向依赖壳

产品

聊天、工具、主题这些功能

目录 packages/onething-runtime。这里写「这件事怎么做」，但不准出现 Electron，也不准去 import 装配层。换壳（桌面换成网页）不该改这一层。

↓ 使用骨架，骨架不认识产品名字

骨架

引擎底座，零业务品牌

目录 packages/core。会话、事件、权限、工具循环这些机制住在这里。它没有外部依赖，也不该出现「DeepSeek」这类具体能力的名字——能力自己登记，骨架只读表。

依赖方向只有一条：壳 → 装配 → 产品 → 骨架。产品层不能回头去找装配层。读到 import 时，用这张图判断「这行该不该存在」。

分层依据仓库 CLAUDE.md 的 Architecture Overview，并对照 2026-09-16 的 apps/、packages/ 目录。另有 packages/shared（跨进程合同）、packages/gateway（微信/Telegram 通道）、apps/cli / apps/server / apps/mobile；本课不展开，避免一次记六层。

04

一条消息怎样穿过这张图

不必一次记住函数名。只要能指着地图说人话：

  1. 你在壳里点发送。React 改的是界面上的数据。
  2. 壳通过 packages/client 打电话给装配好的后端（主进程里）。
  3. 后端调用产品里的会话与工具，走骨架里的循环：问模型 → 可能跑工具 → 再问模型。
  4. 过程中的文字增量从后端推回壳。React 收到新数据，把屏幕重画一遍。

第 2 课把这条线拆开过；第 5 课讲「打电话」怎样对上后端的方法名；第 6 课讲应用还没画出窗口之前发生了什么。今天只要能指层。
