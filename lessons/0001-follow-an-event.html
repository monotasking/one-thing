在下面这个例子中，bus 保存“事件名 → 函数”的订阅表。发布方通过事件名找到接收方，这使两边可以写在不同位置；读代码时，也就需要把这张表找回来。依据：Node.js Events

03

回到你的项目，只补一条连接

现在把教学例子中的 show 换成真实接收函数。先读这一行注册代码：

chat-source.ts · ensureSubscribed · 原代码节选

unsubStream = port.onSessionStream(dispatchSessionStream)

它的意思是：以后收到会话流消息，请调用 dispatchSessionStream。这里登记的是函数，并没有当场处理文字。

同一文件 · 收到消息后才执行

function dispatchSessionStream(payload: SessionStreamPayload): void {
  find(payload.sessionId)?.handleStream(payload)
}

这次看见下一步了：按会话 ID 找到对象，把消息交给它的 handleStream。

收到流消息→dispatchSessionStream→handleStream

证据：chat-source.ts 中搜索这两个函数；chat-port.ts 中的 onSessionStream 把回调登记到 SESSION_STREAM 频道。不要把这里的跨进程传输时序直接套用成前面的同步演示。
