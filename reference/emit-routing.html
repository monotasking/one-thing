两个 emit，
通过名字与数据接起来。

页面端 emit 是通用代码生成的发请求函数；后端 emit 是注册好的处理函数。它们通过 HTTP 交换数据。

读这段源码需要的语法

写法怎么读
type Name = { ... }给一个类型描述起名，不创建运行时函数。export 表示可供其他文件引用。
const api = {}用 api 这个名字指向一个空对象。const 限制变量重新赋值，不妨碍给对象添加属性。
api.emit取出对象里名字是 emit 的项。
api[method]先求 method 的值，再按该值找属性。method 是 "emit" 时等于 api.emit。
api.method直接找名字为 method 的项；不会读取变量 method。
(payload) => { ... }创建接收 payload 的函数。创建时不执行函数体。
api.emit(data)取出 emit 方法并调用，把 data 作为参数传入。
for (const x of list)逐个取出 list 中的元素，每次用 x 表示当前元素。
{ method, payload }对象属性的简写，相当于 { method: method, payload: payload }。
async / awaitasync 函数返回 Promise；await 等异步结果后再继续当前函数。它不代表整个应用停止。
JSON.stringify(request)把请求数据转成 JSON 文本，供 HTTP 传输。这里不会把函数实现一起传给后端。

基础依据：MDN：属性访问 / 函数 / TypeScript：类型别名。其他基础见JS 阅读速查。

先准备，后执行

准备工作（两端各自完成，不规定全局先后顺序）

类型说明：SessionCommandRoutes     → 开发时检查格式
运行时名字：session-command / emit → 路由定义
                     ├─ 客户端创建 api["emit"] 函数
                     └─ 后端登记 handlers["emit"] 函数

发送时

sessionCommands.emit(payload)
  → 客户端生成的函数
  → invoke({ domain, method, payload })
  → transport.invoke → POST /api/rpc
  → 后端 handleRpc → dispatchRpc
  → domains.get(domain) → entry.handlers[method](payload, context)
  → sessionCommandRpcHandlers.emit
  → emitToBus → emitCoreSessionCommandForIpc → eventBus.emit
  → 命令处理表 → handleSendMessage

提交结果经 HTTP 返回；AI 内容随后通过事件通道回显。

三种名字，分别负责什么

名字用途
SessionCommandRoutesTypeScript 类型名，检查接口形状。它不是本次 HTTP 请求里的地址。
domain + method
session-command + emit		RPC 层找到后端接口函数。
command.type
command:send-message		会话系统找到具体命令的处理函数。

返回值也有两层：RPC 外层 ok 表示接口分发/处理是否正常返回；里面的 data.success 表示命令提交结果。客户端解除外层包装后，调用者拿到的是里面的数据。两者都不能代替“AI 回答完成”的事件。
