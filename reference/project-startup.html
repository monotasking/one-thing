项目从哪里开始运行？

先确定启动命令，再追主进程，最后追页面入口。桌面后端通常由 Electron 主进程承载；页面通过 HTTP/SSE 访问它。

1 · 启动命令决定分支

根目录命令实际行为
npm run dev统一脚本默认 all：并行启动桌面和网页前端。后端路线让位于桌面，不额外启动独立 server。
npm run dev:electron统一脚本的 electron 模式：只管理桌面路线。
npm run dev:web网页前端 + 后端路线：发现已有 core 就复用；否则先 server:build，再启动 dist/server/main.js。
npm start
npm run electron:dev		直接进入 dev-app.mjs：构建 Electron 入口 → Vite → Electron，绕过统一脚本的进程管理。
npm run web:dev只启动 React 网页 Vite（默认 5174）；不会替你启动后端。与 dev:web 含义不同。

依据：package.json 的实际 scripts / dev-unified.mjs · main、startBackendLane。统一脚本会先清理其管理范围内的旧开发进程；上表描述清理后的正常启动。忽略 dev-self 等特殊环境分支。

2 · 桌面正常路径的源码接力

步骤入口与跳转完成意味着什么
拉起开发环境dev-app.mjs → build-electron → Vite listen → spawn Electron主进程开始执行 main.cjs。
决定 core 归属electron/main.ts · L429：whenReady → readDiscovery → isAlive已有 core：复用；否则 assembleOwnCore。
装配后端backend.ts：createOnethingBackend → assemble → assembleSteps会话、引擎、工具、RPC 等已装配；HTTP 尚待挂载。
窗口与服务main.ts · L450：createWindow → startPostWindowServices窗口开始加载；HTTP/SSE 异步启动。正常显示由 ready-to-show 触发。
发布连接embed.ts：createOnethingHttpServer → listen → writeHttpDiscovery监听成功，地址可交给页面。默认端口动态分配，可由环境变量指定。
页面取得连接index.html → main.tsx → whenConnected / connect → getConnection经 host:connection 取得 baseUrl / token；HTTP 未好就等待结果。
探测与显示createOnethingClient → 订 SESSION_EVENT → sessions.list → finally → 数据源 start → render App连接尝试完成就挂载；列表等异步返回后继续更新。

这里有两份 main：electron/main.ts 管窗口与后端；src/main.tsx 管页面。前者加载 HTML，HTML 再通过 script 引入后者。两份文件并非普通函数之间的直接调用。

3 · 后端装配内部，按执行顺序压缩

以下是 backend.ts · assembleSteps（L518 起） 的教学摘要，省略生命周期登记与辅助服务：

  1. configureAppRuntimeAdapters、applyHostPorts：接入运行环境与桌面能力，并准备外部 agent 连接器。
  2. lease.acquire：取得数据目录的独占使用权；恢复删除事务，准备会话事件日志，再 initializeStores。
  3. initializeSettings → 配置迁移与凭证升级 → initializeAgents → afterSettings（桌面在这里应用代理设置）。
  4. 建立事件、流与会话相关部件；创建 createStreamEngineLayer 和任务分发层，登记内置触发器。
  5. 准备提示词版本、权限与交互、变量和目录能力，再准备工具目录、资源与搜索服务。
  6. registerAppRpcDomains：登记业务方法；按桌面选项初始化 session skills 与协作运行时。
  7. 创建 MCP / ACP 子系统等装配产物，完成后返回 backend；桌面在创建窗口后再调用 backend.mcp.start()。

装配与启动服务是不同动作。以实际调用语句为准：main.ts 的部分历史注释仍写“不取锁”，但当前 backend.ts 确实调用 lease.acquire；不能只抄文件头理解今天的启动流程。

4 · 网页单独启动时，换掉哪一段？

  1. npm run dev:web统一脚本启动网页 Vite，并检查当前数据目录的 core 发现记录。
  2. 已有 core 就复用，否则启动 Node serverserver:build → node dist/server/main.js → apps/server/src/main.ts 的服务入口。
  3. 浏览器使用当前网页地址作为 baseUrl没有 onethingHost，因此跳过 preload / IPC 交接。开发代理读取发现信息，将 /api 请求转发给 core，并补访问凭证。
  4. 继续同一套客户端、数据源和 React 页面核心区别是“谁承载后端、地址怎么交接”，后续业务仍通过 HTTP/SSE。

依据：startBackendLane / server main.ts / Vite 开发代理配置 / sameOriginBaseUrl、connect。此处描述开发模式；打包桌面由 main.ts 的 loadFile 分支加载本地 dist/index.html。

5 · 按现象找下一处代码

现象先检查
Electron 进程没有起来dev-app 的构建结果、Vite listen 是否成功、Electron spawn。
进程存在，窗口没出现whenReady 是否进入、后端装配是否尚未结束、createWindow 与 ready-to-show；也检查是否启用离屏模式。
窗口出现但外壳还没挂载main.tsx 的 whenConnected 是否仍在等待；向前追 connectionReady、HTTP 监听和 sessions.list 探测。
外壳出现，列表读不到连接错误反馈与 sessions-source 的数据加载；外壳能画出来不等于请求成功。
请求能返回，后续变化没更新connection.ts 的事件订阅、HTTP 传输的 SSE 状态、数据源的事件处理。
改了后端源码却没有变化主进程及打包进去的 backend/core/runtime 不由页面 HMR 更新；重新运行桌面开发启动以重建并重启。

这些是按执行依赖得到的排查入口，不是对每种现象的唯一原因断言。本次未启动、重启或修改应用运行逻辑。

词语与回看入口

Vite：开发时提供页面与更新。preload：页面前执行的桥接脚本。IPC：进程间通信。RPC：将“调用某个方法”的意图送给后端执行。SSE：服务端持续推送事件的连接。挂载：让 React 从页面的 root 容器开始显示组件。

原始资料：Electron 进程模型、app.whenReady。课程衔接：启动练习 / emit 路由速查 / 消息生命周期。不清楚的连接点，可以直接带函数名问我。
