先问：我在哪一层？

读任何文件前先定位层。依赖只准向下：壳 → 装配 → 产品 → 骨架。窗口里的代码不能直接碰硬盘。

1 · 四个词

词它是什么常见误读
JavaScript浏览器与 Node 都执行的语言不是「前端专用」
TypeScript带类型标签的 JavaScript；运行前标签被拿掉不是另一门要单独跑的语言
React用 JS 写界面的库：数据变了就重画不是操作系统，也不能读写硬盘
Electron把浏览器引擎和 Node 捆成桌面应用不是 React 的一部分

Electron 进程模型：官方 Process Model。本项目里主进程常同时承载后端；渲染进程画界面。

2 · 四层对照

层目录记住这一句不准做什么
壳apps/desktop-react遥控器：画界面、发请求、听推送不要在这里实现「怎么调用模型」的核心逻辑
装配packages/backendcreateOnethingBackend 按顺序拧零件不要 import Electron / @main/；宿主能力从外部注入
产品packages/onething-runtime聊天、工具、主题等功能不要 import Electron，不要 import @onething/backend（*.wiring.ts 除外）
骨架packages/core会话 / 事件 / 权限 / 工具循环不要出现具体能力名；不要依赖 runtime / Electron

壳和装配之间的「电话」是 HTTP/SSE，客户端在 packages/client。跨进程合同在 packages/shared。这两处是配件，不当成第五、第六层来记。

3 · 同一套后端，多个插座

插座目录和桌面的差别（压缩）
桌面apps/desktop-react + Electron主进程装配后端，窗口用 HTTP/SSE
浏览器壳同一套 React，--mode web没有主进程；开发代理把 /api 转到已有 core
独立服务器apps/serverNode 进程装配后端，对外 HTTP
命令行apps/cli无窗口；工具集更瘦

另有 apps/mobile、packages/gateway。第一遍不必进这些目录。

4 · 按路径判断层

你打开的路径以…开头先当它是
apps/desktop-react/src/壳 · 渲染进程 · React
apps/desktop-react/electron/壳的主进程 · 开窗与装配入口
packages/backend/装配
packages/onething-runtime/产品
packages/core/骨架
packages/client/壳用来打电话的 SDK
