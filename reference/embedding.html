Embedding / 查资料的数字表示

文字 → 向量 → 相关原文

向量帮助定位资料；如果还要组织回答，再接生成模型。

两条执行路线

提前：资料分段 → 生成片段向量 → 保存向量、编号和原文引用。

提问时：问题 → 生成问题向量 → 比较并取 top-k → 按编号取原文 → 可选：生成回答。

依据：语义检索、段落检索、RAG 原始论文。

术语对照

术语在流程中的意思
embedding / 嵌入向量模型产出的内容数字表示；也常指生成这种表示的过程。
dimension / 维度一个向量包含的数字个数。
chunk / 片段检索时独立编码的一段内容。
cosine similarity / 余弦相似度衡量非零向量的方向接近程度，范围 −1 到 1；不是概率。
top-k按所用评分取前 k 个候选；不保证每个候选都能回答问题。
向量索引 / 向量数据库帮助组织和查找向量的设施；不等同于生成向量的模型。
rerank / 重排序对初步候选进一步评分排序，检查与问题的相关性。
RAG / 检索增强生成将检索到的资料用于生成回答；embedding 检索是常见组成部分。

参阅：相似度度量与重排序。

使用时检查这四件事

  1. 表示是否配套：问题与资料要处于同一可比较空间；按模型要求区分查询和文档编码。相同维度不保证兼容。
  2. 原文能否取回：保存编号、来源及原文或稳定引用，检索结果才可阅读和核对。
  3. 候选是否有用：检查真实问题能否找到答案；不要把高相似度当正确率。必要时重排序。
  4. 是否需要精确匹配：对订单号等精确字段，本课的设计建议是先用精确查询；混合语义与关键词检索也可进一步评估。

前三项是上述流程的实施检查；最后一项是针对精确标识符的设计建议。初学可先用少量资料逐个比较，再按规模考虑索引。
