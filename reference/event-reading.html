事件的下一步
藏在哪里？

在提前登记的接收函数里。沿着“名字 → 注册 → 函数”找回执行路线。

固定用这几个词

术语在代码里是什么意思例子
事件程序发出的某件事的通知新增一段文字
事件名／频道名用于匹配接收者的名字；真实项目可能分成两层text
数据随着通知传给接收者的内容"你好"
发布／触发发出事件，让登记的接收者得到通知emit(...)
订阅／登记先把事件名与接收函数对应起来on(...)
监听器／处理函数被登记、在事件触发时调用的函数show

阅读步骤

① 找发送点→② 记事件名→③ 找订阅处→④ 进入处理函数

如果 on / subscribe 被包装起来，继续看包装函数接受了哪个回调，以及把它登记到了哪个频道。

// 先发生：登记，不执行 show
bus.on("text", show);

// 后发生：触发，才根据登记关系调用 show("你好")
bus.emit("text", "你好");

语义参照：Node.js EventEmitter 官方文档。

三个不要混淆的地方

定义函数 ≠ 登记函数 ≠ 调用函数。分别是“准备好做法”“记住何时找它”“实际执行”。

事件驱动不规定所有系统的执行时机。Node.js EventEmitter 同步调用监听器；网络或跨进程通知要另查传输实现。Node.js · 浏览器主动 dispatchEvent 也有同步语义

订阅晚了会不会补发，要查具体机制。第一课的最小实现没有历史重放；不要推广为所有消息系统都丢弃历史。

OneThing 的一个真实接收点

// 注册：以后收到流消息，请执行这个函数
port.onSessionStream(dispatchSessionStream)

// 真收到时：按会话 ID 转交处理
find(payload.sessionId)?.handleStream(payload)

源码节选来自 chat-source.ts；完整原函数见第一课。session:stream 是频道，text-delta 是里面的一种消息类型。
