文件 chip 的 tooltip:该长什么样

昨天那笔修的是「盒子装得下字」。装下之后露出的下一层问题在你截图里:路径在连字符处被掰成两截(「lenovo-」/「scripts/ChatBot.lua」),「Open」这个动词占了半行,整条提示读起来像一句被折坏的英文,而不是一个地址。下面三台都能选,每台画同一个 chip、同一条路径,亮暗各一遍。

甲 · 只写地址,斜杠处断最小改动

去掉「Open」(动词留给无障碍名与指针光标),路径只允许在 / 后面断行。一行放得下就一行,放不下也是按目录段落折,每一行都是一个完整的段。

乙 · 名字一行,目录一行分层

你悬停时要核对的是两件事:是哪个文件、在哪个目录。第一行把名字用重一档的字重说清,第二行淡一档写目录,目录仍按 / 断。眼睛不用在一长串里找文件名。

ChatBot.lua/Users/yitiansong/data/work/lenovo-scripts

丙 · 乙 + 家目录写成 ~推荐

推荐丙,落地是一件小基础件

项定法
盒子不变:反色墨底、r-1、无箭头、上限 --tooltip-w 320、正上方居中(昨天那笔已定)。
内容第一行文件名(字重 600),第二行目录(同字号,72% 不透明度,新 token --tooltip-text-2);目录形态 chip(dir/)只画一行目录。
断行路径节点 overflow-wrap: normal,每个 / 后放一枚 <wbr>;单段超宽由 .tip 上那条 anywhere 兜底。
家目录显示层把前缀替换成 ~(家目录由 core 的 capabilities 给,壳不猜);aria-label、复制、打开一律全路径。
动词「Open」从可见文字里退出,留在 aria-label(可见文字「ChatBot.lua」包含在无障碍名里,WCAG 2.5.3 成立)。
基础件新建 ui/PathText(纯展示:收 path、home?、layout: 'inline' | 'stacked',产出带 <wbr> 的节点);Tooltip 一个字不改——它本来就收 ReactNode,不该认识「路径」。
消费者三处换内容:用户消息 RefChip、工具卡文件名、拼贴格头名。别处 tooltip 不受影响。

不做的:mono 字体(路径变宽 15%,与提示体「一律 sans」的板冲突)、箭头(板上明写无箭头)、按光标定位(系统里所有 tooltip 都锚在控件上,单独一种会跳)。
