# 「像一台系统」:onething 的桌面隐喻方案(2026-09-09)

> 状态:**方案,未动手**。用户 09-09 原话:「能不能把应用做成类似 macOS 的界面 / 使用方式,考虑系统里已有的东西,设计方案,指出想法里的盲点。」
>
> 一句话读法:**不是画一个假 macOS,是把 macOS 之所以好用的那几条规矩搬进来。** 这台壳今天已经有 Dock、浮窗、边架、分屏树、工作区、焦点链、全局快捷键 —— 它已经是一个窗口管理器了。缺的不是窗饰,是一套**一致的对象模型**和几件**系统级设施**。前两份方案(`dock-scope-2026-09.md` 的作用域、`session-continuity-2026-09.md` 的连续性)其实就是这套系统的「进程模型」和「文档恢复」两章,本文把它们收进同一张图。

## 1. 一台系统由什么组成,你今天各有什么

## 2. 对象模型:三种东西,只有三种

这是整份方案的核心,其余全是它的推论。

- **应用** = 一种内容种类的登记:图标、名字、能打开什么文档、能不能多开、作用域(全局 / 本区)、有没有 Dock 瓦。今天 `stage/items.ts` 的瓦表 + `workbench/kinds.ts` 的种类表 + `content/kinds/*` 合成一张**应用登记表**,插件贡献的面板也登记成应用(`contributes.panels` 已是声明式)。Dock 只读这张表。dock-scope 那三条自述(level / singleton / follow)就是每个应用的「进程模型」。
- **文档** = 应用打开的东西,有身份(ref:`session:<id>` / `file:<path>` / `files-root:<path>` / `diff:<repo>`),有状态可保存可恢复。会话是这台系统的主文档。连续性 C3 的「伴随面」= 文档之间的从属关系(目录 / 文件是会话这份文档的附件)。
- **窗口** = 文档的摆法:叶、浮窗、架子、全屏,将来加真窗。窗口不持有状态,状态在文档上,所以同一份文档换一种摆法(撕成浮窗、钉到架子)不丢任何东西 —— 这条今天已经成立(树/面常驻铁律)。

三条推论:

1. **Dock 上的每一块瓦都对应一个应用,每一格标签都对应一份文档。** 「总览」「检索」「设置」这些也是应用,它们的文档是单例文档(全壳一份)。
2. **关闭是关文档,退出是退应用。** ⌘W 关当前文档(标签);应用没有文档了 Dock 运行点灭。没有「退出应用」这个动作,因为这里的应用没有进程,不占资源 —— 这是与 macOS 的第一处**有意的不同**。
3. **会话是文档,不是窗口。** 所有「回到上次的样子」的规矩围绕文档保存 / 恢复写,不围绕窗口写;这样撕成真窗、开到第二台显示器时,规矩不变。

## 3. 拍定的设计(每条一句为什么)

| # | 决定 | 为什么 |
| --- | --- | --- |
| 1 | **只搬规矩,不搬皮**:不画假红绿灯、不画假菜单栏、不做桌面图标、不做 Launchpad 网格 | 用户已经在 macOS 里,系统套系统只会累;顶栏那三颗灯是真的(`trafficLightPosition`),继续用真的 |
| 2 | **分屏树是主,浮窗是辅**,与今天一致 | macOS 自己都往 Stage Manager / 窗口平铺走;浮窗自由 = 布局债(2005 年 Photoshop 面板地狱) |
| 3 | **一张命令面板 ⌘K** 顶掉检索面 + 工作区面板两个入口 | Spotlight 的价值是「一个入口」;两个入口等于没有入口 |
| 4 | **真 macOS 菜单栏**由 `KEYMAP_COMMANDS` 那张表生成 | 菜单是快捷键的说明书,两处一张表才不会分叉;Electron `Menu` 现成 |
| 5 | **⌘` 在文档间切、⌘⇧` 在工作区间切**;⌘Tab 留给系统 | 半像最糟:借了 macOS 的形就守它的键 |
| 6 | **工作区总览**基于 `expose/`(会话总览)扩成 Mission Control:每个工作区一张缩图,会话可拖进别的工作区 | 底已经有,缺的只是「按工作区分列 + 可拖」 |
| 7 | **活动面板** = 一个应用:列出在跑的会话、后台 agent、调度任务、网关、MCP 子进程,可停 | 系统必须能回答「现在谁在跑」;今天答不出 |
| 8 | **审批进通知中心**:会话流里的审批卡照旧,通知面板同时列出所有待审批,任何一扇窗都能答 | 多窗之后「审批在哪扇窗弹」必须有一个全局答案 |
| 9 | **撕成真窗** = 浮窗多一档落点;真窗与主窗共享同一台 core(HTTP/SSE 已经是这样),各自一本**窗口级**家具账 | 多显示器只能靠真窗;不改传输层 |
| 10 | **浏览器壳 / 手机是同一台系统的「单窗档」**:一次一份文档,Dock 变底栏,没有浮窗与架子 | 同一份 React 也是 web 壳;OS 隐喻在手机上退化成 iOS 而不是消失 |

## 3b. 从 Windows 借的(用户 09-09 追加:「也吸收 Windows 的交互优点」)

macOS 给的是对象模型与克制,Windows 给的是**窗口管理的手感**与**任务栏的信息密度**。两边各取所长,冲突时按 §2 的对象模型裁。

| Windows 里的 | 它好在哪 | 搬成什么 | 与 macOS 那边怎么裁 |
| --- | --- | --- | --- |
| **Snap Layouts / Aero Snap**(拖到边缘吸附、悬停最大化钮弹布局网格、Win+方向键) | 平铺是一等操作,不靠第三方 | 拖到边缘吸附今天已有(`SnapHint`、`SNAP_BAND`);加**布局网格**:标签拖起时顶部弹出「左右二分 / 三列 / 左大右小」几格,松在格上直接成形;键盘 ⌥⌘←→ 把当前文档往左右叶挪 | 与 §3.2「分屏树是主」同向,是它的手感补全 |
| **Snap Groups**(一起吸附的几扇窗当一组,任务栏上一起恢复) | 平铺的结果可以被记住、整组切回 | 就是 `pair`(二合一)与叶的 tab 组;任务栏那一半 = Dock 长按瓦时按「组」列,一点整组回来 | 无冲突 |
| **Alt+Tab 按窗口而不是按应用**,带缩图 | 你要的是「回到刚才那份」,不是「回到那个程序」 | ⌘` 切换器按**文档**列,带缩图与最近使用序;不按应用分组 | 取 Windows 的:§3.5 已按文档 |
| **Task View**(Win+Tab:虚拟桌面一排在上、本桌面窗口平铺在下,桌面可命名、可拖窗过去) | 总览与桌面切换是同一张图 | 工作区总览(P2)照它的布局:上排工作区缩图、下方当前工作区的文档;拖文档到上排 = 挪工作区 | 比 Mission Control 更直接,取 Windows 的形 |
| **Jump List**(任务栏右键 = 最近文档 + 常用任务) | 一次右键直达 | Dock 瓦右键今天已有一半(「目录」瓦的最近目录);推广:每块瓦右键 = 该应用**最近文档 + 固定项 + 动作**,固定项可钉 | macOS Dock 右键只列窗口,取 Windows 的 |
| **任务栏悬停缩图** | 不切过去也能看一眼 | Dock 瓦悬停(`useDockLens` 已有放大镜)扩成该应用文档缩图条,点一格直达 | 无冲突 |
| **关窗即退出**(没有独立的 Quit) | 少一个概念 | §2 推论 2 已是这样 | 取 Windows 的 |
| **Explorer 地址栏 = 面包屑,点一下变可编辑路径;Explorer 有标签** | 导航与输入同一个控件 | 目录面板面包屑点末段变输入框,可粘路径回车换根;目录面板按目录多开就是「Explorer 标签」 | 无冲突 |
| **Win+V 剪贴板历史** | 复制过的东西不丢 | 一个小应用「剪贴板」:壳内复制过的消息 / 代码块 / 路径历史,⌘⇧V 面板 | 与 §7 无冲突;排 P3 之后 |
| **通知飞出 + 操作中心**(通知带动作按钮) | 不切窗就能答 | 审批进通知(§3.8)照它做:通知项上直接「允许 / 拒绝」 | 同向 |
| **开始菜单打字即搜** | 零学习成本的入口 | 命令面板 ⌘K 允许 Dock 上「应用」瓦点开就是它,面板一开焦点在输入框,打字即搜 | 同向 |
| **F2 改名、Alt+F4、Alt 助记键** | 键盘一等 | F2 = 就地改名(会话 / 文件 / 工作区,`ui/inline-edit` 已有);Alt+F4 不搬(⌘W 已有);助记键不搬(与响应链三层冲突) | 半搬,理由各一句 |
| **最大化 / 还原按钮在窗上** | 一键铺满、一键回来 | 叶头「全屏」已有(真全屏);浮窗加一键「铺满中央区」= 撕回中央区并全屏,再点还原到原浮窗 rect | 无冲突,复用 `memory` 那格位置记忆 |

三条从 Windows 学的**原则**(比单个控件更重要):

1. **平铺的结果要能被记住并整组切回**(Snap Groups):这台壳的 `pair` 和叶 tab 组要在切换器、总览、Dock 长按里都以「组」出现,不是拆成单格。
2. **任务栏是信息面不只是启动面**:Dock 瓦要能答「这应用开着哪些、最近开过哪些、正在跑什么」三问(运行点 + 悬停缩图 + 右键 Jump List),不只是「点一下开」。
3. **不切过去也能看一眼、也能答一句**(悬停缩图、通知上的按钮):凡「看一眼 / 答一句」的动作不要求先切窗。审批进通知就是这一条的直接产物。

**不从 Windows 搬的**:Alt 助记键(与响应链冲突)、系统托盘一堆小图标(通知中心已经是那个入口)、窗口标题栏菜单、任务栏合并 / 不合并那套设置(Dock 按应用一块瓦,固定)。

### 分期里的落点

P1 加:布局网格(Snap Layouts)、Jump List、Dock 悬停缩图、⌘` 带缩图;P2 的总览取 Task View 的形;P3 加通知上的直接操作;P3 之后一个小应用「剪贴板」;F2 改名与面包屑可编辑各是一单小活,随 P1。

## 4. 盲点(想法里没想到、或想反了的)

1. **系统套系统。** 你的用户已经有一个 macOS。第二层窗口管理的每一个自由度(浮窗位置、层叠、最小化)都是用户要额外记的东西。判据:一个 UI 自由度只有在**用户会主动用它**时才值得给;浮窗今天真机上的用法是「临时看一眼」,不是「摆一桌」。
2. **「应用」没定义,Dock 就是杂物架。** 今天 Dock 瓦、内容种类、插件面板、MCP、外部 agent 是五种东西;macOS 的 Dock 好用是因为「上面每一个都是应用」这条不变量。先立登记表(§2),再谈像不像。
3. **主对象是会话,不是文件。** macOS 的世界围绕文件转,你的围绕会话转。照搬「桌面 = 文件」会把 AI 聊天做成一个文件管理器。桌面应该是**空舞台 + 最近的会话**,Finder 只是其中一个应用。
4. **窗口自由与分屏树打架。** 你这三个月最值钱的资产是那棵分屏树和它的拖拽 / 焦点 / 常驻规矩。macOS 式的自由浮窗会让每个「放哪儿」的决定落到用户头上。取 Stage Manager 的形:主区平铺,浮窗是暂放。
5. **多窗口的状态同源。** renderer 的 store 是每扇窗一份;两扇真窗开同一个工作区,家具账谁写?必须先定:**工作区家具是窗口级的**(每扇窗一本账,以窗口 id 为键),会话 / 设置 / 通知这些**文档与系统状态在 core 里**(已是)。`spaces.ts` 留的「两窗口开两 space」那条路正是这个方向。
6. **响应链越多窗越关键。** 每加一种窗口(真窗、总览、活动面板)都要接 `src/focus` 的三件声明,否则 Esc / ⌘F / 焦点归还立刻回到 09-02 之前。这不是可选项。
7. **性能:窗多 = 挂着的会话多。** 每一扇可见的窗都在渲染;停靠池(C1)管的是内存不是渲染。规矩:**不可见的窗不渲染内容**(隐藏面板已经不派 RO,把这条推广到浮窗被盖住 / 架子收起 / 真窗最小化)。
8. **权限与身份。** OS 的系统弹窗是模态的、有发起者身份;你的审批卡在会话流里、按会话找。多窗 + 后台 agent 之后,「谁在问、问哪个工作区、在哪答」需要一个全局答案(决定 8),否则后台 agent 的审批永远弹在一扇没人看的窗里。
9. **持久化要一次改到位。** 家具账 v4 每形态一棵树;加真窗、加应用登记表、加伴随面记录 = 账本再改。三件一起迁一次(`persist-migrate.ts` 已有迁移链),别改三次。
10. **可发现性。** OS 靠菜单栏 + Spotlight 让功能被找到;你今天只有右键菜单,新用户不知道有什么。命令面板 + 真菜单栏不是「像 macOS」的装饰,是这套系统能被用起来的前提。
11. **Web / 手机壳。** 同一份 React 也跑在浏览器里(`--mode web`)、手机端在做。OS 隐喻里的 Dock / 浮窗 / 架子在 375px 宽上全部不成立。决定 10 的「单窗档」要在对象模型层就留好,否则又是两套壳。
12. **别把「系统」当噱头。** 先答三个真场景:①三个项目并行,各自的会话 / 目录 / 改动互不打扰(= 工作区 + 伴随面);②边看文件边聊,切来切去不丢位置(= 连续性);③长跑的 agent 在后台,我要知道它在干什么、随时能停、它要审批时我能看到(= 活动面板 + 审批进通知)。方案里每一条都要能指回这三个场景之一,指不回的就是装饰。
13. **半像最糟。** 借了 Dock、借了 ⌘`、借了红绿灯,就得守 ⌘W 关文档、⌘, 设置、⌘N 新建、⌘⇧[ ] 切标签这些默认。检查表放在 §6。

| **P6 应用可装** | 插件贡献应用(图标 + 文档类型 + 瓦),市场里装一个就多一块瓦 | 插件 `contributes.panels` / `uiSlots`,市场 | 生态 |

P0 是地基,P1 是让系统能被用起来,P2–P3 才是「像系统」真正带来的新能力,P4 之后是扩张。**P0–P1 之前不碰 P4**:真窗之前对象模型和家具账必须定型,否则窗口级账本要改两次。

## 8. 它是一个应用,不是操作系统(用户 09-09 第二次追加)

用户原话:「得记住它是一个应用,不是一个操作系统。系统快捷键一定是系统先响应,我们就算拿得到也是系统先做;另外要在不同操作系统下有正确的行为。」这一节是前面所有借来的形的**约束层**,与它冲突的以它为准。

### 8.1 键盘三条礼让

1. **系统保留的键,永不申请。** 不是「申请不到就算了」,是出厂默认表里就不许出现(8.2 那张表);用户改绑到保留键时设置页那一行说「被系统占用」(与 `scopedCollisionsOf` 同一种撞车提示,第三个来源)。理由:就算 Electron 用 `globalShortcut` 抢到了,系统也先动了(切了桌面、开了 Spotlight),用户看见的是两件事一起发生。
2. **应用默认键按平台写,主修饰键抽象。** `keymap` 今天已经是 `primary` 抽象(mac = ⌘,其余 = Ctrl,`formatCombo` 按 `KeymapPlatform` 出键帽),继续用它;凡是「⌘X」在本文里出现,都读作「primary+X」。少数键在两边字面不同(8.3 表),各写各的,不硬抄。
3. **每一条快捷键都有一个非键盘入口。** 键被系统、输入法、浏览器壳吃掉时,同一件事必须还能从命令面板、右键菜单或 Dock 到达。这是 P1「可发现」的另一半理由:快捷键是加速器,不是唯一路。

### 8.2 保留键(出厂默认表禁入)

| 平台 | 系统先拿走的 | 备注 |
| --- | --- | --- |
| macOS | ⌘Space(Spotlight)、⌘Tab / ⌘⇧Tab(应用切换)、⌘H / ⌘⌥H(隐藏)、⌘M(最小化)、⌘Q(退出)、⌃←→↑↓(Spaces / Mission Control)、⌃⌘F(全屏,系统会先处理)、⌘⇧3/4/5(截图)、⌃⌘Q(锁屏)、⌘⌥Esc、⌃Space / ⌃⌥Space(输入法)、fn 一族 | ⌘` 系统交给应用(标准菜单「窗口 › 循环」),可以用;⌘, / ⌘W / ⌘N 是应用惯例,应该用 |
| Windows | 所有 Win+ 组合(Win+Tab / Win+方向 / Win+V / Win+D / Win+L / Win+数字…)、Alt+Tab / Alt+Esc、Alt+F4、Ctrl+Alt+Del、Ctrl+Esc、PrtSc、Ctrl+Shift+Esc、Alt+Space(窗口菜单)、Ctrl+Alt+方向(部分显卡驱动占用) | Ctrl+` 空闲可用;Ctrl+, 是应用惯例;F2 / F11 应用惯例(F11 全屏由应用自己做,不是系统) |

浏览器壳(`--mode web`)再叠一层:⌘/Ctrl+W、+T、+N、+L、+数字、+⇧T、F5 归浏览器,应用拿不到也不该拿。所以 §6 检查表里 ⌘W 关文档只在桌面壳成立,浏览器壳靠标签上的 ✕ 与命令面板。

### 8.3 各平台的正确行为

| 面向 | macOS | Windows | Linux | 落点 |
| --- | --- | --- | --- | --- |
| 窗饰 | 真红绿灯放进顶栏那一行(`hiddenInset` + `trafficLightPosition`,已是) | `titleBarOverlay`:系统画右上三个钮(与主题同色),顶栏其余仍是拖拽区;不自绘 | 默认原生边框;不做无边框(合成器差异太大) | `electron/main.ts` 的 `FRAMELESS_ON_MAC` 扩成三平台表 |
| 菜单栏 | 真 macOS 应用菜单,由 `KEYMAP_COMMANDS` 生成(§3.4) | 不显示窗内菜单栏(`autoHideMenuBar`),可发现性靠命令面板 + 右键;Alt 不出菜单(与响应链冲突,§3b) | 同 Windows | 同一张命令表,三种投影 |
| 关闭最后一扇窗 | 应用留在 Dock(mac 惯例) | 退出 | 退出 | `window-all-closed` 按平台 |
| 主修饰键 | ⌘ | Ctrl | Ctrl | `keymap` 的 `primary`,已是 |
| 键帽显示 | ⌘ ⌥ ⇧ ⌃ 符号 | Ctrl Alt Shift 字 | 同 Windows | `formatCombo`,已是 |
| 文档切换器 | ⌘` / ⌘⇧` | Ctrl+` / Ctrl+Shift+` | 同 Windows | 一条命令,按平台默认 |
| 移动文档到左右叶 | ⌥⌘← → | Ctrl+Alt+← → 与部分驱动撞,改 Ctrl+Shift+[ ] 之外另定,先不给默认键 | 同 Windows | 只从右键 / 命令面板到达,默认键留空 |

| 全屏 | 系统全屏(`setFullScreen`,新 Space) | 无边框最大化(F11 语义) | 同 Windows | `useHostFullScreen` 按平台 |
| 通知 | 系统通知中心 + 应用内通知面板 | 系统 toast + 应用内面板 | libnotify | 已有 `Notification` 走 Electron;审批按钮只在应用内面板(系统通知动作按钮三平台不一致,不依赖) |

### 8.4 落点

- `keymap/`:加一张按平台的 **OS 保留键表**;默认表在启动时按平台校验(单测:三平台默认表与保留表零交集);设置页撞车提示多一种来源。
- `electron/main.ts`:`FRAMELESS_ON_MAC` 改成三平台窗饰表;`autoHideMenuBar`;`window-all-closed` 按平台;菜单模板从命令表生成,非 mac 只装快捷键不显示菜单。
- `src/platform/host.ts`:renderer 只认一格 `platform: 'mac' | 'windows' | 'linux' | 'web'`,由 `host:connection` 交下来,不各处读 `navigator.platform`。
- 真机门:`gate:keymap` 三平台默认表 × 保留表零交集(纯表,不用起窗);Windows / Linux 的窗饰与菜单行为进打包门(`gate:packaged` 今天只跑 mac,加 Windows 一路时一起补)。

### 8.5 对前文的修正

- §3.5 与 §6:所有「⌘X」读作 primary+X;⌘Tab 一行删掉(本来就留给系统)。
- §3b「⌥⌘←→ 挪文档」:改为默认不绑键,只走菜单 / 命令面板(8.3)。
- §3b「Win+V 剪贴板」:应用内是 primary+⇧V,与系统 Win+V 无关;Windows 上 Ctrl+Shift+V 在别的应用里常是「纯文本粘贴」,本应用输入框内不占用它,只在焦点不在输入框时响。
- §5 P4 真窗:窗级吸附一律交给系统(8.3)。
