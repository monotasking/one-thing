# 音乐面 · 整面布局（v7）

2026-09-18 立。样例：<https://claude.ai/artifact/SnEEqJjPNdgatopJeFp3b9>（唱机音乐 App，用户看过并认可的那一版）。唱机场景与黑豆见 `docs/design/pet-system-2026-09.md` §8。

## 0. 为什么改

M1 把节目单直铺在唱机下面。用户原话：「你这个歌词我以为是歌曲列表呢。谁家歌曲列表直接往下铺一排啊。」音乐软件的做法是：歌单藏在一个按钮后面，主界面留给正在放的这一首。宠物 P1 只换了唱机那一块，整面还是老样子，所以这一单把整面补齐。

## 1. 现形

```
┌─────────────────────────────────────────┐
│ 提示行（后端没配好 / 出错，有才画）        │
│ 电台条 StationStrip                      │
├──────────────────┬──────────────────────┤
│ 唱机场景          │ 歌词（≥900 才有这一栏） │
│ 歌名 · 歌手       │                      │
│ 歌条 Transport    │                      │
└──────────────────┴──────────────────────┘
```

- **窄 / 中（< 900）**：一栏。唱机场景 → 歌名 → 歌条。歌词不在主界面上，点歌条上的「歌词」进歌词页（唱机场景整块换成歌词，页头一颗小碟点回来）。
- **宽（≥ 900）**：两栏。左边唱机 + 歌名 + 歌条，右边常驻滚动歌词，没有歌词按钮。
- **播放列表**：任何宽度都不铺在页面上。歌条上一颗「播放列表」钮打开抽屉：≥560 从右侧滑出（宽 360–400、通高），< 560 从底部升起（高 82%）。内容就是今天的 `ProgrammeSheet`（正在播放 / 接下来 / 播放历史三段、拖拽换序、右键菜单）。点遮罩、按 Esc、按 ✕ 都关，焦点回到那颗钮。

## 2. 歌条 Transport 的按钮

一行，从左到右：♥ · ⏮ · ⏯ · ⏭ · 歌词（仅 < 900）· 播放列表 · 音量。进度条在下面一行，与唱臂共用同一个位置读数。

## 3. 三张状态表

### 3.1 生命周期

| 事件 | 面做什么 |
| --- | --- |
| 挂载 | 按当前宽度定一栏 / 两栏；抽屉关着；歌词页不在 |
| 宽度跨过 900 | 两栏 ↔ 一栏。从两栏变一栏时歌词**不**自动进歌词页（回到唱机）；从一栏变两栏时，若正停在歌词页则退回唱机并在右栏显示歌词 |
| 打开抽屉 | 抽屉滑出，焦点落到抽屉里第一个可聚焦元素；主界面不动、照常播 |
| 关抽屉 | 焦点回到「播放列表」钮 |
| 换歌 | 抽屉开着不关；歌词页开着不退 |
| 电台关台 / 没歌 | 歌词页退回唱机；抽屉留着（里面是空态） |
| 卸载 | 抽屉与歌词页状态不落盘（下次开面板从唱机开始） |

### 3.2 UI 生命状态

| 状态 | 主界面 | 抽屉 |
| --- | --- | --- |
| 首载 | 唱机场景照画（素面唱片），歌名与歌条不画 | 里面三段各自不画 |
| 没歌 | 唱机空态（见 §8 空态），歌名位置一句「播放器没在跑」，歌条不画 | 「接下来」为空时那一段不画 |
| 有歌 | 歌名 · 歌手 + 歌条 | 正在播放行高亮 + 均衡器条 |
| 歌词读不到 | 歌词区一句「这首没有歌词」（≥900 右栏 / 歌词页同一句） | — |
| 出错 | 顶上提示行一句原话，其余照常 | — |
| 超量 | 歌名过长单行截断；节目单封顶 `PROGRAMME_LIMIT` 行 | 抽屉内滚动 |

### 3.3 交互

| 动作 | 结果 | 发什么 |
| --- | --- | --- |
| 点「播放列表」 | 开 / 关抽屉（`aria-expanded`） | 不发 |
| 点「歌词」（< 900） | 进 / 出歌词页 | 不发 |
| 点歌词页页头小碟 | 回唱机 | 不发 |
| 点歌词某一句 | 从这句放 | `seek` |
| 抽屉里的行为 | 与今天的 `ProgrammeSheet` 一字不改 | 原样 |
| Esc | 有抽屉先关抽屉；没抽屉在歌词页则回唱机；都没有不拦 | 不发 |

## 4. 不做

- 不做 tab（用户否过两次）。
- 不在界面上写解释性的字（「正在放」这类），状态由画面自己说。
- 不动唱机场景内部与黑豆（那是宠物 P1 / P3 的地盘）。

## 5. 门

- 壳 vitest：抽屉开关与焦点归还、Esc 两级、≥900 两栏时没有歌词钮、跨 900 的两条规矩、歌词页进出。
- `npm run typecheck`、eslint、`ui:consume`、`motion-gate`、`squeeze-gate`。
- music-lab 截图：300 / 360 / 620 / 900 / 1040 / 1280 六档 × （有歌 / 没歌 / 抽屉开 / 歌词页）。

## 6. 接入向导（装 CLI、填凭据、登录）

样例里有、壳上一直没有的那一块。今天壳只在顶上写一句「音乐后端还没配好」，然后什么也做不了 —— 用户得自己去命令行装 ncm-cli、自己登录，这句话等于把人挡在门外。

### 6.1 后端缺口（先补）

| 缺口 | 补法 |
| --- | --- |
| 登录二维码的地址到不了壳 | `ncm-cli login --background --output json` 交出的 `{ qrCodeUrl, clickableUrl }` 今天只作为 `login-output` 那条旧推送的原始输出发出去，资源事件上没有。把它记进 `OnethingMusicRuntimeState` 的新一格 `login`：`{ status: 'idle' \| 'starting' \| 'waiting' \| 'ok' \| 'failed' \| 'quota'; url?: string; message?: string }`，`state` 读法照原样交出去 |
| 壳不知道该重新问 | `music:provider` 加一条事件 `setupChanged`（无 `moment`），setup 的每一步结束后发一次；壳订它重拉 `state` |
| 「已扫码待确认」这一态后端没有 | **不编**。`login --check` 只答成没成，所以界面只有「等你扫」与「成了」两态，中间那一格样例里画过，这一单删掉 |
| 安装输出到不了壳（09-18 施工时发现的第三个缺口） | 与第一个缺口**同一个病根**：`install-output` 今天骑在 `MUSIC_EVENT` 这条宿主广播上，而 React 壳的 `voice` 端口是 `null`，它一个字都收不到——§6.3 第 ① 步那块滚动输出因此根本没有产地。补法与 `setupChanged` 同一种：`music:provider` 再加一条事件 `setupOutput { tool, chunk }`（无 `moment`），骑 `resource:event` 那条**已经在**的全局事件出去，**不新开推送通道**。产地是 `MusicSubsystem.onSetupEvent`（与 `onNowPlayingChanged` / `onPlayerFact` 逐字同形：表住子系统，换一只 CLI 不让订阅者失聪），provider 只转 `install-output` 这一种——`state` 归 `setupChanged`（一步一发才数得清），`login-output` 里装的是登录凭据，不广播 |

轮询由壳做：`waiting` 期间每 2.5s 发一次 `setup { action: 'login-check' }`，成了就停。

### 6.2 二维码要画（09-18 用户拍板，推翻本节原文）

~~`qrCodeUrl` 是一条登录地址，不是一张图；画成二维码要引一个 QR 编码库（壳今天没有，纯 JS 但仍是一笔新依赖）。这一版先给**地址**。~~ 原文的理由只有「要引一笔新依赖」，用户当天拍板**引**：`qrcode-generator@2.0.4`（零依赖纯 JS），已装进 `apps/desktop-react/package.json` 与两份锁文件。

画法钉死三条，理由逐条写在 `content/music/QrCode.tsx` 与 `content/music/qr.ts` 的文件头上：

- **自己拼内联 SVG**（一条 path），不用 canvas、不用库自带的 `createImgTag`——那是 `<img src=gif>`：位图，主题换了不跟着换、放大糊、读屏软件念不出。纠错级别 `M`，`typeNumber` 传 0 让它自适应；静区 **≥4 个模块**，由 `qr.ts` 算进 `size` 里（它是码的一部分，不是留白样式）。
- **深色主题下不反色**：两格颜色 `--qr-ink` / `--qr-paper` 在 `tokens.css` 里只声明一次、深色块里**刻意不重定义**——取景框认的是「深块 + 浅底」这个方向，反色的码有相当一部分读码器不认。
- **地址不能只剩图**：码是 `role="img"` + 一句 `aria-label`，而那条地址仍然以**文字形态**留在旁边（可选、可复制）——读屏用户扫不了码，他要的就是那条地址本身。

布局：码在左，右边一句「用网易云音乐 App 扫这个码」+「在浏览器里打开」+「复制链接」+「取消」。地址那两颗钮**保留**，不删。「在浏览器里打开」走壳既有的那条路（`content/browser-launcher` 的 `openBrowser`，也就是内置浏览器），不是 `window.open`。

### 6.3 三步

向导替掉今天那句提示，占唱机那一块的位置（电台条与节目单在这一步不画）。

| 步 | 屏上 | 动作 |
| --- | --- | --- |
| ① 装工具 | 两行：`ncm-cli`、`mpv`，各自「已装 / 没装」；没装的那行一颗「安装」；装的过程中就地展开一块滚动的安装输出（等宽字、最多 12 行、自动跟到底） | `setup check-env` / `setup install-tool { tool }` |
| ② 填凭据 | 两格输入：App ID、私钥（私钥用 `ui/SecretInput`）；一句「填完才连得上网易云」；一颗「保存」 | `setup set-credentials { appId, privateKey }` |
| ③ 登录 | 一颗「开始登录」→ 拿到地址后：**二维码在左**（§6.2），右边一句「用网易云音乐 App 扫这个码……登上了这边会自己发现」+ 地址一行（可选可复制）+「在浏览器里打开」+「复制链接」+「取消」 | `setup login-start` / `login-cancel`，`waiting` 期间壳轮询 `login-check` |

三步之间按 `setupStage` 自己走，不做「下一步」钮：后端说停在哪一格就画哪一格。装好并登录后 `setupStage` 变 `ready`，向导整块消失，唱机出现。

## 7. 跟主持人说话

样例里那条「跟夜航说点什么」。今天壳上唯一能对电台说的话是抽屉里的「点歌」输入框，而用户最早的那句要求是**「真的是电台主持人」** —— 能跟他说话、他会回、会照你说的改节目单。

### 7.1 后端：一条真的入口

电台的 DJ 本来就是一个**真 agent 在一条真会话里**（`radio-dj`，会话名「电台」，工具只有 `bash`，靠 ncm-cli 干活）。今天只有自动化的唤醒词进得去，人说的话进不去。

| 件 | 内容 |
| --- | --- |
| 做法 `music:radio` · `tell` | 参数 `{ text }`。把人说的话作为一条用户消息发进 DJ 那条会话（与唤醒词同一条 `SEND_MESSAGE` 路，同一份 `radioDj` 模型覆盖），外面裹一句「用户在跟你说话」的交代：可以改节目单 / 换台，要回话就一两句。效果 `[]`（它不出声、不改播放，真正的改动由 DJ 自己的工具做，各自过各自的闸） |
| 事件 `music:radio` · `hostReplied` | `{ text }`，`moment: { weight: 'high', gist: '用户跟主持人说了话，他回了一句' }`，负载带 `say`。**这是宠物开口的产地**：P4 的直通作曲器认 `payload.say`，所以黑豆会把这句话说出来（有语音就出声，没有就只出气泡） |
| 回话怎么拿到 | 装配层订那条会话的流结束事件（`STREAM_COMPLETE`），取这一轮最后一条 assistant 文本；空文本 = 不发事件（他用工具干完活不说话，是合法的） |
| 超时 | 60s 内没有流结束就放手（不发事件、不报错）。DJ 可能正在跑一长串 bash |

**音乐域仍然不认识宠物**：它只发事实。

### 7.2 壳：面板底下一条话

| 件 | 形 |
| --- | --- |
| 位置 | 音乐面最底下一行（电台开着才画），窄宽都在；抽屉拉开时仍在 |
| 输入 | 一格圆角输入，占位「跟{名字}说点什么」（名字取当前宠物） |
| 建议词 | 聚焦时在输入框上方浮一排三颗：「换个心情」「点一首歌」「现在放的是什么」。点一下 = **填进输入框**（不直接发），人自己按回车 |
| 发送 | 回车发 `tell`；输入框当场清空 |
| 你说的话 | 发出去之后在输入框上方冒一枚**你自己的气泡**（右对齐、灰底），停 6s 自己散；它只是回执，不落盘、不进任何列表 |
| 等他回话 | 发出后到 `hostReplied` 之间，黑豆是 `busy` 姿势（他在翻唱片 / 在想）；超过 60s 自己恢复 |
| 他回的话 | 走 `pet:` 的话语那条路（P2/P4 已通），气泡出在唱机那边的黑豆头上，不在这条输入框上 |
| 打字时 | `PetStage` 的 `listening`（歪头、耳朵抖）—— P0 已有这一格，这里只是把它接上 |
| 电台关着 | 这条不画（没有主持人可说话） |

### 7.3 状态表

| 状态 | 屏上 | 发什么 |
| --- | --- | --- |
| 空闲 | 一格输入 | — |
| 聚焦 | 上方三颗建议词 | — |
| 打字 | 建议词还在；黑豆 `listening` | — |
| 发送中 | 输入清空、你的气泡冒出来、黑豆 `busy`；输入框仍可再打字（可以连着说两句） | `tell` |
| 发送失败 | 输入框下一行错话（后端原话），你的气泡撤掉；输入里的字**还回来**，别让人重打 | — |
| 他回了 | 黑豆气泡说那句话；这条输入框什么都不变 | — |
| 60s 没回 | 黑豆从 `busy` 回到该在的姿势，无提示（他可能只是干了活没说话） | — |

### 7.4 门

- 后端：`tell` 发的那条消息形（裹的交代 + 模型覆盖 + `suppressTitleGeneration`）、流结束取最后一条 assistant 文本、空文本不发事件、60s 超时收手、`hostReplied` 带 `moment`。
- 壳：回车发一次且只发一次、失败把字还回来、建议词只填不发、`busy` 起止、电台关着不画、打字时 `listening`。
- 根门 typecheck / boundary / assembly / transport / log；壳门 typecheck / eslint / ui:consume / motion / squeeze。
- `?music-lab` 补一格「他回了一句」的样本。

## 8. 样例里剩下的六条（纯壳）

样例（<https://claude.ai/artifact/SnEEqJjPNdgatopJeFp3b9>）里还没落地的八条里，这六条不需要后端加东西。剩下两条（播放历史、封面与时长）等后端补读法与字段，另一单。

### 8.1 播放列表：头上加一段「正在播放」

抽屉里今天只有「接下来」。加一段在它上面：

| 件 | 形 |
| --- | --- |
| 段头 | 「正在播放」。`nowPlaying` 没歌时整段不画（不留空段头） |
| 那一行 | 与「接下来」的行同宽同高；左边碟形色块，中间歌名 + 歌手，右边一组**均衡器条**（三根，按拍起伏；`prefers-reduced-motion` / motion-tier `none` 下不动，改成静止的三根） |
| 行底 | 一条**进度**（细，贴着行底边），吃 `usePlaybackPosition` 那同一个数 |
| 交互 | 整行**不可点**（它已经在放了）；没有把手、没有 ⋯ 菜单 |

### 8.2 行的碟形色块 + 悬停即放

| 件 | 形 |
| --- | --- |
| 色块 | 每行左边一枚圆形色块，颜色按歌名散列（复用唱机场景那只 `sleeveColorsFor`，同一首歌在哪儿都是同一个颜色），中心一个小孔 —— 是一张唱片的样子，不是封面占位图（封面这件事后端没有，见 §9 留账） |
| 悬停 / 聚焦 | 色块上浮出一颗播放三角，点它 = **立即播放**（发 `programmeAction` 的 `promote` + `next`，与右键菜单里那条走同一条路，不新开做法） |
| 键盘 | 那颗三角是真按钮，`aria-label`「立即播放{歌名}」，Tab 到得了 |
| 右键菜单 | 「立即播放」那一项**保留**（两条路不冲突，键盘用户与鼠标用户各有各的） |

### 8.3 主持人要先说话的那首：小话筒

`entry.say` 有值的行，歌名后一枚小话筒图标；`ui/Tooltip` 悬停 / 聚焦看那句话（长了截断，整句在 tooltip 里）。没有 `say` 不画。

### 8.4 歌词页：他开口时压暗

黑豆开口时（`usePetOnAir`）：

| 件 | 形 |
| --- | --- |
| 歌词 | 整块压暗（`opacity` 降一档 + 不跟唱：当前句不再自动滚），230ms 过渡 |
| 他的话 | 浮在歌词上方居中一块（与唱机那边的气泡同一套皮，但不带尾巴），逐字出现跟宠物气泡同一个节奏 |
| 结束 | `hushed` 到了（或话语过期）恢复：亮回来、跟唱接上当前句，不补滚动动画 |
| 宽屏右栏 | 同样适用（右栏歌词也压暗；唱机那边的气泡照旧在黑豆头上，两处同时出现是对的 —— 一处是"他在说"，一处是"歌词让位"） |

### 8.5 歌词加载骨架

`lyrics` 读法还没回来、且这首歌**有可能有歌词**（有歌名、电台在放）时，画三行灰条（宽度 70% / 55% / 62%，轻微呼吸），而不是空白。读到了就换成歌词；读到的是"没有歌词"则是今天那一句话。

### 8.6 电台关着：心情色块

`StationStrip` 的开台卡里，把今天那排文字预设换成**四枚色块**（每枚一个心情：下雨天、专注、周五、开车；色由该心情自己的一对颜色画成斜向渐变，块上印那两个字）：

| 动作 | 结果 |
| --- | --- |
| 点色块 | **直接开台**（`open { intent: 那句预设的完整意图 }`），不是填进输入框 |
| 输入 + 开台 | 保留：自己打字那条路不变 |
| 「继续这一台」 | 保留在色块下方 |
| 键盘 | 每枚色块是真按钮，`aria-label` 是那句完整意图 |

### 8.7 状态表（这六条合起来的增量）

| 状态 | 屏上 |

| 抽屉里没歌在放 | 只有「接下来」段 |
