# 发送 · 等待 · 生成 · 收尾 · 重试 —— 一条座位(2026-09-15)

正本。样例页 `docs/send-flow-proposal-2026-09-14.html`(可交互,页内每帧量位移),用户 09-15 拍「可以实现了」。

## 0. 起因与推翻的拍板

用户 09-14:「发送消息要非常自然;发送之后自动留出足够的空白;后续 waiting / generating 都非常连贯;流式结束后也要连贯;重试的动画、交互。」

这推翻 `docs/workbench-2026-09.md` 拍点 ⑤(09-04:发送后自己那条**落底 + 跟随**,置顶留账不做)。从今天起:**发送后自己那条置顶,下面整个视口留给回复**。

今天的三处病,都在真机量过(09-14 本会话):
- 发送后自己那条落底,回复在它下面一行一行往上顶,等待期间那段是三个点,首字到了点换正文,视口跟着每一段长高往上滚。
- 收尾那一帧思考段自动折叠:6 万像素一帧缩到 783px,上一条用户消息的 top 从 −60,879 跳到 −286(`probe-stream-end.mjs`),整屏跳变。
- 重试没有任何动画:按下去屏幕不动,等账本删完旧回复再从头画。

## 1. 一句话

**座位**:发送那一帧自己的话原位变气泡,滚到置顶线,最后一轮的下面留出「视口减掉置顶线以上」那么高的空白。之后等待、上下文更新、思考、正文、工具卡全在座位里长;**座位没长满之前视口一像素不动**,长满了自然接上今天的跟底。收尾只做两件事:思考段**锚住视口里正在读的那一行**折回一行;外缘那一行三张脸同格同高只换透明度。重试:按下即开槽,旧回答向上折进座位上缘(锚住自己那条气泡),同一帧折痕开始扫。

## 3. 座位模型(几何)

```
视口上缘 ─────────────────────────────  y = 0
        ── 置顶线 ──────────────────  y = --send-line (24)
        [自己那条气泡]
        [回复:折痕 / 思考 / 正文 / 工具卡 / 外缘那一行]   ← 长
        [座位垫块  data-seat]                              ← 缩(长多少缩多少)
视口下缘 ─────────────────────────────  y = clientHeight
```

- 座位高 `seat = max(0, clientHeight − sendLine − turnHeight)`,`turnHeight` = 从自己那条气泡上缘到回复下缘。**只在最后一轮上有座位**;发送新一条时上一轮的座位在同一次提交里由新气泡原位接管(上面的旧内容一像素不动)。
- 座位 > 0 时**跟底不发**(`grew` 不 stick):内容长进座位,视口不动。座位 = 0 之后照旧 pinned 跟底。
- 视口太矮(`clientHeight − sendLine < 3 行`)退化为今天的落底 + 跟随。
- 自己那条比视口还高:上缘落置顶线,座位取下限三行。
- 人往上翻(browsing):座位照旧,视口不追。
- 窗子 resize:座位重算,`scrollTop` 不动。
- 换会话 / 冷载:没有座位(座位是「刚发送」的产物,不落盘);切回停靠的会话时如果那一轮还在流,座位按当前几何重算。

## 7. 与既有法的关系

- `follow.ts` **一个字不改**:座位与折叠锚定都是 `ChatStream` 那只 hook 里几何层面的事(什么时候 stick、stick 前减多少),状态机判据「只有位置与意图」不变。
- 第四处 `scrollTop` 写点(滑到置顶线)与既有三处(进场 / 长高 / 扩窗补位)并列,判词写在它上面;JS 插值,不用 `scrollTo({behavior:'smooth'})`(定位不是动效,档「无」下照样工作)。
- 观察器回调只读不写(`project_resize_observer_loop_2026_09`):座位高经 `FrameCoalescer` 下一帧写;折叠补偿写的是 `scrollTop`(不改布局),允许在 RO 里直接写。
- 动效:`@keyframes` 只在 `styles/motion.css`(光扫沿用 `--kf-seam-sweep`);JS 时长只在 `components/motion.ts`(新加 `SEND_LAND_MS`=180 / `SEND_LAND_MAX_MS`=320 / `FOLD_MS`=180,与 tokens 镜像);`--send-line` 进 `tokens.css`。
- 三点(`ui/Dots`)在聊天区退役,丸上的三个点不动。

## 8. 留账

- 流式期间读数行跟着正文下缘走;重试档「上折 + 首字」撞在 400ms 内会出现一次先上后下。把读数行钉在座位底边是另一个拍点,本单不做。
- 「上一次回答」版本芯片:core 的 retry 是删掉重开,账本没有版本,先要账本支持。
- 座位不落盘:切走再切回时,如果那一轮还在流,座位按当前几何重算;已经收尾的不再有座位(与「换会话 = 一次新的进场,落底」一致)。

## 9. 单 B 落地记(2026-09-15)

④⑤⑥ 三条与它们的真机门。**判词与 §2 有出入的地方以这一节为准**,逐条写明为什么。

### 9.1 与设计不一样的四处

1. **折叠的锚是「块」,不是「行」**(④)。§2 那句「这条回复里视口内第一块在读的
   东西」第一版实现成了「列里第一件下缘还在视口内的东西」—— 那一句在收尾这一刻
   恒等于**那条助手行自己**,而一块内容缩了、**它所在的那一行的上缘一动不动**,
   于是「锚漂了多少」恒为 0、补偿一次都没发生。`pickFoldAnchor` 现在一层层往里钻
   (同层二分,`bottom` 单调),直到某一件**整个**落在视口上缘之下。门那一侧的
   `anchorOf` 同一条改判 —— 量行会把「`scrollHeight` 塌了、浏览器把 `scrollTop`
   钳回来」读成「屏幕跳了 1517px」,而那一刻行里的正文其实在原地。
2. **重试那道空折痕自己一行**(⑥)。§2 写的是「折痕接着旧回答扫」,而旧回答此刻
   挂着 `.rowRetiring`(`height: 0` + `overflow: clip`),画在它里面的东西跟着一起
   折没了。它现在是 `retrySeamRow`,排在正在上折的那一条**后面**(新一轮的回答就
   从那儿起),形与 `contextSeamRow` 逐字相同:不带 `data-message-id`,报
   `data-retry-of`,走 `.rowLate` 软着陆。
3. **重试的落位排在「那一发回来了」那一拍**,不是按下那一拍(判词在 `landOnRetry`
   的那只 effect 上):按下那一拍旧回答才刚开始上折,算出来的置顶线按的是旧高度。
4. **⑤ 那 12px 的真正治法是「收场那一拍把座位同步补到位」**,不是三张脸同格同高。
   反证分别跑过(9.3):把 grid 退回条件渲染,②b 仍是 0.0px;把那一句同步补座位
   拆掉,②b 当场 24.0px。三张脸同格同高仍然留着 —— 它是**结构上**的那一半(这一行
   的高从此与「此刻是哪张脸」无关),由 `chrome-faces.test` / `message-chrome.test`
   钉着;但真机上能量出差别的是座位那一句,报数时别把功劳记错。

### 9.2 门这一侧的五处改动(`scripts/gate-send-flow.mjs`)

- **长回那一支长出了自己的思考段**(`LONG_THOUGHT`,6,000 字,开头 24 段走慢档)。
  没有它,④ 那条断言挂在两支**根本没有思考段**的场景上,恒绿:把补偿整句拆掉重跑,
  门照样全绿。**一条恒绿的断言不是守卫。**
- **④ 在超量那一档转判**(原本只报不判)。它是唯一量得出这条治法的一档:拆掉高度
  过渡 + `fold-intent` 重跑,常态 / 长回 / 重试三档仍是 0.0px(那三档折叠两三千像素,
  浏览器自己的滚动锚定接得住),**超量当场 1459.8px** —— §0 三处病之二的原样。
- **⑥ 多一格「旧回答多久开始上折」**(`retireAtMs`)。折痕那一格在这台机器上分不出
  治没治:假 provider + 同进程 core,账本删旧回复、开新 run 只要一帧(反证实测:把
  `retryPending` 那条路整个拆掉,折痕照旧 17ms 就在扫 —— 那已经是新一轮自己的折痕)。
  `.rowRetiring` 只有壳那一路给得出,所以判据落在它上面。
- **「一段滚动」的断开判据要看得见地停过**:静够 `QUIET_MS` **且**至少有一帧采到它
  没动。超量那一趟落位段里有一帧长达 1125ms,只按时间判会把「没采到样」读成
  「停了一秒」,一段连续的落位插值被劈成两段,① 判红 —— 红的不是产品,是那一帧太长。
- **折痕在不在、第一块内容什么时候上屏,都改由 `MutationObserver` latch**,不靠 rAF
  采样;超量那一档的 900ms 等待段里 rAF 一共只回调一两次。随之**超量的「折痕真的
  上过屏」摘掉断言只留读数**:机器一忙,壳给这一轮提交的第一帧会晚于第一个字落地,
  折痕一帧都没画过(latch 与采样两边一致地说没有),判它等于判机器忙不忙;而 ① 的
  落位窗现在由 `firstContentAt` 兜底,不再牵在折痕上。

- **「收尾锚定」这一族每一档都先判「量到没量到」**(审查补的):位移那条判据有一个
  恒绿的逃生口 —— 收尾那一帧没采到时 `endFrames` 为 0、`endAnchorShift` 与自己比
  恒为 0,整条直接放行,正是 `docs/thinking-stream-2026-09.md` §7.1 那句
  `p95 of []` = 0 的形。三档各补一条 `endAt >= 0 && endFrames > 1`,并删掉常态与
  超量那两处 `endAt < 0 ||` 的短路。守的是**没量到**这一支,不是位移本身。
  顺带换标号:这一族说的是**正本 §2 规矩 ④**(收尾锚定折叠),与单 A 那条
  「④ 读数行方向反转」不是一件事,门里一律写名字 `[收尾锚定]`,不再挂号。
