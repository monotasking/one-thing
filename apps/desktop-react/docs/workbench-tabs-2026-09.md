# 标签条与拖拽 v3：一条标签条、一个标签最多两格、每一步都有回应

2026-09-05。接 `workbench-2026-09.md`（拼贴台 v2 正本）。v2 的八批已全部合入 main（W1-a 7347cb52 … W5-b eec30723），用户在真机上连报三轮：

- 拖一条会话到顶栏的标签上，不知道能不能放，没有任何交互、手感、提示；
- 拖不到聊天区；文件还是只能打开一个标签；
- 「拖拽 session 的 tab 本就是个伪需求，我最多就是一个分屏，往一个 tab 有两个（二合一）的方向设计」；
- 「files 本身应该是一个可以打开多个的存在，例如 note、例如 workdir，名字应该和 viewer 差不多，设置为目录名」；
- 「手感很差，tab 为什么拿不出来？点击和拖拽都分不清」；「好好设计一下 tab header 上的拖拽、排序」；
- 「不知道为什么 tab 背景颜色变了，拖拽没有浏览器的 tab 的丝滑、流畅和交互感」。

这份文档把这些话收成一个模型、一套手势、一张反馈表和三批施工。它**推翻 v2 在中央区的两条决定**：任意分屏树不再暴露给用户，顶栏不再按叶分组画多条标签条。架子与浮窗里的树照旧（W4 的结构不动），但它们的檐也只暴露标签与二合一，不再暴露「分屏 ▸」菜单。

## 1. 借谁的手感

成熟的拖拽体验不是发明出来的，是从用户已经练过的肌肉记忆里借来的。本方案每一条手势都能指出出处：

| 手势 | 出处 | 我们的用法 |
| --- | --- | --- |
| 按下标签立刻切换，不等松手 | Chrome、Safari、Finder 的标签 | 按下即选中，松手不动就是一次点击 |
| 横向拖动很小的距离就开始换序，被拖的标签跟手、邻居滑开让位、松手滑入槽位 | Chrome 标签条 | 横向 6px 起拖；邻居 120ms 让位；松手 150ms 滑入 |
| 被拖的标签**长得和原来一模一样**，只是浮在邻居上面；其它东西一律不变色 | Chrome 标签条 | 被拖标签不换底色、不放大、不改形，只加一层很轻的投影 |
| 竖向拉出标签条一段距离才「撕」下来 | Chrome 拖出新窗口 | 竖向离开标签条 24px 撕下成卡片 |
| 把一个标签放到另一个标签上 = 两个并排 | Arc 的 Split View、Safari 的分屏 | 二合一 |
| 拖到项目**上**与拖到项目**之间**是两件事，由位置决定 | Finder 列表里拖进文件夹 vs 插到两项之间 | 标签往下压 6–24px 放到另一个标签上 = 二合一；在条里横着走 = 换序 |
| 落点在内容区上显示「落下后占的那一半」 | VS Code 编辑器拖放 | 内容区右侧 28% 带亮出右半边 |
| 拖着的东西下面挂一行说明 | macOS 拖放的角标（＋ / ✕）、Figma 的拖拽提示 | 浮影下常驻一行「松手会发生什么」 |
| 不能放的地方光标变禁止、松手弹回 | macOS / Windows 通用 | 拒绝态 |

## 2. 模型：中央区只有一条标签条，一个标签最多两格

### 2.1 数据结构

中央区不再是任意深度的拼贴树。它是一条标签列表，每个标签装一格或两格内容：

```ts
/** 一格内容，与 v2 的 ContentRef 完全相同：种类 + 键。 */
interface ContentRef { kind: string; key: string }

/** 一个标签。panes 长度为 1 或 2，永远不会更多。 */
interface Tab {
  id: string
  panes: [ContentRef] | [ContentRef, ContentRef]
  /** 两格时左格占的宽度比例，0.2–0.8，缺省 0.5。拖分隔杆改它。 */
  ratio: number
}

/** 中央区。 */
interface CenterStrip {
  tabs: Tab[]
  /** 活动标签的下标。 */
  active: number
}
```

它与 v2 树的关系是：**中央区的树退化成一片叶**，叶里每一格 tab 就是上面的 `Tab`。两格的标签在树上是一个 `row` 切分节点带一个比例；一格的标签就是一个 `ContentRef`。也就是说，v2 的 `PaneNode` 类型不删，只是中央区永远只允许深度 1，`splitLeaf` 在中央区没有调用者。架子与浮窗里的树也按同一条政策渲染：一片叶 = 一条标签条，标签里至多两格。

为了让「两格」在登记表里也是一种内容而不是特例，加一种内容种类 `pair`：

```ts
/** kind = 'pair'，key = `${refId(a)}|${refId(b)}`。 */
registerContentKind({
  id: 'pair',
  title: (ref) => ({ text: `${titleOf(a)} ⫽ ${titleOf(b)}` }),
  icon: (ref) => iconOf(a),
  render: (ref) => <PairPane a={a} b={b} />,   // 两格各自 renderRef，中间一根 ui/Splitter
  beforeClose: (ref) => 两格各问一次，任一格说「别关」就不关,
  dispose: (ref) => 两格各 dispose,
})
```

这样 `workbench/*` 里一个字都不用出现「两格」这个概念：树上它就是一格 tab，标签条画它的标题，关它就是关它。「拆开」是把一格 `pair` 换成两格普通 tab；「二合一」是把两格普通 tab 换成一格 `pair`。两个动作都是 `tree.replaceRef` / `insertTab` / `removeTab` 的组合，不需要新的树操作。

### 2.2 为什么是两格不是树

用户原话是「我最多就是一个分屏」。任意树带来的三个代价——顶栏要按叶分组画多条标签条、每片叶各有一组动作、落点要判五个方向——在两格模型里全部消失：顶栏只有一条标签条；动作组只有一组；落点只剩「并成新标签」「与它并排」两种。VS Code 支持任意编辑器组，但绝大多数人只用到左右两个；Arc 的 Split View 最多四格，常用的也是两格。两格是够用的上限。

### 2.3 三条不变量

1. **一个内容在中央区只出现一次**。把已经开着的文件拖到别处是搬，不是复制（v2 已是如此）。
2. **会话标签至少有一个，且不可关**（v2 的 `resident` 契约不变）。
3. **两格标签里两格不同**。把 A 拖到「A ⫽ B」上是空动作，不是替换。

## 3. 文件面板按目录多开

今天 Dock 上一块「Files」瓦，只会打开工作目录，名字永远叫 Files。改成：

- **每个目录是一份面板内容**：`files-root:<绝对路径>`（W3 已登记这一种，本方案把它扶正为文件面板的唯一形态，`panel:files` 退役）。标签与瓦上的名字是目录名（`basename`），Tooltip 是全路径；两个目录同名时名字后面带上父目录（`docs · a` / `docs · b`），与查看器对同名文件的做法一致。
- **Dock 上那块瓦改成「目录」**：点它打开当前会话的工作目录那份面板；右键菜单列出最近打开过的目录和「打开目录…」（系统对话框）。打开过的目录记在 workbench store 里按工作区持久化，最多记 20 个。
- **一个目录面板可以住在任何地方**：左架子、浮窗、中央区的一个标签，都行。两个目录面板并排是常态：左架子那条标签条上就是 `start-electron | notebook`。
- **文件单击 = 开一个标签**（在焦点标签条的末尾），已经开着就切过去并让那个标签闪一圈。预览标签整体退役：`Tab.preview` 字段、斜体标题、单击顶替、↵ 固定这四样一起删。理由：预览是 VS Code 为「快速翻看很多文件」设的，代价是用户搞不清为什么只有一个标签；这次用户明确说了他要的是多个标签。真机复现还抓到 `tree.insertTab` 对已开着的 ref 提前返回、`preview:false` 永远清不掉的 bug，随退役一起消失。

## 4. 手势：一张状态机

### 4.1 阈值

| 常数 | 值 | 为什么 |
| --- | --- | --- |
| `DRAG_START_X` | 6px | 标签横向起拖。比 W3-b 的 8 小一点：换序是标签最常见的拖法，起得要快；但要比触控板的点击抖动（2–3px）大。 |
| `DRAG_START` | 8px | 行、瓦等来源的起拖，任意方向。 |
| `TEAR_OFF` | 24px | 竖向离开标签条多远算撕下。等于标签条高度的三分之二，与 v2 的 `TEAR_OFF_DISTANCE` 同值。 |
| `ONTO_FROM` | 6px | 指针低于标签条底缘多少算进入「放到标签上」带（到 `TEAR_OFF` 为止）。第一版用的是停驻 300ms，真机上换序途中稍一停顿就误并，改成位置判据。 |
| `NEIGHBOR_MS` | 120ms | 邻居让位的过渡。 |
| `SETTLE_MS` | 150ms | 松手滑入槽位。 |
| `PAIR_BAND` | 28% | 内容区左右各多宽算「与它并排」。 |
| `TAB_MIDDLE` | 44% | 标签正中多宽算「落到它上面」，两侧各 28% 算「落到它旁边」。 |

### 4.2 标签上的手势

```
idle ──按下──▶ pressed（当场激活这个标签；光标 grabbing；标签本身不动、不变色）
pressed ──松手，位移 < 6──▶ idle（一次点击，到此为止）
pressed ──|Δx| ≥ 6──▶ reorder
pressed ──|Δy| ≥ 24──▶ tear

reorder：被拖标签浮到邻居上面（只加一层很轻的投影，不放大、不改形、不换底色），
         x 零延迟跟手，夹在标签条两端之内；
         邻居让位的判据是**被拖标签朝运动方向的那条边越过邻居中心**（Chrome 的规则）：
         往右拖看被拖标签的右边缘，右边的邻居中心被它越过就滑到左边去；往左拖看左边缘。
         不是中心对中心——中心对中心时宽标签要整个越过窄邻居才换位，手感发黏，而且永远够不到末位；
         也不是把邻居按「拿走被拖那格之后」的位置算——那样宽标签一抬起来右邻居就先跳一下。
         邻居中心用抬起那一刻量好的位置算，不读正在过渡中的活矩形，否则拖快了槽位会漂。
         最终下标 = 左边仍未被越过的邻居数 + 右边已被越过的邻居数，不再另外加减；
         标签条与内容区**什么都不变色**——浏览器换序时屏幕上只有那一格标签在动。
reorder ──指针压到标签条底缘下 6–24px──▶ onto（邻居不再让位；指针底下那个标签描圈亮起；浮影只剩一行「与 X 二合一」）
onto ──回到条内──▶ reorder
reorder ──竖向离开标签条 ≥ 24──▶ tear（原位折成 0 宽、邻居合拢；标签变成一张卡片跟手）
tear ──回到标签条带内──▶ reorder（原位展开，继续换序）
reorder ──松手──▶ moveTab；被拖标签从手上的位置 150ms 滑进新槽，落定闪一圈
onto ──松手──▶ 二合一（被拖标签并进目标标签的右格；目标已是两格则替换右格；指针底下没有标签 = 滑回）
tear ──松手──▶ 按 §5 的落点表落定；落在自己那格的内容区 = 放回
任何态 ──Esc / pointercancel / 窗口失焦──▶ 滑回原位（150ms），树一字不变
```

「按下即激活」是 Chrome 的做法，也是用户「点击和拖拽分不清」的解药：按下那一刻反馈已经给了（内容切过去了），后面要么松手结束，要么拖走。实现上它要求**标签条 DOM 在按下时不能重建**——只换活动态属性和内容区，被按住的元素必须还在手里。样例第一版就是在这里失手的。

### 4.3 行、瓦上的手势

```
idle ──按下──▶ pressed（抬起 1px；光标 grabbing）
pressed ──松手，位移 < 8──▶ 打开（文件：末尾开新标签或切过去；会话：焦点标签的会话格换成它；目录：打开目录面板）
pressed ──位移 ≥ 8──▶ drag（浮影卡片：图标 + 名；行本身留在列表里变淡）
drag ──移动──▶ 按 §5 的落点表实时判定并显示
drag ──松手──▶ 落定；卡片 180ms 飞进空位/槽位；落定的标签闪一圈
drag ──松手在拒绝态──▶ 卡片弹回来源行
```

### 4.4 触控板与鼠标

两者走同一套 pointer 事件。触控板上「按住拖动」是三指或按住不放，阈值不变。双击不做任何事（本仓判例：双击与右键在触控板上打架）。

### 4.5 流畅的三条硬规矩

浏览器标签拖起来「丝滑」不是动画多，是三件事都做对了：

1. **被拖的东西 1:1 跟手**：每一个 `pointermove` 直接写 `transform`，不经 React、不节流、不加缓动；被拖标签的过渡关掉，`will-change: transform` 提前声明。
2. **只有该动的在动**：邻居用 120ms 过渡滑开；标签条、内容区、其它标签的颜色一律不变。所谓「起拖后可放的地方淡亮」只用于**从外面**（会话行、文件行、Dock 瓦）拖进来的情形，换序时不做。
3. **反馈是同一个节点在挪**：空位是同一格只在落点变化时换位置，圈和半边是同一个覆盖层换矩形；任何按帧拆掉重建的反馈都会被看成闪烁。

## 5. 落点与反馈：一张表

拖拽期间**先判后画**：每一帧算出唯一的落点，再按表画反馈。判定次序从上到下，先命中先赢。

| 落点 | 判定 | 屏幕上 | 浮影下那行字 | 松手 |
| --- | --- | --- | --- | --- |
| 拒绝区 | 指针在红绿灯、顶栏尾格、Dock 上 | 卡片变灰、虚线边；光标 not-allowed | ✕ 这里不能放 | 弹回 |
| 标签正中 | 指针在某个标签中间 44%（被拖标签自己除外） | 那个标签描圈、底色亮 | 与「X」二合一 / 替换「X 的右格」 | 并成两格 |
| 标签之间 | 指针在标签条带内，不在任何标签正中 | 那个位置腾出一格带边的空位（宽 = 卡片宽）；悬到的标签让开 | 放到第 n 位 | 插入 |
| 窗口边带 | 指针在窗口四边 24px 内 | 那条边亮一层薄膜 | 钉到左侧架子 | 进架子 |
| 内容区右带 | 指针在活动标签内容区右侧 28% | 右半边亮出来；两格时写「替换 X」 | 与「X」二合一 · 放在右侧 | 并成两格 |
| 内容区左带 | 指针在左侧 28%，且活动标签是一格 | 左半边亮出来 | 与「X」二合一 · 放在左侧 | 并成两格，它在左 |
| 内容区中间 | 其余 | 内容区描一圈；标签条末尾腾空位 | 开成新标签 | 末尾开新标签 |
| 自己的内容区 | 拖的是活动标签本身 | 不画 | 松手放回标签条 | 放回 |
| 窗外 | 指针出了窗口 | 卡片变成一张虚线窗轮廓 | 松手成新浮窗 | 新浮窗 |

两条贯穿所有落点的规则：

1. **从外面拖东西进来时**，起拖那一刻所有能放的地方先淡淡亮一层（标签条、内容区、四条边带各铺一层 6% 的主题色），悬到的那一处再亮到实。换序不适用（§4.5）。
2. **浮影下那行字永远不空**。落点变了字就变，没有落点写「松手放回」。这是唯一一处在拖拽期间出现文字的地方，内容区上不再写字（v2 的色块加文字太重）。

反馈都是同一个 DOM 节点在挪，不是拆掉重建：空位是同一格只在落点变化时换位置，圈和半边是同一个覆盖层换矩形。样例第二版「标签条上没手感」的病根就是空位每帧重建、宽度动画永远从 0 起。

## 6. 二合一的细节

- **哪一格是焦点**：点哪格哪格拿焦点；输入框跟着有会话的那一格（路线 B，W5-b 已如此）。两格都是会话时跟最近点过的那格。
- **标签的标题**：`A ⫽ B`，两个图标各自画，中间一根 1px 竖线；最大宽度 260px，长了各自截断。
- **格头**：每格顶上一条 28px 的小檐，写这格的名字和一颗「拆开」；一格标签没有格头（与今天一样）。
- **拆开**：右格拆出去成为紧邻其后的新标签，左格留在原标签里，焦点留在原标签。
- **关闭**：关一格标签 = 两格各问一次 `beforeClose`（脏文件确认），任一格拒绝就不关。关格头上的 ✕ 只关这一格，另一格变回一格标签。
- **分隔杆**：`ui/Splitter`，比例存在标签上，键盘 ←/→ 5% 一步。
- **持久化**：`pair` 就是一格普通 ref，随中央区标签列表一起进 `onething.workbench`。`session:new` 那格（W5-b 的保留键）也能参与二合一。
- **不允许**：三格；`pair` 里再放 `pair`（拖一格两格标签到另一个标签正中 = 拒绝，理由「两格的标签不能再并」）。

## 7. 键盘与无障碍

每一个拖拽能到的落点都有一条不用鼠标的路，动作单产地是标签的右键菜单（本仓判例）：

| 鼠标 | 键盘 / 菜单 |
| --- | --- |
| 换序 | 菜单「左移 / 右移」（W3-b 已有）；标签条内 ←/→ 只移焦点不换序（APG 手动激活档） |
| 二合一 | 菜单「与右边的标签二合一」「与左边的标签二合一」 |
| 拆开 | 菜单「拆开」；格头上的按钮 |
| 撕成浮窗 / 钉到架子 | 菜单「撕成浮窗」「移到架子 ▸」（W3 已有） |
| 打开文件为新标签 | 文件树里 ↵ |

播报（`announce()`）：换序「已移到第 n 位，共 m 位」；二合一「已与 X 并排」；拆开「已拆开」；拒绝「这里不能放」。

## 8. 默认摆法

真机复现出来的「拖不到聊天区」不是拖拽判据的错，是文件面板出厂摆法是一扇浮窗，正好停在聊天区中间，往那一放落进的是浮窗自己。改成：

- 目录面板出厂摆法 = 左架子；会话总览出厂摆法 = 左架子。
- 浮窗仍然是合法落点，但不再是任何面板的出厂档。
- 从浮窗里拖东西出去时，浮窗自身矩形不再是落点（拖的东西来自它，它不该接住自己），指针在窗内时按窗底下的那片叶判。

## 9. 与今天代码的落差

## 11. 验收标准（代理可自证）

1. 三种来源（会话行、文件行、标签）拖到标签条上的每一个位置，屏幕上都有空位或描圈，浮影下都有一行字；这一条在 `gate:drag` 里对每种来源各断言一次。
2. 按下标签立刻切换内容，松手不动不再发生任何事；按下后横向移动 6px 才浮起；竖向 24px 才撕下。
3. 换序：拖到最左、最右、中间三处松手，顺序与活动位正确；宽标签能拖到窄邻居之后，且刚抬起那一帧邻居一个都不动；往右拖时右邻居在被拖标签右边缘越过它中心那一刻让位（不是中心对中心）；松手后有 150ms 的位移过渡（读到 `transition` 与非零起始位移）；中途 Esc 顺序不变、无残留 transform、无残留浮影；换序全程标签条与其它标签的底色逐字不变。
4. 往下压 6–24px 放到标签上 = 二合一：目标描圈、提示出现；回到条内回到换序；换序途中停住 1s 不发生任何事。
5. 文件单击三次 = 三个标签；第四次单击已开的 = 切过去。
6. 从架子里拖文件到聊天内容区中间 = 新标签，右带 = 与聊天并排；从浮窗里拖出去时浮窗不接住自己。
7. 目录面板：打开两个目录，架子标签条上两个目录名；同名目录带父目录后缀。
8. 一格都不重挂：换序、二合一、拆开、换比例四步内容根节点同一 DOM。
