## 0. 一句话

**待办在后端做成一种资源 `todo:`,壳里的每一次勾选、改字、加项都走 `resources.do`;一块「待办文档视图」组件同时给输入框顶部的计划抽屉和 Dock 的清单面板用。** 输入框不认识「待办」:它只提供一个「顶条」注册口,计划条是登记进去的第一位真住户。

## 1. 今天有什么、缺什么

**已经有的(全部照用):**

- 文件就是数据。`<todo 目录>/user-notes/*.md` 是用户的清单,`<todo 目录>/sessions/<会话 id>/ai-todo.md` 是 AI 给那个会话写的计划。todo 目录缺省是 `~/.onething/todo-plan`,可在设置里改。
- `OnethingTodoPlanStore`(`packages/onething-runtime/src/todo-plan/store.ts`)负责读快照、建 / 改 / 重命名 / 删清单,以及路径安全校验(`assertPathSegment`)。
- `OnethingTodoPlanWatcher` 监听整个 todo 目录。它会跳过应用自己刚写过的文件,只把「别人改的」报出来(AI 用写文件工具改、用户在自己的编辑器里改)。
- 系统提示词里的 `todo` 段(`prompts/content/todo-rules.md`)教 AI 用 `write` / `edit` 维护计划,并且这两个目录的写操作不弹权限框(`wiring/permission/capabilities.ts`)。
- 删会话时会一并删掉那个会话的 `ai-todo.md`(`session-provider.ts` 调 `deleteSessionAiTodo`)。
- 本机实测:7 份用户清单、27 个会话有计划。

**缺的:**

1. **React 壳里没有任何地方显示待办。** 旧界面是 Vue 时代的独立小窗,09-04 随 Vue 宿主一起删了。
2. **监听器在正常启动后根本没开。** 全仓唯一调用 `startTodoPlanWatcher()` 的地方是 `rpc/domains/settings.ts` 的保存设置之后。所以从启动到用户第一次保存设置之间,AI 改了计划,界面收不到任何通知。这是一个存量 bug,不是这次新引入的。
3. **现有写接口是「整份覆盖」。** `todo-plan.update` 收的是整份 `content`。AI 和用户会同时改同一个文件(AI 在推进计划、用户在勾一项),整份写回会把对方刚写的那一行盖掉——就是壳 CLAUDE.md 病型 C「整份写回换行身份」在文件上的样子。
4. **现有 `todo-plan` RPC 域是 atom 之前的手写域**(授权手写在处理者里,推送走单独的 `/api/todo-plan/events` SSE 路由)。按 `docs/design/atom-2026-09.md` §4,新界面不再往手写域上接。

## 3. 后端:`todo:` 资源

### 3.1 地址

| 地址 | 指的是 | 说明 |
| --- | --- | --- |
| `todo:notes` | 用户清单这一整组 | 单例。「列出清单」「新建清单」作用在它上面 |
| `todo:note/<id>` | 一份用户清单 | `<id>` = 文件名去掉 `.md`,沿用 store 的 `assertPathSegment` |
| `todo:session/<sessionId>` | 一个会话的 AI 计划 | 文件不存在也是合法地址,读出来是「不存在」 |

### 3.2 读法

> **已被改写(09-17)**:用户选定编辑方式 A 之后,本节由 `todo-editor-2026-09.md` §4.1 取代——后端不再解析 markdown、不返回 `blocks`,`document` 返回原文 `content` + `revision`。


| 读法 | 地址 | 返回 |
| --- | --- | --- |
| `list` | `todo:notes` | `[{ ref, title, updatedAt, total, done }]`,按文件名排序(与 store 今天的顺序一致) |
| `document` | `todo:note/*` / `todo:session/*` | `{ exists, title, filePath, revision, updatedAt, blocks, total, done }`;不存在时 `exists: false`,其余字段为空 |

`blocks` 是**后端解析好的**结构,壳不自己解析 markdown(一份解析器,不是两份):

```ts
type TodoBlock =
  | { kind: 'section'; line: number; level: 2 | 3; text: string }
  | { kind: 'task'; line: number; indent: number; done: boolean; text: string }
  | { kind: 'bullet'; line: number; indent: number; text: string }
  | { kind: 'paragraph'; line: number; text: string }
  | { kind: 'code'; line: number; lang: string; text: string }   // 整个代码围栏一块
```

- 第一行 `# 标题` 不进 `blocks`,它是 `title`。
- `line` 是它在文件里的行号(从 0 起),是做法定位用的。
- `revision` = 文件内容的短哈希。只用来判「我手上这份是不是最新的」,不存储。
- 解析器是纯函数,放在 `packages/onething-runtime/src/todo-plan/document.ts`,同一个文件里还有下面「按行改」的那几个函数。今天 store 里的 `countTasks` 改成调它,同一条正则不写两遍。

### 3.3 做法

> **已被改写(09-17)**:用户选定编辑方式 A 之后,本节由 `todo-editor-2026-09.md` §4.2 取代——四条按项的做法合并成一条 `edit { edits: LineEdit[], baseRevision }`,对账规则推广到多行并整批写入。


所有针对一项的做法都**按行改,不整份覆盖**。每条都带 `expect`(调用方以为那一行现在是什么原文),用来和 AI 的并发修改对账:

| 做法 | 地址 | 参数 | 做什么 |
| --- | --- | --- | --- |
| `setItem` | 文档 | `{ line, expect, done?, text? }` | 改一项的勾选状态或文字,只动这一行 |
| `insertItem` | 文档 | `{ after: number \| null, text, indent? }` | 在某一行后插入 `- [ ] text`;`after: null` 插到最后一个任务后面(没有任务就插到文末) |
| `removeItem` | 文档 | `{ line, expect }` | 删一行 |
| `moveItem` | 文档 | `{ line, expect, to }` | 挪一项(右键菜单「上移 / 下移」用) |
| `create` | `todo:notes` | `{ title }` | 新建清单,沿用 `createUserNote` 的起名去重 |
| `rename` | `todo:note/*` | `{ title }` | 沿用 `renameUserNote` |
| `delete` | `todo:note/*` | `{}` | 沿用 `deleteUserNote` |
| `createPlan` | `todo:session/*` | `{ text }` | 会话还没有计划时,用户自己写第一项。沿用 store「没有实质内容不建文件」那条规则 |

**`expect` 对不上时怎么办**(这是整个方案里最要紧的一条):

1. 先看 `line` 那一行是不是 `expect`。是 → 照做。
2. 不是 → 在全文里找**原文恰好等于 `expect` 的行**。恰好一行 → 改那一行(说明 AI 在上面插了几行,行号挪了)。
3. 零行或多行 → 返回结构化的 `conflict` 结果,带上最新的 `document`。壳用它原地替换,不报错、不弹提示。

读、改、写这三步在 provider 里对**同一个文件串行**(一把按文件路径的异步锁),避免应用自己两次操作交错。和 AI 写文件之间没法加锁(AI 走的是普通写文件工具),靠的就是 `expect` 对账。

### 3.4 事件

| 事件 | 发在 | 载荷 | 来源 |
| --- | --- | --- | --- |
| `changed` | 文档地址 | `{ revision, origin: 'app' \| 'external' }` | 应用自己改完发 `app`;监听器报的发 `external` |
| `created` | 文档地址 | `{ title }` | 新建清单 / 第一次出现 `ai-todo.md` |
| `deleted` | 文档地址 | `{}` | 删清单 / 删会话 / 文件被外部删掉 |

监听器今天通过 `broadcastChanged` 往外报,而 React 壳的宿主端口里 `todoPlan` 是 `null`。改法:provider 在 `attach(hub)` 时直接订阅 `TodoPlanRuntime` 的变更(给 `TodoPlanRuntime` 加一个 `onChanged(listener) → 退订`),把 `TodoPlanChangedPayload` 翻译成上面三条事件。**不经过宿主端口**,所以桌面、server、CLI 三个宿主行为一致。事件经既有的 `resource:event` 全局事件走 SSE 出去,不新开通道。

### 3.5 效果与授权

- **效果按主体分档**(atom §4.1 口径):用户主体的 `setItem` / `insertItem` / `removeItem` / `moveItem` / `create` / `rename` / `createPlan` 是 `[]`;其他主体是 `file_edit`;`delete` 对其他主体是 `file_destructive_edit`。
- **会话计划的读写要过会话归属判断**,判据与今天 `todo-plan` 域的 `sessionAccess.resolve(context, sessionId, 'read' | 'write')` 相同:读法走 `ReadGuard`,做法在 `plan` 里判。
- **`exposure.aiTool: false`。** AI 今天用 `write` / `edit` 维护计划,提示词、免审批和行为都已经调好。这一批不给 AI 生成 `todo` 工具,AI 的行为一个字不变。要不要换成结构化工具,放到 §9 留账。

### 5.2 输入框顶条:注册口,不写死

今天 Composer 顶部有一格 `StatusBar` + `DrawerStatus`,但**生产代码里没有任何地方调用 `beginStatus`**(它的文件头写着「这一批没有引擎」)。这一格正是计划条要住的位置。做法是把这一格从「写死的 status」改成**注册表**:

```ts
// src/composer/strips.ts
export interface ComposerStrip {
  id: string
  order: number
  /** 这一条此刻在这个会话里要不要出现、条上画什么。返回 null = 不出现。 */
  useBar(sessionId: string): StripBarModel | null
  /** 抽屉内容。只在这一条被展开时挂载。 */
  Drawer: ComponentType<{ sessionId: string }>
}
export interface StripBarModel {
  icon: ReactNode            // 进度环 / 转圈 / 完成点
  text: ReactNode            // 条上那句话,超出截断
  tone?: 'normal' | 'accent' | 'muted'
  label: string              // aria-label
}
```

- `DrawerKind` 增加 `{ strip: string }` 这一支(与 `PickDrawerKind` 同样是对象形),抽屉仍是**一个槽**,后来者顶替先来者。
- `StatusBar` 改名为通用的 `StripBar`(外观不变),Composer 按 `order` 依次渲染所有 `useBar` 非空的条,抽屉里渲染被展开那一条的 `Drawer`。
- 现有的执行状态原样登记成第一条(`status`),行为逐字不变。计划条登记成第二条(`plan`,放在 `content/todo/plan-strip.tsx`)。登记表是 `composer/strips/index.ts` 里的一个数组,**`Composer.tsx` 里不出现「todo」或「plan」**。
- 两条同时出现的情况今天不会发生(status 没有生产者),规则先定下:按 `order` 上下排,每条一行。

### 5.3 计划条(`plan` 这一条)

| 情况 | 条上画什么 |

## 7. 陌生能力演练

- **「AI 计划里的一项可以点一下跳到做这一步的那条消息」**:要改的是 `todo-provider` 的 `document` 读法多带一格锚点(能力自己的模块)+ `TodoDocView` 行上多一个动作(壳渲染模块)。Composer、注册表、Dock 零改动。
- **「给输入框顶上再加一条:后台任务进度」**:新写一个 `ComposerStrip`(能力自己的模块 + 它的 `Drawer`)+ 登记表一行。`Composer.tsx` 零改动。
- **「插件也想读写用户清单」**:插件 `api.resources` 已经能 `do(todo:note/…, 'insertItem')`,主体是 `system:plugin:<id>`,效果自动是 `file_edit`。零改动。

三个答案都是「能力自己的模块 + 它的壳渲染模块 + 各一行登记」,骨架到位。

## 9. 留账(本批不做)

1. **要不要给 AI 一个结构化的 `todo` 工具**(`exposure.aiTool` 打开)。好处是 AI 勾一项不用先 `read` 再 `edit`,也不会写坏格式;代价是换掉已经调好的提示词和行为。这是用户能感知的行为变化,单独拿给用户定。
2. `browser-port` / `git-port` 并入 `resource-port`。
3. 设置里 `general.todoPlan` 的 `cardHeight` / `pinned` / `docked` / `autonomy` 是 Vue 小窗留下的字段,React 壳不读。随 T5 一起清理,或另开一单。
4. 清单之间拖拽挪项、清单内拖拽排序。本批只有右键「上移 / 下移」。
5. 在命令面板里搜索待办项。
