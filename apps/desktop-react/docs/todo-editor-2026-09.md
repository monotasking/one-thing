## 0. 一句话

**不在编辑的时候,用消息那一套解析器和块组件原样画;按下鼠标那一刻,把那一小段原文换成一块可编辑的同样式文字——粗体仍是粗体、行内码仍是等宽小底,只多出淡灰的 markdown 记号;改完变成一条「从第几行起、原来是哪几行、换成哪几行」的行编辑发给后端。** 不引入任何编辑器库。

### 1.1 为什么不用 CodeMirror 6 / ProseMirror / Lexical

- **用户要的第一条是「和消息一样」。** CodeMirror 与 ProseMirror 都自己管 DOM,不能把消息的 React 块组件放进去当渲染层,只能照着消息的样式再写一套装饰。两套样式迟早走样——这正是壳里「两个产地必漂」那条判例。
- **ProseMirror / Lexical 是所见即所得,那是被否掉的 B。** 它们存的是自己的文档树,写回时要重新生成 markdown,原文写法会被统一掉。
- **待办的编辑粒度很小。** 一次改的是一项或一块,跨行选中、多光标、大段粘贴不是这块面的需求。CodeMirror 的强项(整篇一个编辑器、跨行选区、完整撤销栈)在这里用不上,代价却是约 150KB 依赖和一套要自己维护的 live-preview 装饰。
- **退路留好了。** 「正在编辑的那一段」在代码里是一个接口 `ActiveEditor`(§3.4)。哪天真要跨行选中,把 `SourceEditable` 换成 CodeMirror 实例,只动这一格。
- **为什么不是第一版的「镜像 + 透明 textarea」**:textarea 只能是一种字体,编辑时粗体变细、行内码变成比例字,进编辑那一下字会跳——用户试样例时第一条就挑的这个。`contenteditable` 里每一段可以有自己的样式,于是进编辑时唯一的变化是记号出现。

### 1.2 这条路要自己扛的四件事(都有对策)

| 风险 | 对策 |
| --- | --- |
| 中文输入法:组字时按回车 / 退格会被误当成「新起一项 / 删项」;组字中重画会打断输入法 | 所有结构键先过 `isComposingKey`(从 `ComposerInput.tsx` 抽进 `ui/`,两处共用);`compositionstart` 到 `compositionend` 之间**不重画**,`compositionend` 后补画一次 |

| 重画会清掉浏览器自带的撤销栈 | 撤销整个交给文档级的 `DocHistory`(§6.4),`historyUndo` / `historyRedo` 与 `⌘Z` / `⇧⌘Z` 都走它 |

## 2. 要改消息的地方(两边一起受益)

今天消息的列表模型是 `{ kind: 'list'; ordered; items: BlockModel[][] }`:勾选状态丢了,嵌套列表拍平后也不知道原来在第几层,列表项也没有自己在原文里的位置。待办三样都要,消息也该有。

```ts
// content/model/blocks.ts
| { kind: 'list'; ordered: boolean; start: number | null; items: ListItemModel[] }

interface ListItemModel {
  blocks: BlockModel[]
  checked: boolean | null   // null = 不是任务项
  depth: number              // 拍平前的嵌套层级,0 起
  offset: number             // 源偏移,与 ParsedBlock 同口径
  end: number
}
```

- **拍平的裁定不翻**:屏幕上仍然没有 `<ul>` 套 `<ul>`,只是每项按 `depth × --indent-1` 缩进。
- `List.tsx`:`checked !== null` 的项不画圆点,在圆点位置画勾选框。消息里是**只读**的(`aria-disabled`,不响应点击);待办里由 `BlockCtx.edit` 提供点击(§3.3)。完成项文字降一档颜色并加删除线。
- 流式增量解析(`incremental.ts` / `block-stream.ts`)只认块级 `offset` / `end`,不读 `items` 的内部结构,所以不受影响;这一点由它们现有的测试兜底。
- `SearchPanel.dom-parity` 这类 DOM 快照若因列表改结构而变,按快照文件头的规矩 `-u` 一次并逐格说明。
- 这是用户能看见的消息变化(AI 回复里的任务清单开始显示勾选框和缩进),本批一起交。

### 3.1 `LineEdit`(纯函数,后端与壳共用)

```ts
interface LineEdit {
  start: number            // 从第几行起(0 起)
  expect: string[]         // 调用方以为这几行现在是什么
  lines: string[]          // 换成什么;空数组 = 删除
  anchor?: string          // expect 为空(纯插入)时,插入点上一行的原文
}
type Located = { ok: true; start: number } | { ok: false; reason: 'conflict' }

function locate(doc: readonly string[], edit: LineEdit): Located
function apply(doc: readonly string[], edit: LineEdit, at: number): string[]
function invert(before: readonly string[], edit: LineEdit, at: number): LineEdit
```

`locate` 的规则(与 `todo-2026-09.md` §3.3 同一条,只是从「一行」推广到「几行」):

1. `start` 处的几行恰好等于 `expect` → 就在这里。
2. 否则在全文里找**连续几行恰好等于 `expect`** 的位置;恰好一处 → 在那里(AI 在上面插删了几行)。
3. 纯插入:按 `anchor` 找上一行,规则同 2。
4. 零处或多处 → `conflict`。

壳做乐观补丁用它,后端真写文件也用它——同一份代码,两边判断永远一致。

### 3.2 `ItemPrefix`(值对象)

把 `  - [x] `、`* `、`12. ` 这类行首拆成 `{ indent, marker: '-' | '*' | '+' | { ordered: number, delim: '.' | ')' }, task: boolean | null }`,方法:

- `format()`:原样拼回,**保留用户原来的记号**(`*` 仍是 `*`)。
- `continued()`:回车新起一项用的前缀。任务 → 未勾选任务;有序 → 序号 +1;记号和缩进不变。
- `indented(±1)`:缩进一层 = 两个空格(读原文推断:原文用四个空格或 tab 就沿用)。
- `toggled()`:只翻 `[ ]` / `[x]`。

### 3.3 `RegionIndex`:哪些东西能点进去改

从解析结果算出**可编辑单元**,一个单元对应原文里连续的几行:

| 单元 | 对应 | 编辑框里放什么 |
| --- | --- | --- |
| 列表项 | 一个 `ListItemModel`(不含它的子项) | 前缀**之后**的文字;前缀留在外面照常画成勾选框 / 圆点 / 序号 |
| 标题 | 一个 heading | 整行,含 `## ` |
| 段落 | 一个 paragraph | 整段原文 |
| 引用 | 一个 blockquote | 整段原文,含 `> ` |
| 代码块 | 一个 code | 围栏**里面**的内容;围栏行留在外面;编辑框换等宽 |
| 表格 / 图 / 其他物件 | 整块 | 整块原文,等宽 |

`BlockCtx` 加一格可选的 `edit?: EditableSurface`:

```ts
interface EditableSurface {
  isActive(offset: number): boolean
  renderActive(offset: number): ReactNode            // 这一格正在编辑时,画 ActiveEditor
  onActivate(offset: number, caret: CaretHint): void // 点了这一格
  onToggleTask(itemOffset: number): void
}
```

- 消息不传它,块组件行为一个字不变。
- 顶层块由 `EditableDoc` 包一层「点了就激活」;列表项在 `List.tsx` 里按项询问 `ctx.edit`。**块注册表和各 kind 里不出现「待办」**:它们只知道「这块面可以编辑」。
- 查看器里打开的 `.md` 文件将来想就地改,传同一个 `edit` 就行。

### 3.4 `EditSession`:结构编辑

不碰 DOM 的类,单测直接测。它拿着「当前文档行 + 当前 Caret」,每条命令返回 `{ edits: LineEdit[], caret: Caret }` —— **每条命令都交回一个光标**,这是 §6.0 规则 5「键盘动作不让光标消失」在类型上的样子(只有 `close()` 交回 `null`)。

| 命令 | 触发 | 做什么 | 光标去哪 |
| --- | --- | --- | --- |
| `enter()` | `↵` | 列表项:光标处拆成两项(新项前缀用 `continued()`);空项:有缩进退一层,没有就删掉这项。标题:光标后的字带着新起一个待办项。段落 / 引用:换行 | 新项开头;空项删掉时去上一项末尾 |
| `backspaceAtStart()` | `⌫`,且光标左边在这一项里没有**看得见的**字 | 依次:空项删掉 → 标题 / 引用降成段落 → 缩进的项退一层 → 并到上一项(列表或段落)→ 列表项变段落 | 并项时落在接缝处;其余原地 |
| `deleteAtEnd()` | `⌦`,且光标右边在这一项里没有看得见的字 | 把下一项(列表或段落)的文字并进来 | 原地 |
| `indent(±1)` | `Tab` / `⇧Tab`(列表项) | 只动前缀 | 原地(同一个原文位置) |
| `toggleTask(line)` | 点勾选框 | 只翻 `[ ]` / `[x]` | 正在编辑就原地保留 |
| `toggleMark(kind)` | `⌘B` / `⌘I` / `⌘E` | 规则见 §6.5 | 见 §6.5 |
| `insertAfterLastTask()` | 「+ 添加一项」 | 插一行,记号照文档里已有任务项的写法 | 新项开头 |
| `close()` | `Esc`、`⌘↵`、按下在文档外 | 结束编辑 | `null` |

导航(←→↑↓ 等)**不在这里**,在 `CaretController`(§6.0):它只改光标、不改原文。

`ActiveEditor` 是 `CaretController` 与屏幕之间的接口(`value` / 选区投影 / `focus()` / 量尺),今天只有 `SourceEditable` 这一种实现。

### 3.5 `ui/SourceEditable`(新库件)

- 参数:`value`、`onChange`、`paint(value) → ReactNode`(把切分画成带样式的段)、`label`、`multiline`、键盘回调、`caretHint`(第几个字,或「屏幕上某个 x、贴上沿 / 贴下沿」)。
- 结构:一个 `contenteditable="plaintext-only"` 元素,`role="textbox"`、`aria-multiline` 按单元类型。它就是渲染态那个元素本身(同一个 class、同一个位置),只是多了可编辑,所以进编辑时版式不挪。
- 输入:`input` 时读 `textContent` → 算光标字数 → 按新值重画 → 放回光标;组字期间不重画。
- **不自带撤销、不处理导航键**:撤销归 `DocHistory`(§6.4),←→↑↓ 等归 `CaretController`(§6.0)。第二版里它自带一个会话级撤销栈,第三版删掉 —— 那个栈离开这一项就没了,正是「⌘Z 有时有用有时没用」的来源。
- 输入:所有 `beforeinput` 一律 `preventDefault`,改原文模型后从模型重画;绕过 `beforeinput` 的改动(拼写纠正、脚本 `execCommand`)在 `input` 里被丢弃并从模型重画。屏幕永远是模型的投影。
- Esc:照 `ui/inline-edit.ts` 向焦点树登记瞬态 Esc 口,不在别处挂 keydown(I2);键盘处理走元素上的 `onKeyDown`。
- 焦点环:`data-focus-ring="none"`(光标就是指示)。
- 三类状态写进件的文件头:挂载即拿焦点并按 `caretHint` 放光标;交互态 rest / focus / 组字中;没有 disabled 档。

### 3.6 `source-marks.ts`:切分

用同一个解析器解析正在编辑的这一段(列表项的内容当一段 phrasing 解析),再按原文位置切分:

- 文字节点覆盖的字符 → `content`
- 行内码的值 → `code`(浅底,不换等宽)
- 链接文字 → `link`(强调色),链接地址 → `url`(淡灰)
- 其余字符(`**`、`` ` ``、`[`、`](`、`)`、`## `、`> `)→ `mark`(淡灰)

好处是规则永远与渲染一致:渲染认成粗体的,高亮就把两边的 `**` 标成记号;渲染不认的(比如写错的 `**半截`),高亮也不会假装它是记号。

## 4. 后端改写(替换 `todo-2026-09.md` §3.2 / §3.3)

**后端不再解析 markdown,也不再返回 `blocks`。** 解析只在壳里做一次,用的是消息那一份;后端只管字节和行。

### 4.1 读法

| 读法 | 地址 | 返回 |
| --- | --- | --- |
| `list` | `todo:notes` | 不变:`[{ ref, title, updatedAt, total, done }]` |
| `document` | 文档地址 | `{ exists, title, filePath, content, revision, updatedAt, total, done }` |

`total` / `done` / `title` 用一个极小的行扫描函数算(`- [ ]` / `- [x]` / 第一行 `# `),只给列表和计划条的读数用,不参与渲染。

### 4.2 做法

| 做法 | 地址 | 参数 |
| --- | --- | --- |
| `edit` | 文档 | `{ edits: LineEdit[], baseRevision }` —— 一次提交里的几条行编辑,按顺序对账、一次写盘 |
| `create` / `rename` / `delete` | 清单 | 不变 |
| `createPlan` | `todo:session/*` | 不变 |

`setItem` / `insertItem` / `removeItem` / `moveItem` 四条合并成一条 `edit`:勾选、改字、加项、删项、挪项在壳里都已经是 `LineEdit`,后端没必要知道是哪一种。

`edit` 的执行:拿文件锁 → 读当前内容 → `baseRevision` 相同就直接按 `start` 应用;不同就逐条 `locate` → 全部定位成功才写盘,任何一条 `conflict` 整批不写,返回 `{ conflict: true, document }`。整批要么全成要么全不成,不会写出半截。

效果分档、会话归属、`exposure.aiTool: false`、事件、装配,全部照 `todo-2026-09.md` §3.4–§3.6。

## 5. 数据层(补充 `todo-2026-09.md` §4)

- 查询格存 `content` + `revision`;**解析结果按 `revision` 缓存**(同一个 revision 只解析一次)。
- 提交:`EditSession` 交出 `LineEdit[]` → 本地先用 `locate` + `apply` 改 `content`(乐观补丁)→ 发 `edit`。回 `conflict` → 用回来的 `document` 覆盖;回 `denied` / `failed` → 回滚。同一个文档的提交**排队串行发**,前一条回来之前后一条的 `baseRevision` 用本地乐观后的值。
- 外部改动(`origin: 'external'`)重读回来:
  - 不在编辑:直接换内容;按行原文比对旧新两份,新出现或勾选状态变了的列表项进「刚被改过」,闪一下。
  - 正在编辑:草稿不动。`EditSession` 用 `locate` 重新找自己那几行的新位置;找不到(那几行被 AI 改了或删了)→ 草稿保留在编辑框里,框上方一行小字「这一项刚被改过,提交会以你的为准」,提交时把 `expect` 换成新内容,即用户这次的草稿覆盖那一项。

## 6. 交互细节

### 6.0 光标模型(第三版,§6 其余各节都服从这一节)

**总则:同一个画面 + 同一个动作 = 同一个结果。** 光标落在哪,只取决于此刻屏幕上是什么、光标在哪,不取决于之前按过什么。唯一有意保留的历史是「目标列」,它的寿命写死在规则 3 里。

**为什么要立这一节。** 第二版的光标由三套机制拼成:同一项里靠浏览器原生移动,项的边界处靠补丁,原生移动之后再由异步的 `selectionchange` 按「上一次光标在哪」去猜原文位置。用户报的四个问题全部长在接缝上:到了项开头 ←↑↓ 没人接;单行项 ↑↓ 走的是浏览器「跳行头行尾」;同一位置 ↓ 用了过期的目标列;以及复查时新发现的——同一项折行里走浏览器的目标列、跨项走我们的,一串 ↑↓ 会漂。

**结构:光标只有一个产地。**

- 光标是文档级的值对象 `Caret { unit, anchor, focus, goalX, goalFor }`(位置是原文字数)。屏幕上的选区只是它的投影,每次改完都由模型重新设一遍。
- `CaretController` 是唯一能产出新 `Caret` 的对象,输入只有三种:键盘导航、鼠标、输入 / 结构编辑的结果。
- **所有导航键都在 `keydown` 里由它算完、画完,一律 `preventDefault`**,不交给浏览器。浏览器自带的 `selection.modify` 只当**量尺**,在同一个事件里同步调用一次(它最懂字形簇、单词边界、行尾)。量完、换算、重画都在同一个事件里完成,浏览器没有机会画出中间态。
- 不再用 `selectionchange` 推导光标(第二版的「按上一次在哪猜」删除)。

**七条规则:**

1. **整篇是一个文档。** 所有导航都不在项与项之间断开(下表)。已经是全文第一项再按 ↑、最后一项再按 ↓:光标不动。
2. **一步 = 一个看得见的字。** 字形簇为单位(emoji、带肤色的 emoji 算一个),`Intl.Segmenter` 切。退格 / Delete 删的也是光标旁边那一个**看得见的**字形簇。
3. **目标列。** 第一次按 ↑↓ 时记下横坐标,并记下「记下它时光标在哪」(`goalFor`)。之后**只要光标还在 `goalFor`** 就沿用;鼠标按下、←→、Home / End、打字、任何结构编辑都会清掉它。同一项里的折行和跨项用同一个目标列、同一种量法。
4. **一把尺子:在「静止画面」上量。** 所有横坐标都在「记号全部收起」的画面上量:没打开的项本来就是这样;打开着的项临时叠一个不可见的同位置副本来量。否则经过一个展开了记号的项再回来,会差出记号那几个字的宽度(样例实测:`` `ma‸ke` `` ↓↓↑↑ 回来落在 `` `mak‸e` ``)。
5. **键盘动作永远不让光标消失。** 只有 `Esc`、`⌘↵` 和按下在文档外会结束编辑。每条结构编辑都交回一个光标(§3.4 表的最后一列)。
6. **两个看得见的字之间藏着记号时取哪个原文位置:** 往右走停在记号左侧、往左走停在记号右侧(从哪边来停哪边,然后那个元素因被光标贴着而展开);鼠标按下一律取靠左;不显示记号档只有一个规范位置——跟左边那个字走(§6.5)。
7. **量之前先滚进窗口。** 浏览器只肯回答「窗口里」某个点下面是哪个字;目标行在列表或整页之外时,先把它滚进来(列表和整页都滚),再量。样例里漏了这一条时,窄窗口下 ↓ 会退回行首。

**键位表(编辑中):**

| 键 | 不带 ⇧ | 带 ⇧(扩选区) |
| --- | --- | --- |
| `←` / `→` | 移一个看得见的字;在项头 / 项尾进上一项末尾 / 下一项开头 | 在这一项里扩,到头停 |
| `⌥←` / `⌥→` | 按词移;在项头 / 项尾同上跨项 | 在这一项里按词扩 |
| `⌘←` / `⌘→`、`Home` / `End` | 这一视觉行的行首 / 行尾(行首落在 `## ` / `> ` 之后) | 扩到行首 / 行尾 |
| `↑` / `↓` | 按目标列到上 / 下一视觉行;在项的首 / 末行进上 / 下一项;全文首 / 末项不动 | 扩到这一项的头 / 尾 |
| `⌘↑` / `⌘↓` | 全文第一项开头 / 最后一项末尾 | 扩到这一项的头 / 尾 |
| `⌘A` | 选中这一项全部(跨项选区不做) | — |
| `↵` / `⌫` 在项头 / `⌦` 在项尾 / `Tab` | 见 §3.4 | — |
| `⌘Z` / `⇧⌘Z` | 文档级撤销 / 重做(§6.4) | — |

输入法组字期间,以上所有键交给输入法,光标模型不动;`compositionend` 时把组好的字一次写进原文。

### 6.1 鼠标

**一切在按下鼠标(`pointerdown`)那一刻完成,不等 `click`。** 第一版样例实测:正在编辑一项时点另一项,按下那一刻旧编辑框失焦、列表重画,松开时按下的那个元素已经不在了,浏览器不发 `click`,于是要点第二次。现在同一个处理里先提交上一项、再打开这一项,只重画一次,也不依赖失焦事件。

**命中范围是整行。** 第一版里行与行之间 4px 的缝、勾选框左边、行尾空白都点不中。现在按下时如果没落在任何单元上,就找垂直方向最近的单元(24px 以内),再把点击坐标夹进它的范围里取最近的字——点在行尾空白就是行尾,点在勾选框左边就是行首。

| 按下在 | 结果 |
| --- | --- |
| 勾选框 | 翻勾选,不进编辑;正在编辑时先提交草稿再翻,编辑状态与光标保留 |
| 列表项 / 段落 / 标题 / 引用的字 | 打开这个单元,光标落在点的位置 |
| 行间缝隙、勾选框左边、行尾空白 | 同上,落到最近的那个单元 |
| 正在编辑的那一段里 | 按**它此刻展开后的画面**量,取靠左;按住拖动在这一项里扩选区(跨项不做);清掉目标列 |
| 链接 | 进编辑;`⌘` + 按下 = 打开链接 |
| 代码卡的檐 | 檐上动作照常,不进编辑 |
| 文档外面 | 提交并退出编辑(不拦截,外面的按钮照常响应) |
| 右键 | 右键菜单:删除 / 上移 / 下移 / 复制文字 |

见 §6.0 键位表。第二版这里的那一段描述已被取代。

### 6.3 键盘(不在编辑)

文档是一个 `ui/a11y/list-selection` 列表,当前项跟随键盘:`↑↓` 移动、`Space` 翻勾选、`↵` 进编辑(光标在末尾)、`⌫` 删当前项(`⌘Z` 可撤回)。焦点作用域:抽屉里属于 composer 那一格,面板里是 `todo`。

### 6.4 撤销:一条文档级历史 `DocHistory`

- **一条**历史,不再分「编辑框里原生撤销 / 提交之后另一个栈」两层(第二版的两层导致离开一项之后 ⌘Z 失效、拆项并项不能撤)。
- 记什么:打字在同一项里 600ms 内合并成一步;结构编辑(拆项 / 并项 / 降级 / 缩进 / 勾选 / 加格式 / 粘贴 / 输入法上屏)每次单独一步。每一步存「改之前的原文快照 + 改之前的 Caret」(真实现存反向 `LineEdit`,`invert` 算,与第一版方案同)。
- 撤销:恢复原文,并把光标放回**那次改动之前的位置** —— 不管你之后去了哪一项;那一项会被打开。重做把光标放回改动之后的位置。
- 撤销也是一次普通提交,走 `LineEdit` 对账,文件被 AI 改过也不会撤坏。
- 原文随改随写回本地文档模型(不等「离开这一项」),所以撤销、原文读数、跨项操作看到的永远是同一份;发往后端的提交按「离开这一项或停手 400ms」合批。
- 按键:`⌘Z` / `⇧⌘Z` 在编辑中与不在编辑(焦点在文档列表上)时是同一条历史。**开工第一步先实测**应用菜单 Edit 的 `undo` 角色会不会先把 `⌘Z` 吃掉;会的话待办作用域在命令表里答 `edit.undo`,不许为此另挂 keydown。
- 历史跟着文档实例走(换会话、关面板即清空),不落盘。

### 6.5 显示档位:元素 / 整块 / 不显示记号

三档是 `RevealPolicy` 的三个实现,**唯一的区别是「此刻哪些记号画出来」**;§6.0 的光标规则三档逐字相同。设置里一个三选一,缺省「元素」(与 Typora 缺省一致);切换档位时光标停在同一个原文位置。

| 档 | 画出来的记号 | 光标旁的字 |
| --- | --- | --- |
| 元素(缺省) | 光标所在或贴着光标的那个行内元素(粗体 / 斜体 / 行内码 / 链接 / 行首 `## `);有选区时选区碰到的元素都展开 | 光标两边的原文字符永远都画在屏幕上(否则光标会停进看不见的字里) |
| 整块 | 这一项的全部记号(Typora「聚焦时显示简单块的源码」) | 同上 |
| 不显示记号 | 永远不画(像 Notion) | 屏幕位置与原文位置一一对应:两字之间藏着记号时只有一个规范位置——**跟左边那个字走**(粗体末字后面打字仍是粗体,首字前面打字是普通字);行首永远落在 `## ` / `> ` 之后 |

不显示记号档的三条补充(看不见记号,就要给别的办法):

- **光标所在的元素铺一层淡底**,告诉你接着打字会是什么格式。
- **格式靠 `⌘B` / `⌘I` / `⌘E`(规则照 Word):** 有选区 → 先把只盖住半个元素的选区扩到整个元素、去掉两头空白,已是这种格式就拆掉,否则包上;没选区、光标在元素内侧边缘 → 跳到元素外(接着打普通字);在外侧边缘 → 跳进去;在元素中间 → 拆掉整个元素;其余 → 插一对空记号,光标放中间。跳过去的位置记一个 sticky,光标没动之前保留。
- **内容被删空的元素连记号一起删掉**(刚用 `⌘B` 插进来、光标还夹在中间的那一对除外),否则会留下看不见也删不掉的空记号。
