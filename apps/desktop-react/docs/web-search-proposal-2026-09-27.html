Electron 41 里后台的 WebContentsView 标签怎么省内存?有没有官方推荐做法

我先查一下官方文档和相关 issue。

结论:官方没有「冻结一个 view」的开关,推荐的做法是让不可见的 view 把渲染进程交出去,回来时重新加载。具体有三档:

1. 对隐藏的 view 调 webContents.setBackgroundThrottling(true)(默认已开),只省 CPU,不省内存。
2. 长时间不可见的标签直接 view.webContents.close(),留下 URL 与标题,再显示时重建 —— Chrome 的 Tab Discarding 就是这么做的。
3. 用 app.getAppMetrics() 按进程看占用,只挑超过阈值的去丢。

issue #41802 里有人实测第 2 档每个标签回收 80–140MB。

每种状态

改了什么

  1. 流中态从一行字变成一张步骤单。每次搜索、每次打开各占一行:左边是动词(搜索 / 阅读),中间是查询词或页面标题,右边是结果(「6 条」「已读」「未读到正文」)。正在进行的那一行右边是跳动的省略号,不转圈。最多显示最近 4 行,更早的收成一句「前面还有 N 步」。顶上一行报「已找到 N 个来源」和已经找到的站点脸,人能看出这次检索有多大。
  2. 收起行多说一件事:细读了几篇。「检索 · 9 个来源 · 细读 4 篇」。9 个里只有 4 个是模型真打开读过的,其余只是在搜索结果里出现过;这个差别对「这段话靠不靠得住」很关键,原来要展开、而且只有失败时才看得出来。
  3. 来源行变成两行:标题 + 域名和摘要。摘要模型里早就有(source.excerpt),只是从没画出来。读过的来源标题用正文色并带一枚「已读」小签,只在搜索结果里出现过的标题退一档灰。清单顶上加一个「全部 / 只看已读」切换。
  4. 点开一条来源,看到的是摘录,不是工具输出。原来点开是 ToolDrawer,里面是工具拼好的整块纯文本当代码块显示。现在先给这一页的摘录(命中词加粗)、完整地址,和三个动作:在内置浏览器打开、复制链接、看原始调用(原来那个抽屉降到这里,还在)。
  5. 悬停出两个快捷动作:在内置浏览器打开、复制链接,不用先展开。
  6. 消息尾来源丸不变,只是加了一圈细线,跟正文里的行内代码块分开。
