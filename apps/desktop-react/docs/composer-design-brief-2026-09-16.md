# Composer 现状说明(2026-09-16)

> 本文只描述今天代码里 composer 及其相关部件的结构与行为。
> 源码位置:`apps/desktop-react/src/composer/`(面板)、`src/references/`(引用种类)、`src/data/models-source.ts`(模型)、`src/data/composer-interactions.ts`(ask 的数据来源)。

---

## 1. 产品是什么

onething 是一个桌面 AI 聊天应用(Electron + React,同一套界面也能在浏览器里跑)。支持很多家模型提供方(Claude、Codex、DeepSeek、Gemini、Kimi、OpenAI 兼容等),AI 能调用工具(读写文件、跑 bash、上网、打开内置浏览器等)。中央区是一棵可以分屏、拖拽的「拼贴树」,每一格叫一片**叶**,叶里可以装会话、终端、浏览器、文件查看器、改动 diff、设置页。

Composer(输入面板)是会话底部那块写消息的面板。

## 2. 它在哪

- Composer 属于会话叶,不属于外壳。有几片会话叶就有几块 composer:分屏「会话 A | 会话 B」就是两块,各自有草稿、抽屉和附件;终端、浏览器、设置这些叶里没有 composer。会话叶可以被收进侧边的架子或撕成浮窗,composer 跟着叶一起去,宽度随叶变窄。
- 它浮在消息流的底部,消息流在底部给它留出等高的空间,面板长高时消息不会被盖住。
- 输入区随内容自动长高,到上限后在框内滚动,面板不再往上长。
- 每条会话一份草稿(含附件),切走再切回来草稿还在。

## 3. 结构:一块面板、三个部分

```
      ┌──────────────── 抽屉槽(只有一个) ────────────────┐   ← 贴在面板上沿之外,向上展开
      │ 住户四选一:@ 引用 / / 命令 / 模型 / 执行状态        │
      └──────────────────────────────────────────────────────┘
┌──────────────────────────── 面板 ────────────────────────────┐
│ [状态条:仅在有执行时出现]                                     │
│ ┌─ 本体行:write 形态 ⇄ ask 形态(交叉淡变)────────────────┐ │
│ │ 输入区(富文本,内嵌引用 chip)                              │ │
│ │ 📎  [模型名 · 思考档 ▾]                    ◔ 上下文圆环  (↑) │ │
│ └──────────────────────────────────────────────────────────────┘ │
└───────────────────────────────────────────────────────────────┘
  面板外还有两个不占布局的浮物:附件摞、读数明细卡
```

- 没有弹出菜单。所有「选东西」都发生在同一个抽屉槽里,新住户顶替旧住户,同一时刻只有一个抽屉。
- 附件摞、读数卡浮在面板外,不占布局,出现时面板尺寸不变。
- ask 不是抽屉,是本体行换成另一副样子:轮到用户回答 AI 的问题时,回答区占据输入框的位置。

## 4. 各个部件

### 4.1 输入区与引用 chip

- 占位文案:「说点什么…( @ 文件 · / 命令 )」。
- 引用插进输入框后是一个不可编辑的整体,退格一次整枚删除。
- 输入框里的 chip、按下回车后发送中的气泡、落进账本后的气泡、AI 回复里的行内引用,用的是同一个组件,样子一致,从按下回车起不再变化。
- chip 是「链接式」:没有盒子,读起来是正文里的一个词——图标 + 名字。文件 chip 显示文件名,悬停提示全路径,点击打开查看器。命令 chip 不可点,呈现与可点的引用不同。

### 4.2 `@` 与 `/` 抽屉(file pick / command picker)

触发:输入 `@`(任意位置)或 `/`(只认行首)时抽屉打开,继续打的字是搜索词。

抽屉里出现哪些组由「引用种类注册表」决定(`src/references/kinds/`),每种引用自己声明:在哪个字符下出现、怎么查、一行显示什么、组头叫什么。当前登记:

| 触发字符 | 组头 | 一行里有什么 |
| --- | --- | --- |
| `@` | 引用文件(这一组即使为空也显示) | 路径 |
| `/` | 命令 | 命令名 · 说明 · 用法 |
| `/` | 技能 | 同上 |
| `/` | 插件 | 同上 |

目录、网页、提示词这三种引用不从抽屉进入;网页从内置浏览器的 ⋯ 菜单插入。

行为:

- 一行的字段:主名(必有)、副说明(可选)、附加信息(可选)、键盘选中行尾的操作提示(「⏎ 引用」/「⏎ 选用」,只在选中行显示)。
- 抽屉高度固定,上限是所在叶高度的一半,打字过程中高度不跳。打开时抽屉与面板拼成一整块。
- 取数有四种状态:正在找(「正在找…」);新结果没到时旧候选留在屏上;这一次失败但旧候选还在(「这一发没找成,先看上一批」与列表并排显示);没有匹配(「无匹配」)。
- 分组只有一层,组头没有计数。

### 4.3 模型选择(model select)

- 入口是工具行左侧、附件按钮旁边的一颗药丸:写模型名;这型模型能思考时,再跟一格思考档(如「高」);末尾一个展开记号。名字太长时截断,药丸不折行。切换模型的请求进行中时药丸处于忙态。没选模型时写「选择模型」。
- 点药丸打开模型抽屉,两栏:
  - 左栏:顶上一行搜索框(「搜模型或 Provider…」),下面按 Provider 分组的模型表,每行是模型 id + 行尾的上下文窗口大小(如 `200k`,不知道就留空)。只有这一栏滚动。
  - 右栏:当前选中那一型的详情卡——名字、窗口、价格(「$x 进 / $y 出」,每百万 token)、思考阶梯(单选:关 / 最少 / 低 / 中 / 高 / 极高 / 最大,每档一句注释,如「不思考,最快」「日常」「想到底」;具体有哪几档由模型决定;不支持思考时写「这一型不思考」)。读数还没拉到时写「这一型的读数还没拉到」,不画骨架。
  - 宽度不够时两栏按容器宽度退化。
- 行为:
  - 点一行只是选中它,抽屉不关;右栏随之刷新。关抽屉靠点面板外或 Esc。
  - 改选时列表的滚动位置不变。
  - 模型目录在打开抽屉时才去拉;左栏立即完整显示(模型 id 已在手),窗口大小和右栏读数稍后到,左栏没有加载态。
- 模型的完整设置(自定义模型、覆盖上下文长度等)在设置页,不在这里。

### 4.4 上下文(context)

- 工具行右侧、发送键左边有一个上下文圆环,表示「上下文已用 / 窗口大小」。窗口未知时显示未知态(不画进度)。会话正在做上下文压缩时有单独的压缩态。
- 悬停或聚焦圆环时,面板上方浮出读数卡(不占布局),同时刷新一次数据。卡里是一列「键 值」:
  - 压缩(仅在压缩中):「正在压缩 · 2 / 5」
  - 上下文:「38k / 200k · 19%」,或「38k · 窗口未知」
  - Tokens:「↑12k ↓3k」
  - 花费:「$0.42」;厂商报价:「$0.40」
  - 缓存命中:「87%」
  - 没有任何读数时:「还没有读数」
- 「引用进上下文」就是 4.1 / 4.2 的 `@` 引用;没有单独管理「哪些文件在上下文里」的面板。

### 4.5 ask user(AI 向用户提问)

- 来源:AI 调用 `ask_user` 工具时,后端发出一个交互请求;该会话自己的 composer 收到后切成 ask 形态。答案回填给那次工具调用,不会变成一条新聊天消息。一次可以有多道题。
- 版式(自上而下):
  - 顶行:`‹  1/3  ›` 翻页 · 题目文字(多选题带「多选」标记)· 右端「拒绝回答」。
  - 选项列:每项一条横条,左侧选择记号(单选 / 多选两种)、标签、副说明。选项区的最小高度按所有题里最多的选项数计算,翻题时面板高度不变。
  - 最后一条是「其他」:点记号或行内文字即可在这一行里直接打字(占位「就在这行写,回车即答」),不另开输入框。题目可以配置为不带「其他」。
  - 底行:左边提示「‹ › 换题 · 再点取消 · esc 拒绝整单」(出错时换成错误文案);右边提交按钮「提交 2/3」,全部答完才可点,提交中显示「正在提交…」。
- 键盘:← → 换题;Esc 拒绝整单;焦点默认落在「其他」那一行。

### 4.6 状态条与执行状态抽屉

面板顶部一条细栏,执行中显示「正在执行 /review · 读取文件」并带进行中指示;完成后显示「执行完成 · /review · 4 步」,不消失。点它开合抽屉,抽屉里是步骤流水。目前这部分没有接真实引擎,只有演示命令会触发。

### 4.7 附件

- 通过附件按钮添加,或把文件拖进面板(拖入时面板显示拖放态)。
- 附件显示为面板外的一叠卡片,图片和其他文件是两种卡。收拢时只露顶上三张、错落叠放;展开是一个状态而不是 hover 效果,删掉一张其余就位;鼠标离开后有短暂宽限再收拢。

### 4.8 发送 / 停止

- 右下角是发送按钮;模型生成时变为「停止生成」。
- Esc 两段式停止:生成中第一次按 Esc,占位文案变成「再按一次 Esc 停止生成」,第二次才真正停止。
- 发送之后消息流的表现(`docs/send-flow-2026-09.md`):自己那条滑到视口顶部附近,下面留白给回复;等待期间显示一条扫光的折痕;收尾时思考段折回一行,锚住正在读的位置,不跳屏;重试按下即开槽。

## 5. 键盘与焦点

- 键盘可选的列表(`@` / `/` / 模型)里,「键盘选中」只由 ↑↓ / Home / End 和点击改变;鼠标悬停只是 hover 态,不移动键盘选中。↵ 作用在键盘选中那一行。
- Esc 由内向外逐层处理:ask 形态 → 拒绝整单;有抽屉 → 收抽屉;生成中 → 两段式停止;都没有 → 交给外层。
- 点面板外面只关模型抽屉;`@` / `/` 抽屉和状态抽屉不会被别处点击收起。
- ⌘N 在 composer 里是在当前项目下新建会话。
