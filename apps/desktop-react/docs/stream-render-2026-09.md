# 流式渲染架构(R 线,2026-09 设计)

起因:流式期渲染事故六轮(块消失/重影/错位/表格退化/交接线漂移),每轮都修在「账本投影 × 活尾巴」的拼接缝上;修好一种漂法,下一种还在路上。用户两问定性:「是不是该考虑架构?」「流式中和结束后是不是两个渲染?」——是。本设计消灭拼接缝,让流式与落定成为同一条渲染路。

## 一、五条不变式(宪法,违反任何一条=架构回退)

1. **单一事实流**:屏幕内容唯一来源=账本投影。delta 不是第二份内容,是账本的**先行披露**——同一个字符串更长的前缀提前到达。
2. **前缀定律**:对每个 (消息, part),活流与账本装下的是**同一字符串的两个前缀**(打包定律 `decode∘encode≡id` 的推论)。渲染长度 = max(账本长度, 活水位)。「同一截只画一次」「只长不缩」由此**结构恒成立**,不靠记账正确。
3. **流式=落定的短前缀**:一个推导函数。流式期屏幕 = 「到目前为止的落定态 + 更长前缀 + 未结算标记」;落定不是换画面,是前缀走到了头。不存在「过程中才有的病」这一类。
4. **中间态必须合法**:markdown 增量层只许产出「某个前缀的合法渲染」(早成形表/单向升级);起手式抬头等非法中间态按表处理(table-tail 补齐先例)。
5. **结构只增不换**:块身份跨帧稳定(单向闸),DOM 不重挂(row memo + 引用契约)。
6. **存储节拍不进显示路径**(09-01 用户直觉定题:「打包每 2s」是给磁盘定的节奏,凭什么被显示器听见)——直播期间,打包行到达那一帧**屏幕零像素变化**:它只做记账(水位清格),不做绘画。账本被读只有三个时刻:进门、断线重连、翻旧账。此条做成门断言(打包行到达帧的帧 diff 必须为空),它同时是 R2 正确性的最简验收:水位合并做对了,这条自动成立;做错了,它第一个红。

## 二、分层(各层职责一句话)

| 层 | 职责 | 改动 |
|---|---|---|
| **L0 传输** | 两条通道照旧;**合批器给每条 delta 盖账本身份章**:(messageId, runId, requestIndex, partIndex, kind, charOffset) | packages/backend stream-coalescer + @shared 类型,**加性字段**,老壳照跑 |
| **L1 状态** | core 投影 reducer 一字不动;旁挂**水位表** `Map<messageId, Map<partIndex, {text, offset}>>`——delta 按身份落格,打包行到达时「账本长度 ≥ 水位」即清格(被覆盖),不等式反向(理论不可能)= 定向重折 + 遥测计数 | 新小件,几十行 |
| **L2 推导** | 单一物化路(chat-materialize 缓存)读「投影 ∪ 水位表」,每 part 一条 `max(两前缀)` 合并式 | **appendTail/handOverToLedger/交接线/tailLens/turnIndex 落点启发式全家退役**——净删数百行,六轮事故的宿主整体消失 |
| **L3 markdown** | 增量解析照旧(prev.cut/早成形/单向闸),吃 per-part 合并后的字符串 | 不动 |
| **L4 React** | MessageRow memo + 引用契约(P0 机器) | 不动 |

## 三、守卫(不新造,现有资产换岗)

- **门矩阵**(七格 A–M+真机节奏素材)原样作 R2 验收:新路必须一次全绿。
- **运行时钳位**(dev):每 part 渲染长度单调断言 + 同源区间单画断言(门 H 的运行时版)——架构保证之外的最后一道岗哨。
- **遥测**:水位对账不等式反向计数,生产应恒 0;不为 0 = 前缀定律被上游破坏,直接报警不静默修补。

## 四、分期

| 期 | 内容 | 风险/回滚 |
|---|---|---|
| **R1** | 后端 delta 盖章(coalescer+@shared 加性字段);壳侧只读不用,老路照跑 | 零行为变化,单独入库 |
| **R2** | 壳侧水位线合并替换拼装机器;门矩阵全绿+钳位上岗;拼装旧路短期开关保留 | 开关一翻即回旧路 |
| **R3** | 真机浸泡(用户真实 agent 工作流数日)→ 删旧路+开关,净删收账 | 浸泡期任何红回 R2 |
| **R4:markdown 丝滑化** | 见下节,四件套 | 独立于 R1-R3 可并行设计,落地依赖 R2 的行级供给 |

### R4:markdown 丝滑化四件套(09-01 用户以百列怪物表定题:表头期裸文本数秒/数据首行上下抖)

1. **行级提交流(结构只在行界变)**:增量解析器对块层只发「整行落定」的结构提交(单调只增),半截的活行进块内**专用尾槽**(定高,就地填充)——块树不再每帧重算,任何中间态按构造合法;半行单元格不再逐帧决定「这一行存不存在」。
2. **结构先承诺(骨架先立)**:行首模式即可承诺型(`|` 行=表候选、``` =围栏候选),表头行**从第一个 `|` 起就按表格骨架渲染**(容器+单元格逐格长出),消灭「裸文本几秒→整段变形」的落差;承诺不可逆(单向闸语义推广),承诺错误(分隔行终未到)= settle 时按「模型写错照实画」既有拍板降回,一次性、非逐帧。
3. **几何锁定**:表 `table-layout:fixed`,列宽由表头一次锁定,数据行只填不排,settle 才允许一次重平衡;横向滚动条槽 `scrollbar-gutter:stable` 常留——滚动条出没不再制造竖向抖动;段落→表等一次性变形配高度锚定过渡+scroll anchoring,下方内容不被踹。
4. **超量退让**:百列级表加列上限削量(前 N 列+「还有 M 列」尾格,横滚看全)——与列表削量同一条超量纪律;行数走既有 content-visibility。

四件的公共前提正是 R2 的水位/行级供给;门矩阵加「怪物表」素材(百列/分隔行写错/表头超长)与「零竖向抖动」断言(逐帧量块底边,单调)。

**R4 扩展性再审四改(09-01 用户以 OOP 视角追问后修订):**
- **IR 反转(最大一条)**:块流 IR 是**我们自己的词汇**(开块/追行/关块 + kind + 载荷),markdown 解析器只是这条流的**生产者之一**——HTML part/图片 part/工具卡/未来的 mermaid、公式走同一条 IR。markdown 从脊柱降级为插件;新语法=新生产者或新 kind,不再挤 micromark 扩展这一条门。
- **容器栈**:三操作带嵌套语义(开容器/关容器),单调流长的是一棵树非平表——引用里的列表、列表里的代码块靠它;quote 复用注册表的既有判例是它的先声。
- **结构与注解分家**:跨块引用(脚注/引文/AI 批注)不许回改前文结构;另设「解析映射」通道,后到的定义只翻转既有节点的注解状态(DOM 不动,亮一盏灯)。「只追加」定律因此在有回指的语法下仍成立。
- **行内第二轴**:行内节点(链接/@引用/行内公式/提及)自己的注册表+同款流式必答题;消息引用批的半张表收编正名。
- **统摄原则:机制与政策分离**——开/追/关+容器栈是机制,永不为任何一型开特例;骨架先立/关块才渲/逐行亮是各型自报的政策,住注册契约。六轮事故的元凶皆系政策渗入机制。

**块注册表的供货合同随之升级(09-01 用户拍板纳入重构)**:注册表本身(kind→组件)保留;喂法从「每帧一份重新推导的块列表(块是一次性对象)」改为**单调块流**——仅三种操作:开块 / 给末块追加行 / 关块,外加一个活尾槽。块在「开」的那一刻获得终身身份号,React key 稳定从「小心维护」变「构造必然」;每种块的注册契约照 part 五问扩展(流式中间态的形 / 落定形 / 失败态 / 身份 / 几何策略),缺一问不许注册。既有 kinds(段落/表/围栏/引用/分隔线/figure)逐个迁入,单向闸与早成形政策在新合同下大半自然退役。

## 五、内容模型扩展性(09-01 用户追加:后续要图片/视频/文件/AI 生成的 HTML……)

行业经验一句话:**可扩展的流式内容系统都是「part 有型 + 注册表分发 + 管线不认识型」**(Notion 块模型/ProseMirror 节点注册同路;本仓已三次收敛到这个形:blocks/kinds、查看器三注册表、PaneContent)。落到 R 线:

**1. part 是扩展单元,不是 message。**账本 contentParts 本就带 kind(text/reasoning/tool);加一种内容=加一种 part kind(image/video/file/html…)。**管线(L0-L2)对 kind 不知情**:身份章、水位表、物化缓存全按 (messageId, partIndex, kind, progress) 走,只有叶子渲染器(注册表分发)认识具体型——六轮事故的教训反面:任何在管线里 special-case 某一型的写法都是下一轮事故。

**2. 前缀定律按型退化。**text 的 progress=字符数(max 合并);资产型的 progress=**状态机序号**(已宣告→生成/上传中(带百分比)→ref 就绪→字节已解析),同样单调只进不退——水位表通吃,一个字段两种解释。

**3. 事实与字节分家(已有地基,推广即可)。**part 只携带**内容地址**(hash/ref),字节走旁路异步解析——这就是 resolveBlob+blobEpoch 已经在跑的模式,推广成按 kind 注册的 AssetResolver(图片解出 objectURL、视频解出可流播源、文件解出元信息)。字节没到=占位,占位就是此刻的事实(诚实态先例)。

**4. 布局稳定性是媒体流式的第一难题(经验之谈):元数据先行。**图片/视频必须在字节前先到一条「尺寸/时长」元数据,渲染器**按内在比例先占位**——否则每张图加载完成都把下面的正文踹一脚(布局位移是媒体流的头号体感病,占位即钉死)。这条写进 part kind 的注册契约:**每个 kind 必答「流式中间态长什么样、占多大」**。

**5. AI 生成的 HTML=带信任边界的 kind,不是特殊的文本。**流式期按普通代码 part 呈现(高亮文本);settle 后经显式动作(或策略)提升为 **sandboxed iframe 预览**(独立 origin、CSP 无外联、postMessage 单向)——永不 innerHTML 进宿主 DOM。信任策略进一张表(哪些来源可自动预览/哪些要点一下),与插件 webview L3 线、artifact 沙箱同一套安全语汇。

**6. 注册契约(每个 part kind 必答五问,状态先行的 part 版):**中间态渲染(progress 各阶段的形)/落定形/失败与诚实态/身份(memo 与零重挂的键)/尺寸策略(先占多大)。缺一问不许注册——与库件「三类状态缺一不许入库」同款门槛。

R 线分期不变;本节的落地物是 R2 里水位表按「progress 通吃」实现 + part 渲染注册表立骨架(text/reasoning/tool 三型迁入),图片型作第一个扩展验证(素材:生图流)。

## 六、架构审查记录(09-01,资深前端架构师视角红队自审)

**结构级四条(不钉死会重演六轮事故):**
1. **换代律**:前缀定律的地基是「只追加」,而编辑重发/重新生成/压缩/删除/标注五个动作在改写历史。规则:**追加是常态,改写是换代**——part 带世代号 gen,任何重写=gen+1=整段替换(一次合法重画),永不就地改;压缩类历史手术走整份重折。水位/缓存键全部带 gen。
2. **身份由引擎铸造**:delta 的 (partIndex, offset, gen) 章唯一产地=引擎(它本就给打包行编号),同一计数器出两种凭据;合批器只搬运不编号——两处各编一套=把「对不上」搬到后端重演。
3. **活水位只存连续前缀**:delta 通道无重放,断线可能丢段;规则=偏移恰等于当前水位才收,否则扔(账本 ≤2s 自然补齐,自愈零成本),严禁「收到就拼」拼出带洞字符串。
4. **多实例从第一天**:水位表按 sessionId 持有(T4 会话多开/Dock 活预览/QuickLook 多消费面),禁模块级单例(chat-source 判例学费已交)。

**补强级三条:**
5. 长 part 性能:分块数组攒、读时懒拼,合并结果按 (账本长,活长,gen) 记忆——禁每帧天真字符串拼接(十万字 part×每帧 7 字=O(n²))。
6. 字素边界:偏移按 UTF-16 码元,渲染边界向字素边界收一格,防切开 emoji/代理对的一帧乱码。
7. 性质模糊测试:随机乱序×随机切割喂同源,终态逐字节同——对「乱序无害」的机器证明,与门矩阵(已知病照妖镜)互补。

**审毕认可项**:数据层纯 TS 零 React(可跨壳复用)/HTML 沙箱边界/每期回滚路径/遥测+六不变式常驻岗哨。

**多帽补审(09-01 第二轮):**
8. 【QA】后台节流追帧:窗口最小化时 rAF 停摆而 delta 照灌,恢复可见那一刻**不走增量,直接一次全量解析**(等价落定路),禁增量追帧堆出 1153ms 级长帧。
9. 【UX】选区稳定:流式追加不许打飞用户已选中的文字(断言钉住);骨架承诺错误的降级=一次性+高度锚定,不许闪。
10. 【a11y】读屏播报单位=R4 的行提交/块关闭(逐 delta 播报是灾难),行级提交流白捡的对齐。
11. 【安全】渲染层三规(工具结果会把外来 markdown 混进消息,攻击面真实存在):链接 URL scheme 白名单(拦 javascript: 等伪协议)/远程图片默认阻断或代理(追踪像素+IP 泄露)/代码块 bidi 隔离+ANSI 中和(双向覆盖字符伪装代码)。一次性立规,最便宜的时刻是现在。
12. 【容量】消息列表虚拟化预案位:memo 省 CPU 不省 DOM;块身份稳定(R4)正是将来行级 content-visibility/虚拟化的前提,不现在做但留位。
13. 【运维】不变式违反生产态**永不 throw**=自愈+计数;「理论不可能」计数器须有可见面(挂通知中心诊断区,依赖 C1 拍板)。
14. 【分布式】整套=Kafka 消费者语义(热通道无持久+冷日志按 offset 收敛),工业验证十余年的形,非新发明——快照围栏(listRaw 定格+pendingLedger 回放)已有先例覆盖读时刻竞态。

## 六之二、R2 状态先行三表(09-01,动手前先产,施工照它走)

### 表 1 · 水位表的生命周期(它的寿命是「这一条打开着的会话」)

| 事件 | 水位表怎么动 | 为什么 |
|---|---|---|
| **建**(`open(sessionId)`) | 与 `fold` 同时新建一个**值**(不是全局单例;换会话就是换一份) | 审查条 4:多实例从第一天。它是 `fold` 的邻居,不是模块里的那一个 |
| **喂**(裸 delta 带 R1 的章) | 按 `(messageId, partIndex, gen)` 落格,**偏移恰等于当前水位才收**;偏移小于水位=回声,丢;大于水位=中间缺了段,丢并计数 | 审查条 3:delta 通道无重放,断线会丢段。带洞的字符串比没有更坏,账本 ≤2s 自愈 |
| **打包行到达** | **只清格,不画画**:账本对这一格画得出来的长度 ≥ 水位长度时,那一格退役 | 第六不变式:存储节拍不进显示路径。清格不改 `max`,所以那一帧零像素变化 |
| **重折在飞**(`fold.pending`) | **一个字不动**,照收照存 | 重折是账本那条路的事。从前的交接线要在重折点重新起算(`rebaseTailLens`),那正是 09-01 抓到的漂移源;水位表没有基准可漂 |
| **缺号触发整份重折** | 不动 | 同上。重折完成后账本变长,自然清格 |
| **换会话 / `open('')` / `reset()`** | 整份丢 | 上一条会话的水位与这一屏无关 |
| **这一轮收尾**(`stream:complete/error/aborted`) | 该消息那一格整条丢 | 收尾后账本是全的,水位只会说同样的话。也是 R2 期对「换代」的保守答复:重跑/编辑重发一律清水位,不去猜 gen |
| **HMR dispose** | 随 `chat-source` 那一口 `reset()` 一起退役(不写第二套拆卸) | 本目录 CLAUDE.md 的模块级副作用律 |

### 表 2 · UI 生命状态(每一格水位的形)

| 状态 | 判据 | 屏幕上 |
|---|---|---|
| **无**(empty) | 这条消息没有任何水位格 | 纯账本投影,与 R1 之前逐字相同(冷加载、历史消息、中途入场的第一帧) |
| **领先**(ahead) | 水位长 > 账本可画长 | 画水位那一份(`max`),这是直播期的常态 |
| **齐平**(level) | 两者相等 | 画哪一份都一样 —— 打包行到达那一刻正是走到这里,所以零像素变化 |
| **落后**(behind) | 账本可画长 > 水位长(中途入场 / 重连补齐) | 画账本那一份;水位那一格当场退役 |
| **反向**(不可能) | 账本长 > 水位长**且**两者前缀不同 | 前缀定律被上游破坏。生产态**不抛**:计数 + 定向重折(审查条 13),门里另有断言 |

### 表 3 · 交互状态(这一层没有交互态,只有读者)

水位表是纯数据,不接鼠标键盘。它的「交互」只有一条:**读者是谁**。今天只有一个读者(物化读路 `chat-materialize`),将来 Dock 活预览 / QuickLook 是第二第三个读者 —— 所以它按会话持有、不做模块级单例,加一个读者不需要改它一个字。

### 与既有两件的关系(逐条钉死,免得三份状态各说各话)

| 既有件 | R2 之后 | 理由 |
|---|---|---|
| `refold` / `pendingLedger` | **一个字不改** | 它们是账本那条路的自愈机制;水位表与它们**正交** —— 重折期间水位照收,重折完账本自己追上来 |
| `tail` / `tailLens` / `tailCoverage` / `appendTail` / `handOverToLedger` | **整条退役**(开关关掉时才走) | 它们的全部工作是「在两条内容车道之间对账」。水位表让两条车道变成同一个字符串的两个前缀,对账这件事**不存在了** |
| `chat-materialize` 的按节点 memo | 保留,键上加一格水位版本 | 审查条 5:合并结果按 (账本长, 活长, gen) 记忆,禁每帧天真拼接 |

## 六之三、R4a 状态先行三表(09-01,动手前先产,施工照它走)

R4a = **行级提交流内核**:块流 IR(`content/blocks/stream/events.ts`)+ 机器(`machine.ts`,纯机制)+ markdown 生产者(`content/markdown/block-stream.ts`,政策)+ 注册契约五问(`stream/contract.ts`)。开关 `onething.blockStream`(默认开)。

### 表 1 · 块实例的生命周期(它的寿命是「这一条消息这一段正文」)

| 事件 | 块实例怎么动 | 为什么 |
|---|---|---|
| **开**(`open`) | 当场发终身身份号 `${源偏移}:${kind}`,进容器栈当前层的末位 | 号是**产地派生**的:直播 / 收尾 / 重折 / 冷加载四条路必须给出同一个号,而不透明计数器活在一台机器实例里,重折换一台号就全变(那一刻整条消息重挂) |
| **落定一行**(`append`) | 提交那一份换成更长的前缀,活尾槽当场作废 | 「结构只在行界变」的兑现处:一帧里有没有 `append` = 这一帧结构动没动 |
| **半截活行**(`tail`) | 只换**画面**,块的数目 / 身份 / 前面每一块一个字不动 | 一帧的文本结不结束在换行上由 provider 的分片说了算(table-tail 那条病历的根),所以半截的行不许改结构 |
| **关**(`close`) | 提交冻结,从此 model 永不再变 | 判据是增量层那个安全切点(「前 N 个字符的解析不会被后面追加的字符改掉」)—— 一个字都不用另编。收尾时全体关闭 |
| **没长成**(`retract`) | 从末位摘掉,号退役 | 原位换装的前半拍(段落 → 表)。**只许作用于末块** —— 结构只在尾巴上收,提交过的一格都不动 |
| **早成形认领** | `retract` + `open`(换了型就是另一个号) | 这是**唯一一个可以在行中间动结构**的口子,而且是型自己在注册契约里声明出来的(`stream.earlyForm`),不是机制的漏洞 |
| **模型写错字导致认领翻回去** | 退役过的号可以回来,记一笔 `revivals` | 曾经写过「身份永不复生」那条更硬的法,当天被这个**真实**场景推翻:`\|-` 认成表,下一帧写了个 `\|-x` 又变回段落。这不是「理论不可能」,是常态 |
| **换会话 / 换消息 / 收尾** | 整条车道丢掉(`forget`) | 收尾之后账本是全的,冷加载那条无状态路给出同一份号 |
| **HMR dispose** | 随 `assemble/markdown.ts` 那一口 `reset()` 一起退役(不写第二套拆卸) | 本目录 CLAUDE.md 的模块级副作用律 |

### 表 2 · UI 生命状态(每一个块实例的形)

| 状态 | 判据 | 屏幕上 |
|---|---|---|
| **开着·只有活尾槽**(midway) | 刚 `open`,还没落定过整行 | 按这一型的 `stream.midway` 画:`grow` 逐行亮(段落 / 标题 / 围栏 / 引用 / 列表),`hold` 由别的型代画(表 / 图 / diff 在合上之前是 `code(closed:false)`) |
| **开着·有提交**(growing) | 落定过 ≥1 行,还没关 | 画「提交 + 活尾槽」。这是直播期的常态 |
| **关了**(settled) | `close` 过 | 画提交那一份,从此逐字不再变;`stream.settled==='swap'` 的型在这一刻已经换过装了 |
| **没长成**(retracted) | `retract` 过 | 不在屏幕上。号退役,可复生(记 `revivals`) |
| **画不出来**(failure) | 注册表不认识 / 渲染器抛错 | 按 `stream.failure`:`source` 兜到 source-fallback(源码永远可见),`honest` 就地说实话 |
| **违法**(不可能) | 关了的块又在长 / 撤回中间那一块 / 同号共存 | **永不 throw**(dev 也在这一侧):丢掉那条事件 + `violations` 加一。只有 vitest 里抛,因为反证要的是红 |

### 表 3 · 交互状态(这一层没有交互态,只有读者)

块流是纯数据,不接鼠标键盘 —— 交互住在各 kind 的组件里(块壳的檐、动作、折叠),块流一个字都不知道。它的「交互」只有一条:**读者是谁**。今天只有一个读者(装配管线第 ④ 步),将来 Dock 活预览 / 导出 / 读屏播报是第二第三个 —— 所以它按 `(messageId, 段序号)` 持有、不做模块级单例,加一个读者不需要改它一个字。

### 本期没做、记在账上的两格

1. **容器栈有机制、markdown 还没用它**:引用 / 列表今天仍以自持嵌套的 model 到达(`quote.blocks` / `list.items`)。把它们迁进容器栈要改 `to-blocks` 的产出形,属可感知的行为风险,不在「保行为等价」这一期。机器的容器语义已经全测(开 / 关 / 撤回整支 / 栈顶纪律)。

## 六之四、R4b 状态先行表增补(09-01,动手前先产)

R4b = **政策层三件**:承诺(commit)/ 几何锁定 / 超量削列。机制层(块流 IR + 机器)一个字没改 —— 这正是 R4a 那条「机制与政策分离」要买的东西。

### 表 1 增补 · 承诺(commit)的生命周期

| 事件 | 块实例怎么动 | 为什么 |
|---|---|---|
| **承诺开**(行首 `\|` 且那一行有 ≥2 根竖线) | 段落 `retract` + 表 `open`(号 `${偏移}:table`) | 用满 R4a 立的那个唯一口子:早成形认领是唯一可以在行中间动结构的地方,而且是型自己在注册契约里声明出来的 |
| **承诺中·列在长** | 同一个号,只发 `tail` | 列数变是**画面**变,不是结构变 —— 结构只在行界变这条不受影响 |
| **表头落定 / 数据行到达** | `append` | 行界提交 |
| **承诺兑现**(真分隔行到齐) | **零事件** | micromark 自己就给出 table,同号同型,承诺与事实合流 |
| **承诺收回**(分隔行写完而格数对不上) | 表 `retract` + 段落 `open` | 一次性,而且**降在事实可知的那一刻**(不是拖到 settle)—— 见下面的出入记档 |
| **settle** | 不再承诺,照实解析 | 「模型写错照实画」既有拍板 |

**单调性由构造保证,不由记账保证**:每条判据只许在文本增长时从假变真。曾经想过给承诺配一本账(「承诺不可逆」),写到一半发现不需要 —— 唯一的反向是「分隔行写完而格数对不上」,而那不是反悔,是事实变得可知。

**与派工令的出入(记档)**:派工令写「承诺错误 settle 时一次性降回」。实现降在**分隔行写完那一刻**,比 settle 早。理由:那之后整条流稳定,收尾零变化(「流式末帧 == 冷加载」自动成立);拖到 settle 反而要先把 `| --- | --- |` 当数据行画出来,再在收尾整段塌一次。**这是可感知的行为选择,列在这里等复议。**

### 容器栈迁移(item 4)——**勘察后需要一次拍板**

R4a 留账说「机制的容器已经在,markdown 还没用它」。R4b 动手迁引用/清单时撞到三件事,都不是实现难度,是**设计选择**:

1. **栈是给顺序生产者用的,而 markdown 生产者是个差分器**。机器的 `open-container` / `close-container` 靠一根栈决定「新块开在哪一层」;差分器要往**一个已经存在的容器**里补一个孩子时,栈上没有它 —— 要么加一对 `enter/exit`(IR 从 7 个词长到 9 个),要么给 `open` 加一格 `parent`(不用栈了)。两条路都是 IR 变更,该拍板,不该是政策批的顺手改动。
2. **迁了也拿不到身份收益**。容器折回 `quote.blocks` / `list.items` 之后,`Quote` / `List` 仍然按下标发 key —— 孩子的流身份到不了 DOM。要拿到收益得改块词汇(把孩子当 children 递)或改组件契约,又是一次拍板。
3. **`list` 还缺一个词**:`items: BlockModel[][]` 是两层,容器树里得有一个 `list-item` 节点才装得下 —— 那是**块词汇**的变更。

所以本批只把**嵌套素材**先送进门(引用里的清单 / 清单项里的围栏与表 / 引用套引用),让「流式末帧 == 冷加载」与零双画先守着;迁移本身等三选一的拍板。

## 七、与既有法的关系

本设计是后端 F 线三定律(事实一条流/状态即折叠/打包是压缩)在壳侧的兑现——壳当初为降延迟自建了第二条内容车道,六轮事故全是那条车道与定律的摩擦。R 线不是新发明,是把壳拉回定律之内。
