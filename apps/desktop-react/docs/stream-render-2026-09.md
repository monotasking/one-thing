# 流式渲染架构(R 线,2026-09 设计)

起因:流式期渲染事故六轮(块消失/重影/错位/表格退化/交接线漂移),每轮都修在「账本投影 × 活尾巴」的拼接缝上;修好一种漂法,下一种还在路上。用户两问定性:「是不是该考虑架构?」「流式中和结束后是不是两个渲染?」——是。本设计消灭拼接缝,让流式与落定成为同一条渲染路。

## 一、五条不变式(宪法,违反任何一条=架构回退)

1. **单一事实流**:屏幕内容唯一来源=账本投影。delta 不是第二份内容,是账本的**先行披露**——同一个字符串更长的前缀提前到达。
2. **前缀定律**:对每个 (消息, part),活流与账本装下的是**同一字符串的两个前缀**(打包定律 `decode∘encode≡id` 的推论)。渲染长度 = max(账本长度, 活水位)。「同一截只画一次」「只长不缩」由此**结构恒成立**,不靠记账正确。
3. **流式=落定的短前缀**:一个推导函数。流式期屏幕 = 「到目前为止的落定态 + 更长前缀 + 未结算标记」;落定不是换画面,是前缀走到了头。不存在「过程中才有的病」这一类。
4. **中间态必须合法**:markdown 增量层只许产出「某个前缀的合法渲染」(早成形表/单向升级);起手式抬头等非法中间态按表处理(table-tail 补齐先例)。
5. **结构只增不换**:块身份跨帧稳定(单向闸),DOM 不重挂(row memo + 引用契约)。

## 二、分层(各层职责一句话)

| 层 | 职责 | 改动 |
|---|---|---|
| **L0 传输** | 两条通道照旧;**合批器给每条 delta 盖账本身份章**:(messageId, runId, requestIndex, partIndex, kind, charOffset) | packages/backend stream-coalescer + @shared 类型,**加性字段**,老壳照跑 |
| **L1 状态** | core 投影 reducer 一字不动;旁挂**水位表** `Map<messageId, Map<partIndex, {text, offset}>>`——delta 按身份落格,打包行到达时「账本长度 ≥ 水位」即清格(被覆盖),不等式反向(理论不可能)= 定向重折 + 遥测计数 | 新小件,几十行 |
| **L2 推导** | 单一物化路(chat-materialize 缓存)读「投影 ∪ 水位表」,每 part 一条 `max(两前缀)` 合并式 | **appendTail/handOverToLedger/交接线/tailLens/turnIndex 落点启发式全家退役**——净删数百行,六轮事故的宿主整体消失 |
| **L3 markdown** | 增量解析照旧(prev.cut/早成形/单向闸),吃 per-part 合并后的字符串 | 不动 |
| **L4 React** | MessageRow memo + 引用契约(P0 机器) | 不动 |

## 三、守卫(不新造,现有资产换岗)

- **门矩阵**(七格 A–M+真机节奏素材)原样作 R2 验收:新路必须一次全绿。
- **运行时钳位**(dev):每 part 渲染长度单调断言 + 同源区间单画断言(门 H 的运行时版)——架构保证之外的最后一道岗哨。
- **遥测**:水位对账不等式反向计数,生产应恒 0;不为 0 = 前缀定律被上游破坏,直接报警不静默修补。

## 四、分期

| 期 | 内容 | 风险/回滚 |
|---|---|---|
| **R1** | 后端 delta 盖章(coalescer+@shared 加性字段);壳侧只读不用,老路照跑 | 零行为变化,单独入库 |
| **R2** | 壳侧水位线合并替换拼装机器;门矩阵全绿+钳位上岗;拼装旧路短期开关保留 | 开关一翻即回旧路 |
| **R3** | 真机浸泡(用户真实 agent 工作流数日)→ 删旧路+开关,净删收账 | 浸泡期任何红回 R2 |
| **R4**(备选) | 若仍存某类闪动:markdown 层节点身份持久化(增量树) | 独立评估,大概率不需要 |

## 五、与既有法的关系

本设计是后端 F 线三定律(事实一条流/状态即折叠/打包是压缩)在壳侧的兑现——壳当初为降延迟自建了第二条内容车道,六轮事故全是那条车道与定律的摩擦。R 线不是新发明,是把壳拉回定律之内。
