## 1. 现状与真因(调研 09-09)

- 会话列表点一行 = `content/session-open.ts` `enterSessionInWorkbench` 三档:已开着 → 跳过去;焦点会话叶装着别的会话 → **原位换 ref**(`replaceRef`);没有会话叶 → 中央区开一格。第二档就是用户说的「覆盖」。只有拖到标签条上才会多一格。
- 「切回来要重新加载」的真因在 `data/chat-source.ts` 的引用计数:一片叶换掉会话 ref → 旧会话的 `ChatSource` 引用归零 → `release` 在下一拍 `dispose()` 整台机器;切回来 `acquire` 重新 `runLoad`,从 core 再拉一遍。**不是网络慢,是壳把它扔了。**
- 目录面板(`files-root:<路径>`)根在开出来那一刻冻结,与会话没有任何关系;换会话它不动。文件查看器同理。
- 工作区切换:全部家具 per-space 换装,没有任何东西跟人走(dock-scope §1.3)。

## 2. 工作区一致性(不改 dock-scope §2)

「工作区」「设置」「应用」「通知」四块瓦是全局的。切工作区那一拍:进场树先剥掉自己账上残留的全局格,再从离场的活树把全局格**连区域、连叶内位次、连浮窗 rect、连 floatOrder 位次**一起搬过来。所以「工作区」面板在 A 工作区是右架子第二条,切到 B 还是右架子第二条;在 A 是左上角一扇浮窗,到 B 还是同一个角同样大小。机制、落点、边角全在 dock-scope §2.3–§2.5,本文不复述。

## 3. 会话一致性:伴随面

### 3.1 定义

**伴随面** = 目录面板、文件查看器、改动面板这三种内容。它们不是工作区的家具,是**某条会话的**:在哪条会话是环境会话(`envSessionId`,焦点粘住的那条)的时候开出来的,就归哪条会话。会话本身、总览、检索、模型、设置这些不是伴随面,与本节无关。

### 3.2 记什么

每条会话一份记录,住在 workbench 的 per-space 家具里(与 `regions` 同一本账、同样落盘):

```ts
sessionCompanions[sessionId] = {
  seats: Array<{ ref: ContentRef; region: RegionId; leafId: string; index: number }>, // 开着哪些、各在哪
  active: RefId | null,                                                                // 最后看的是哪一格
  view: Record<RefId, {                                                                // 每一格自己的状态
    scrollTop?: number
    expanded?: string[]        // 目录面板:展开了哪些子目录
    selected?: string          // 目录面板:选中哪一行
    line?: number              // 文件查看器:看到第几行
  }>
}
```

`view` 由各种内容自己写、自己读(目录面板写 `expanded` / `selected`,查看器写 `line`),壳只负责按会话存取。核心层不知道哪一种内容记什么。

### 3.3 切会话那一拍

```
离场会话 A:
  把树上所有伴随面(三种内容的格)连坐标收进 sessionCompanions[A].seats,
  记下当前活动的那一格到 .active,各格把自己的 view 交上来;
  从树上摘掉这些格(叶空了就按既有 prune;会话叶不动)。
进场会话 B:
  有记录 → 按 seats 逐格放回原区域原位次(叶没了就落到同区域第一片叶末尾),
           活动格设成 .active,各格拿回自己的 view 恢复滚动 / 展开 / 行号;
  没记录 → 继承「种类」不继承「内容」:
           A 开着目录面板 → 给 B 开一格 B 自己 workdir 的目录面板;
           A 开着改动面板 → 给 B 开一格 B 自己仓的改动面板;
           文件查看器不继承(那是 A 看的文件,与 B 无关);
           B 没有 workdir → 什么都不开。
  焦点不动(还在 B 的输入框)。
```

这样用户在 A 看 `Dock.tsx` 第 120 行,切到 B 翻另一个项目的文件,再切回 A:目录面板展开着原来的子目录、选中 `Dock.tsx`,查看器停在第 120 行,活动标签就是那格查看器。这就是「回到上次中断的地方」。

### 3.4 边角

- **两条会话同一个 workdir**:各自一份记录,目录面板的 ref 相同(`files-root:<同一路径>`),树上同时只放一份,`view` 各记各的。
- **两片会话叶并排**:伴随面跟环境会话,焦点从左叶点到右叶,伴随面按 3.3 换一轮。并排时右叶想常看自己的目录,把那格目录面板**钉住**(标签右键「钉住」):钉住的格不算伴随面,不随会话收放,这是 §4.2 之外唯一一个新增的标签动作。
- **关掉一格伴随面** = 从当前会话的记录里删掉,切回来不会再冒出来。
- **删除会话** → 记录一起删。会话 workdir 改了 → 目录面板那格不自动换根,下次进场照记录放回;要看新目录就再点「目录」瓦。
- **Dock 的「目录」瓦**:点 = 给环境会话开一格它 workdir 的目录面板(已有就叫到前面);「改动」瓦同理。零改动。
- **换工作区**:伴随面是 per-space 家具,随工作区一起收放;全局瓦携带不碰它们。
- **另一条路(不取)**:不收放,所有会话的伴随面都留在标签条上,切会话只是激活对应那格(dock-scope §4 第二稿)。标签会随会话数累积,「回到中断处」也做得到但屏幕上全是别人的目录。按用户「切回来回到中断处」这句取收放。

## 4. 点会话列表:预览标签

### 4.1 默认行为

沿用 `enterSessionInWorkbench` 的第一档「已开着 → 跳过去」,用户已确认这是对的。第二档「覆盖」改成**预览**:

- 焦点会话叶里至多有一格**预览格**。列表点一行,这一行没开着 → 进预览格;预览格里原来那条被换掉(这就是今天的「覆盖」,但只覆盖预览格)。标签名用斜体或浅一档的颜色标出「预览」。
- 预览格**转正**的时机:在里面发了一句话、输入框有草稿、把标签拖过、右键「保留」。转正后它就是一格普通标签,下一次列表点别的会话会在它旁边**新开**一格预览。
- 用户描述的两种情形都落对:「只开着一条,在列表里来回切着看」→ 一直在复用预览格,标签不增;「拖了两条到标签条上都在干活,再点第三条」→ 那两条早已转正,第三条开进新的预览格,不覆盖任何一个在干活的。
- 「我在这条会话里做了事,切走再切回来还要 load」这条病的两半:做了事的会话已转正所以标签还在(§4),而且就算被覆盖了内存也留着(§5)。

### 4.2 设置

设置项 `sessions.openMode`,三档,per-space 家具(照 `data/file-open-mode.ts` 的形:`FileOpenMode` 那套 store / 落盘 / 清洗全是现成的判例):

| 档 | 行为 |
| --- | --- |
| `replace`(默认,09-10 改判) | 原位换 ref。被换掉的那条留在停靠池里(§5),换回去不重载 |
| `newTab` | 列表点一行永远在焦点会话叶末尾新开一格 |
| `preview` | §4.1 |

入口:设置 → 界面,一行三选;标签条右键菜单里同一行(动作单产地是右键菜单,09-01 判例)。三选与菜单的**次序即上表次序**,缺省那一档排第一(单产地 `SESSION_OPEN_MODES`,两处都不许自己再排)。

**缺省从 `preview` 改成 `replace`(09-10)**。用户原话:「open 的行为应该可控:可以选择覆盖(但切换速度不要慢),也可以新开 tab;tab 只是为了分屏或其他用处,对 session 来说没那么重要,重要的是加载的速度。」——三档的价值在**可控**,不在标签;标签条是为分屏之类的用处存在的,对「切会话」这件事本身不重要,所以缺省回到最直接的那一档。09-09 立 `preview` 为缺省时押的是「覆盖会顶掉在干活的那条」,而那条病 C1 已经从另一头治了(停靠池 74abc07a):替换不再等于丢掉,只是屏幕上少一格标签,切回去不重载 —— 用户那句「覆盖可以,只要切得快」要的正是这个。§4.1 与 §4.3 一个字没改,`preview` 只是从缺省变成可选。

**换缺省不改写存量档案**:账上存着 `preview` 的空间原样留着 —— 那是用户自己在设置页或右键菜单里选过的。清洗(`clampMode`)判的是「认不认得这一档」,不是「是不是今天的缺省」;缺省只对账上压根没有这一格的空间生效。

### 4.3 骨架落点

`session-open.ts` 第二档改成读 `openMode`;预览格是**叶上的一格标记**(`PaneLeafNode.previewIndex?: number`),不是新种类;转正 = 清掉标记;`replaceRef` 照旧是原位换,所以叶不重挂。会话种类不需要知道自己是不是预览。

### 4.4 标签是什么

左边的会话列表是**目录**:这个工作区里所有会话都在那儿,像书架。顶栏的标签条是**工作台**:此刻摆在桌上、可以并排、可以拖到架子上或撕成浮窗的那几样。目录里点一本 = 拿到桌上翻;桌上已经摊着 = 翻到那一页。单叶模式下两者看起来像重复,是因为今天点目录总是**换掉**桌上那本;预览格让「翻一翻」和「摊开干活」有了区别,分屏时标签的意义(哪几样并排)本来就清楚。这一条不新增任何 UI。

## 5. 不重载:会话留在内存里

### 5.1 机器不扔

`chat-source.ts` 的 `release` 归零后不再 `dispose`,改成**停靠**:进一个有上限的最近使用池(建议 8 条,LRU),仍然订着 SSE 所以内容跟着核心走;`acquire` 命中停靠池 → 直接拿回,**不跑 `runLoad`**;超出上限的那条才真正 `dispose`。删除会话立刻出池。这一处改动只碰 `retain / acquire / release` 三口与一张池表,`ChatSource` 内部一个字不动。

### 5.2 视图状态按会话记

新 `data/session-view-state.ts`:`{ scrollAnchor(哪条消息、偏移多少), draft(输入框草稿), folds(哪些工具卡 / 折痕展开着) }`,按会话 id 记在内存(草稿若已有落盘产地就复用它,不立第二处)。聊天区挂载时先读它再决定滚到哪,卸载前写回。停靠池 + 视图状态两件一起,切回来的那一帧就是离开时的样子。

### 5.3 与伴随面的关系

§3 记的是「桌上摆着什么、各自看到哪」,§5 记的是「会话本身的机器与视图」。前者是家具落盘,后者是内存(重启后会话本身照旧从账本载入,那是正常的一次加载,不是这条病)。
