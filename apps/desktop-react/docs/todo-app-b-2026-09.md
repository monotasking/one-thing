# 待办 App · B 形实施方案(2026-09-17)

> 起因:用户看过真机上的「我的清单」浮窗后说「ui 我很不满意;如果有 100 个,现在的样式就得再铺 100 个吗」「要想一个 app,而不是一堆 tab 的组装,这一个窗口太像一个 tab 页了」。三个候选(样例 artifact「待办 App 三案」)里用户选 **B · 一个输入框**,并追问「这个动作为什么不放在 header」—— 定稿:**切换清单与搜索都在窗口头里,头下面直接是正文**。
>
> 本篇取代 `todo-2026-09.md` §5.4(Dock 面板那一形:清单标签条 + ⋯ 菜单)。编辑器内核(`todo-editor-2026-09.md`)不动,只加「收起的单元」一格(§5)。

## 1. 一句话

一扇待办窗 = **一条头**(App 图标 · 当前清单名 ▾ · 搜索 ⌘F · ⋯ · 关闭)+ **一份正文**。切清单和搜索是同一个弹层;正文里已完成的项默认收成一行、小节可折叠。窗口宽窄、在浮窗 / 架子 / 舞台 / 计划抽屉里都是这一套。

## 2. 形与交互

### 2.1 头

| 位置 | 内容 | 行为 |
| --- | --- | --- |
| 左 | App 图标(ListChecks) | 无动作(身份) |
| 左 | 当前清单名 + ▾ | 点 = 开「切换 / 搜索」弹层,输入框为空;名字过长截断,Tooltip 全名 |
| 右 | 搜索框(「搜索清单和项」+ ⌘F 键帽) | 点 / ⌘F = 开同一个弹层,焦点进输入框 |
| 右 | ⋯ | 新建清单 / 打开源文件 / 在访达中显示 / 编辑时显示记号(三档) / 显示已完成 |
| 右 | 窗口钮(关闭等) | 由宿主给,见 §3 |

- 窄于 `--todo-head-narrow`(约 420px):搜索框收成一颗放大镜(`ui/IconButton`,Tooltip「搜索清单和项」),清单名吃剩下的宽。
- 头的空白处按下 = 拖窗(宿主既有手势,见 §3)。
- 右键清单名:重命名 / 在访达中显示 / 删除(沿用 T3 的菜单与确认)。

### 2.2 切换 / 搜索弹层

一个弹层两种内容,判据是输入框空不空:

| 输入框 | 内容 |
| --- | --- |
| 空 | 「最近」5 份(按最后打开);「全部清单」按名字排,底部「+ 新建清单」 |
| 有字 | 「清单」:名字命中的(最多 8,高亮命中);「项」:各清单里命中的项(最多 50,每条带所属清单名、完成的画 ✓) |

- 键盘:↑↓ 走 active(`ui/a11y/list-selection`,hover 不改 active)、↵ 打开、Esc 先清空输入再关、⌘F 在弹层里 = 选中全文。
- 打开一份清单 = 关弹层 + 正文换成那份 + 记进「最近」。打开一条**项** = 同上,并滚到那一项、那一行淡闪(复用 `recentlyChanged` 的淡底),光标**不**进编辑(看到 ≠ 要改)。
- 弹层宽度 = 窗宽减两侧 `--sp-2`,高度封顶 `min(420px, 窗高 − 头高 − --sp-4)`,内部滚动;选中项 `scrollIntoView`。
- 结果为空:一句「没有找到「x」」+ 「新建清单「x」」一行(按 ↵ 就建)。

### 2.3 正文

- 顶部:清单大标题(= 文件 `# ` 那一行,可编辑)与一行读数「N 项未完成」(文字读数,不是徽)。
- **已完成默认收起**:每个小节(文件里 `##`/`###` 之间,没有小节就是整份)里已完成的项收成一行「▸ 已完成 N 项」,点开展开;展开状态按清单记(`preferences.showDone[ref]`)。⋯ 里「显示已完成」是全局开关,开着时不收。
- **小节可折叠**:`##` / `###` 标题前一个折叠三角(hover 才显),折起来显示「N 项未完成」;按清单 + 标题文字记(`preferences.folded[ref][heading]`)。
- 空的一项不画勾选框(只在编辑它时画)。
- 计划抽屉(会话计划)用同一份正文,打开时滚到第一条未完成那一项附近(已完成的小节整节折起来也由上面两条自然得到)。

## 3. 壳:头从哪儿来 —— 「内容自带头」

浮窗、架子、舞台的标题栏**就是那片叶的标签条**(W4 判例:没有第二条檐)。待办窗现在的毛病是标签条画了一格「待办」,待办面板自己又画一排清单标签 —— 两条带子叠着。

**做法:`ContentKind` 加一格自述 `stripHeader`**(一行登记,不是给待办开特例):

```ts
/**
 * 这一种内容**独占一片叶**时,叶的标签条不画标签,改画它交出来的这条头
 * (宿主的窗口钮、拖窗手势照旧挂在条上)。叶里有两格以上时照常画标签,
 * 这条头改由内容自己画在正文顶上 —— 头随内容走,永远只有一条。
 */
stripHeader?: ComponentType<{ contentRef: ContentRef; placement: 'strip' | 'inline' }>
```

- `LeafStrip` / `PaneLeaf`:叶里只有一格且种类有 `stripHeader` → 条上渲染 `<Header placement="strip">`,右端照旧挂 `host.actions`,空白处拖窗判据 `isDragBlank` 不变(头里的钮与输入框本来就是 `button` / `input`,补一句 `input`)。
- 叶里多格 → 标签条照旧;内容组件自己在正文顶上画 `<Header placement="inline">`。内容怎么知道自己此刻是哪一种?这是「宿主对这一份实例说的事实」,与 `content/visibility.ts` 的 `PanelVisibility`(`visible` / `interactive`)同一类 —— 在那一格上加 `headerInStrip: boolean`,叶摆内容时一并给出,缺省 `false`(= 自己画在正文顶上),不新开 context。
- `panel` 这一种内容是所有瓦共用的:它的 `stripHeader` 按 `ref.key` 查一张表 `PANEL_HEADERS`(与 `content/index.tsx` 的面板组件表并排,一行一瓦),查不到 = 不自带头。
- 焦点:头里的输入框 / 钮属于那块面的作用域(`todoLists`),不是叶的;⌘F 由 `todoLists` 答 `view.find`(命令表已有这条命令,零新增)。

**陌生能力演练**:「音乐面也想要自己的头(播放状态 + 搜歌)」= 写一个 `MusicHeader` + `PANEL_HEADERS` 一行。「终端想在单格时把 shell 名放进标题栏」= `terminal` 种类加 `stripHeader`。壳与其他种类零改动。

## 4. 后端:一次搜全部清单

今天 `todo:notes` 只有 `list` 读法(名字 + 数字)。弹层要搜项,前端逐份读 100 份文件是 100 次往返。加一条读法:

- `todo:notes` 读法 `search`,`query: { q: string, limit?: number }` → `{ lists: [{ref,id,title}], items: [{ref,id,title,line,text,done}] }`。
- 后端在 store 的快照上做:标题包含(大小写不敏感)、任务项文字包含;`text` 去掉行首记号;`line` 是行号(打开项时滚到它)。
- 自述 `resource-spec.ts` 加一行;provider 一个分支;无效果(读)。
- 不进全局检索索引(清单文件不是会话账本;接进 `search` 能力是另一单,留账)。

## 5. 编辑器:收起的单元

折叠与「已完成收起」都是**视图**事实,原文一个字不动。落到编辑器是一格输入:

- `EditableDoc` 收 `hidden: ReadonlySet<number>`(被收起的单元起始行)与 `folds: FoldRow[]`(要画的「▸ 已完成 N 项」/ 小节折叠行,各带展开回调)。
- `CaretController`:`neighbour` / `moveVertical` / `moveDocumentEdge` / 最近行命中**跳过** `hidden`;光标所在单元被收起(外部改动勾完了它)→ 就近重开下一个可见单元。
- 勾选一项之后它**不立刻消失**:在场留 `LINE_CHANGED_MS` 再收进「已完成」(否则点完那一行从鼠标底下跳走)。
- 一致性自测(`?todo-lab`)加三项:折叠小节后 ↓ 跳过、已完成收起时退格合并不吃隐藏行、展开再收起光标不丢。
